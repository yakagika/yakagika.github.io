本資料は複数の講義で共通に使う資料です. コーディングエージェントに書かせた変更を確認し, 作業を記録し, 何を公開してよいかを判断するために必要な範囲の git と GitHub を扱います.

エージェント自体の導入と操作は[共通資料 コーディングエージェントの利用](agent.html)で扱います.

# エージェントの変更を確認するために git を使う

コーディングエージェントは, 指示を受けて手元のファイルを書き換えます. 1 回の指示で複数のファイルを同時に変更することも, 既存の行を消すこともあります.

このとき困るのは, **何が変わったのかがファイルを見ただけでは分からない**ことです. 完成したファイルは目の前にありますが, エージェントがどの行を足し, どの行を消したのかは残っていません. 変更前の状態と見比べようにも, 変更前の状態がもう手元にありません.

git は, ファイルの状態を記録して, 記録どうしの差分を取る道具です. 記録を取っておけば, エージェントが何をしたかを行単位で確認できます. 結果が悪ければ記録した時点まで戻せます.

::: note

この資料では, git を「共同開発のための道具」としてではなく, **エージェントの仕事を読むための道具**として扱います. 履歴を残すこと自体が目的ではなく, 差分を読んで承認するか差し戻すかを判断できることが目的です.

:::

# git と GitHub は別のもの

**git** は手元のパソコンで動くプログラムです. ファイルの状態を記録し, 差分を取り, 過去に戻します. インターネットに接続していなくても動きます.

**GitHub** は git の記録をインターネット上に置いておくサービスです. Microsoft が運営しています. 手元の記録を GitHub に送っておけば, パソコンが壊れても失われませんし, 他人に見せることもできます.

git を使うのに GitHub は必須ではありません. 一方 GitHub を使うには git が必要です. 同じような役割のサービスに GitLab や Bitbucket があります.

この講義では, 各自の GitHub アカウントで**リポジトリ** (記録の置き場所, repository, 略して repo) を 1 つ作り, そこに作業を記録していきます.

# public と private の違い

GitHub でリポジトリを作るとき, **public** (公開) と **private** (非公開) を選びます.

- **public**: URL を知っていれば誰でも中身を読めます. 検索エンジンにも載ります.
- **private**: 自分と, 自分が明示的に招待した人だけが読めます.

迷ったら private にしてください. 後から public に変えられます. 逆に, public にしたものを private に戻しても, **公開されていた間に誰かがコピーしたものは取り戻せません**.

## public に置いてはいけないもの

次のものは, たとえ「誰も見ないだろう」と思っても public なリポジトリに入れてはいけません.

**API キーと認証トークン**. 外部サービスを使うための鍵です. [補足B X(Twitter) APIによるデータの取得](dsp_b1.html)で配布するトークンは, 教員が契約したアカウントの共有の前払い残高に直結しています. これが公開されると, 第三者が残高を使い切ることができます. GitHub 上の公開リポジトリは機械的に走査されており, 鍵が置かれると数分で発見されます.

**個人情報を含むデータ**. アンケートの回答, 名簿, 成績など, 個人が特定できるデータです. 匿名化したつもりでも, 複数の項目を組み合わせると個人が特定できることがあります.

**提供を受けたデータ**. 企業や自治体から研究目的で提供されたデータには, 公開してよい範囲の取り決めがあります. 取り決めを確認せずに公開することはできません.

## 鍵を記録に入れてしまったとき

git は履歴を残す道具なので, 一度記録した鍵は**ファイルから消しても履歴には残ります**. 「消したから大丈夫」にはなりません.

やるべきことは, ファイルを直すことではなく, **その鍵を無効にして発行し直すこと**です. X のトークンなら教員に連絡してください. 履歴からの完全な削除は手順が複雑で, かつ既に誰かが取得していた場合には意味がありません.

## 鍵をファイルに書かない

鍵をソースコードに直接書くと, 記録するときに一緒に入ってしまいます. 鍵は `.env` のような別のファイルに書き, そのファイルを記録の対象から外します.

対象から外すには, リポジトリの一番上に `.gitignore` という名前のファイルを作り, 除外したいものを書きます.

~~~ text
# 認証情報
.env
*.key

# データ (容量が大きく, 公開できないものを含む)
data/

# Python が自動で作るもの
__pycache__/
.venv/
~~~

`.gitignore` に書いたファイルは, git が記録の候補から外します. `data/` を除外しているのは, 提供を受けたデータや個人情報を含むデータを誤って記録しないためです.

# 最低限の操作

ここでは 6 つのコマンドだけを扱います. いずれも[共通資料 プログラミング用の設定](setup.html)で扱った CLI から実行します.

## リポジトリを手元に持ってくる: clone

GitHub で作ったリポジトリを手元にコピーします.

~~~ bash
git clone https://github.com/<自分のユーザ名>/<リポジトリ名>.git
cd <リポジトリ名>
~~~

以降のコマンドは, すべてこのディレクトリの中で実行します.

## いま何が変わっているかを見る: status と diff

`git status` は, 変更されたファイルの一覧を出します.

~~~ bash
git status
~~~

~~~ text
On branch main
Changes not staged for commit:
        modified:   analysis.py

Untracked files:
        analysis_result.csv
~~~

`modified` は既にあったファイルが書き換わったこと, `Untracked` はまだ git が知らないファイルであることを示します.

`git diff` は, 中身がどう変わったかを行単位で出します.

~~~ bash
git diff
~~~

~~~ text
diff --git a/analysis.py b/analysis.py
--- a/analysis.py
+++ b/analysis.py
@@ -10,7 +10,7 @@
 df = pd.read_csv('data/survey.csv')

-mean = df['score'].mean()
+mean = df['score'].dropna().mean()
 print(mean)
~~~

先頭が `-` の行が消えた行, `+` の行が足された行です. この例では, 平均を取る前に欠損値を除くように書き換わっています.

::: warn

**エージェントに作業させたら, 承認する前に `git diff` を読んでください.** エージェントは「変更しました」と報告しますが, 報告の文と実際の差分が一致するとは限りません. 差分を読んで, 何が起きたか説明できないうちは次に進まないでください.

この判断の仕方は[共通資料 コーディングエージェントの利用](agent.html)で詳しく扱います.

:::

## 記録する: add と commit

記録は 2 段階です. まず記録したいファイルを選び (`add`), 次にまとめて記録します (`commit`).

~~~ bash
git add analysis.py
git commit -m "欠損値を除いてから平均を取るように修正"
~~~

`-m` の後ろは**コミットメッセージ**で, 何をしたかを自分の言葉で書きます. 後から履歴を見たときに, この 1 行だけで何をしたか分かる必要があります. 「修正」「更新」だけでは分かりません.

現在のディレクトリ以下の変更をすべて記録するときは `git add .` と書けます. ただし `.gitignore` で除外していないファイルが巻き込まれるので, 実行する前に `git status` で一覧を確認してください.

## GitHub に送る: push

手元の記録を GitHub に送ります.

~~~ bash
git push
~~~

commit しただけでは手元にしか残りません. push して初めて GitHub 側に反映されます. 提出のたびに push してください.

## 過去に戻す

直前の commit の状態に戻すには, 次のようにします.

~~~ bash
git restore analysis.py
~~~

エージェントの変更が意図と違っていたとき, これで元に戻せます. commit していない変更は失われるので, **エージェントに作業させる前に commit しておく**と, いつでも戻れる状態になります.

# エージェントが使うもの: branch と worktree

ここから先は, 自分で操作する必要はありません. エージェントやツールがこれらを使うので, 何をしているかを読めるようにしておきます.

## branch

**branch** は, 記録の枝分かれです. `main` という枝で作業していたところから別の枝を伸ばし, そちらで変更を試して, うまくいったら `main` に合流させます.

エージェントに大きな変更をさせるとき, 元の状態を `main` に残したまま別の枝で作業させると, 失敗しても `main` は無傷です. `git status` の 1 行目に出る `On branch main` は, いまどの枝にいるかを示しています.

## worktree

**worktree** は, 同じリポジトリの作業コピーを複数の場所に置く仕組みです. branch が「記録の枝分かれ」なのに対し, worktree は「作業する場所の分裂」です.

エージェントを複数同時に動かすとき, 全員が同じディレクトリを触ると互いの変更を上書きします. worktree で作業場所を分ければ, それぞれが独立して作業できます. [共通資料 コーディングエージェントの利用](agent.html)で扱う herdr は, この仕組みを使ってエージェントごとに作業場所を分けます.

# リポジトリの構成

進捗を記録するリポジトリは, 次の構成を出発点にしてください. 作業しながら自分に合う形に変えて構いません.

~~~ text
<リポジトリ名>/
├── AGENTS.md          # エージェントへの指示
├── README.md          # このリポジトリが何か
├── .gitignore         # 記録しないもの
├── notes/             # 学んだことを書き出す場所
│   └── 2026-04-15-pandas-groupby.md
├── src/               # プログラム
│   └── analysis.py
└── data/              # データ (.gitignore で除外)
~~~

`AGENTS.md` は, エージェントに毎回読ませる決まりごとを書くファイルです. 中身は[共通資料 コーディングエージェントの利用](agent.html)で扱います.

`notes/` は, エージェントに教わったことを自分の言葉で書き出す場所です. これは任意ですが, 最終回の発表の質疑で効きます.

### Exercise GIT-2

**公開してよいか判断する**

次の 5 つについて, public のリポジトリに入れてよいか, 入れてはいけないかを判断し, その理由を書いてください.

1. 自分で書いた `analysis.py`
2. 補足B で配布された X の認証トークンを書いた `.env`
3. 政府統計のポータルからダウンロードした CSV
4. 授業で配布された, 学生の学籍番号を含むアンケート結果
5. `analysis.py` が出力した集計結果のグラフ画像

<details class="protected" data-pass="yakagika">
<summary>回答例</summary>

1. **よい**. 自分で書いたコードで, 鍵もデータも含まない.
2. **いけない**. 認証トークンは共有の前払い残高に直結する. 公開リポジトリは機械的に走査されるため, 発見されるまでの時間は短い. `.gitignore` に `.env` を書いて除外する.
3. **よい**. 誰でもダウンロードできる公開データであり, 再配布に制限がない. ただし容量が大きい場合は, リポジトリに入れず取得手順を書く方が扱いやすい.
4. **いけない**. 学籍番号は個人を特定できる. 学籍番号を消しても, 学部と学年と回答の組み合わせで特定できることがある. `data/` ごと除外する.
5. **場合による**. 集計結果そのものは個人を特定しないが, 元データが 4 のような非公開データなら, 集計の粒度によっては特定につながる. 元データが 3 なら問題ない.

</details>
