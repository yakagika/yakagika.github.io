# 総合演習 — 代数的に定義し, Haskell で実装する

本講義は, 関数・データ型・代数・モナド・効果と積み上げてきました. 総合演習ではこれらを「代数的な定義 → 実装 → 検証」という 1 つの型に組み合わせます.

- [第7章](fp7.html) **代数的データ型**: 構築子で値の世界を定義する (本章では「初代数」という見方を足します).
- [第8章](fp8.html) **型クラスと代数**: 演算と **法則** (結合律・単位元律) で型を特徴づける — 本章の「公理」の既習例です.
- [第9章](fp9.html) **多相データ型**: 未規定 (失敗しうる操作) を `Maybe` / `Either` で型に乗せる.
- [第10章](fp10.html) **モナドと入出力**: 公理を実装につなぐ `do` 記法と, モデルに触る UI (REPL).
- [第11章](fp11.html) **可変状態と効果**: 状態を持つ対象の実装.

## 仕様を等式で書く — 順序の逆転

ふつうのプログラミングは「データ構造を実装する → それを使う関数を書く」と実装から始めます. 本章はこれを逆にします. まず演算が満たすべき **等式** を書き, それを型の **定義** とみなし, 実装はあとから選ぶのです.

この見方では役者は 3 つに分かれます.

- **シグネチャ (signature)**: 演算の名前と型の一覧. 「何ができるか」だけを宣言する.
- **公理 (axiom)**: 演算どうしが満たすべき等式. 「どう振る舞うか」を実装抜きで固定する.
- **モデル (model)**: 公理を満たす具体的な実装. **1 つの仕様に対してモデルは複数ありうる** — 実装は仕様を満たす一例にすぎない.

[第8章](fp8.html)の `Monoid` はまさにこの形でした: `(<>)` と `mempty` がシグネチャ, 結合律・単位元律が公理, `Add` や `Stats` などの `instance` がモデルです. 本章はこの見方をモノイド以外の対象へ広げます.

::: note
「仕様を先に等式で書く」流儀は 1970 年代に **代数的仕様記述 (algebraic specification)** として確立した設計法で, 現代では型クラスの法則と property-based testing (後述の QuickCheck) という形で実務に生きています.
:::

## 公理の書き方 — 観測子×構築子マトリクス

「どんな公理を書けばよいか」には機械的なレシピがあります. まず演算を役割で分類します.

- **構築子 (constructor)**: 値を **作る** 演算.
- **観測子 (observer)**: 値から **情報を取り出す** 演算 (戻り値が別の型になる).
- **派生 (derived)**: 既存の値から別の値を作るが, 構築子ではないもの.

そのうえで, **各観測子・派生を, 各構築子が作った形に適用したら何になるか** を表 (マトリクス) で 1 マスずつ埋めます. 埋めた各マスがそのまま公理になり, 空欄は「未規定」— 意図的な設計判断として扱います.

## 通し実演: Stack を仕様から作る

スタック (後入れ先出しの入れ物) を, 実装を決める前に定義してみます. シグネチャは型クラスで書けます ([第8章](fp8.html)).

~~~ haskell
class StackSig t where
  empty   :: t a                 -- 構築子: 空のスタック
  push    :: a -> t a -> t a     -- 構築子: 1 つ積む
  pop     :: t a -> t a          -- 派生:   1 つ降ろす
  top     :: t a -> a            -- 観測子: 先頭を覗く
  isEmpty :: t a -> Bool         -- 観測子: 空か
~~~

すべてのスタックは `empty` に `push` を重ねて作れる — 構築子はこの 2 つです. マトリクスを埋めると:

| | `empty` | `push x s` |
|---|---|---|
| `isEmpty` | `True` | `False` |
| `top` | (未規定) | `x` |
| `pop` | (未規定) | `s` |

埋まった 4 マスがそのまま公理です.

~~~ text
isEmpty empty      = True
isEmpty (push x s) = False
top (push x s)     = x
pop (push x s)     = s
~~~

空欄の 2 マス (`top empty`, `pop empty`) は **意図的に未規定** とします (「空でない」を前提条件とする部分関数). この空欄をどう扱うかは設計判断で, `Maybe` で全域化する道もあります — 必修課題では同じ問題が「0 除算」として再登場します.

公理を満たすモデルを 1 つ作ります. リストの先頭に積む実装です.

~~~ haskell
newtype ListStack a = ListStack [a] deriving (Show, Eq)

instance StackSig ListStack where
  empty                       = ListStack []
  push x (ListStack xs)       = ListStack (x : xs)
  pop    (ListStack (_ : xs)) = ListStack xs
  pop    (ListStack [])       = error "pop: empty stack"
  top    (ListStack (x : _))  = x
  top    (ListStack [])       = error "top: empty stack"
  isEmpty (ListStack xs)      = null xs
~~~

### 公理を実行する — QuickCheck

公理はそのまま **テスト** になります. `QuickCheck` は「等式をランダムな入力 100 個で試す」ライブラリで, 公理 1 本を **property** 1 本に写せます.

~~~ haskell
import Test.QuickCheck

-- 「任意のスタック」の作り方も構築子で決まる (ランダムなリストに push を重ねたもの)
instance Arbitrary a => Arbitrary (ListStack a) where
  arbitrary = foldr push empty <$> listOf arbitrary

-- 公理をそのまま property に (どのモデルでも同じ式が書ける)
prop_isEmpty_push :: (StackSig t) => Int -> t Int -> Bool
prop_isEmpty_push x s = not (isEmpty (push x s))

prop_top_push :: (StackSig t) => Int -> t Int -> Bool
prop_top_push x s = top (push x s) == x

prop_pop_push :: (StackSig t, Eq (t Int)) => Int -> t Int -> Bool
prop_pop_push x s = pop (push x s) == s
~~~

ghci で実行します. QuickCheck を使うので `stack ghci --package QuickCheck ch12-1.hs` のように起動してください.

~~~ text
ghci> quickCheck (prop_top_push :: Int -> ListStack Int -> Bool)
+++ OK, passed 100 tests.
~~~

公理が破れていれば QuickCheck が反例の入力を表示します. 「公理 = 仕様 = テスト」が 1 つの式で往復するのが, この流儀の要です.

### 同じ仕様の別モデル — 実装非依存

リストを **逆順に** 持つ実装でも, 同じ公理が通ります.

~~~ haskell
newtype RevStack a = RevStack [a] deriving (Show, Eq)

instance StackSig RevStack where
  empty                 = RevStack []
  push x (RevStack xs)  = RevStack (xs ++ [x])
  pop    (RevStack xs)  = RevStack (init xs)
  top    (RevStack xs)  = last xs
  isEmpty (RevStack xs) = null xs

instance Arbitrary a => Arbitrary (RevStack a) where
  arbitrary = foldr push empty <$> listOf arbitrary
~~~

~~~ text
ghci> quickCheck (prop_top_push :: Int -> RevStack Int -> Bool)
+++ OK, passed 100 tests.
~~~

2 つのモデルは内部表現も性能も違います (`RevStack` の `push` はリスト全体を歩きます) が, **公理は性能を語らない** ので, どちらも正しいスタックです. 仕様に書いていないことは仕様に含まれない — これが「実装は仕様を満たす一例にすぎない (実装非依存)」の意味です.

# 必修課題: 式の代数と評価器

## 式のシグネチャ — 代数を先に決める

「数式」という対象を, まず構築子だけの代数として定義します.

~~~ text
num                : Double → Expr           -- 数はそれだけで式
add, sub, mul, div : Expr × Expr → Expr      -- 2 つの式を組み合わせた式
~~~

これを Haskell に写したものが, [第7章](fp7.html)の再帰的データ型です.

~~~ haskell
data Expr
  = Num Double
  | Add Expr Expr
  | Sub Expr Expr
  | Mul Expr Expr
  | Div Expr Expr
  deriving (Show, Eq)
~~~

`data` 宣言はこの代数の **初代数 (initial algebra)** を作ります — 「構築子から作れるものはすべてあり (ゴミなし), 等しいと宣言していないものは全部別物 (混同なし)」という, 過不足のない実装です. たとえば `Add (Num 1) (Num 2)` と `Num 3` は **式としては別の値** です. 評価すれば同じ数になりますが, その「評価」は次に決める観測子の仕事であって, 式の世界では区別が保たれています. 区別が保たれているからこそ, 同じ木に評価以外の観測 (表示や式変形など) も後から載せられます.

## 評価の公理 — マトリクスを埋める

観測子は評価 `eval` です. 観測子×構築子マトリクスを埋めていきます (`?` の 2 マスは演習で埋めます).

| | `Num x` | `Add a b` | `Sub a b` | `Mul a b` | `Div a b` |
|---|---|---|---|---|---|
| `eval` | `x` | `eval a + eval b` | `?` | `?` | (分母 0 で未規定) |

`Div` の列に, Stack の `top empty` と同じ **未規定** が現れました. ここでは前提条件つきの部分関数のままにせず, [第9章](fp9.html)の `Either` で **全域化** する設計を採ります: `eval :: Expr -> Either EvalError Double`. 全域化後の公理は次の形になります.

~~~ text
eval (Num x)   = Right x
eval (Add a b) = (+) <$> eval a <*> eval b   -- 左右が両方成功したときだけ足す
eval (Sub a b) = ...                          -- 演習で
eval (Mul a b) = ...                          -- 演習で
eval (Div a b) = 左右を評価し, 分母が 0 なら Left DivByZero, さもなくば商
~~~

(`<$>` / `<*>` は [第10章](fp10.html)の Applicative — 「両方の `Either` が成功したときだけ関数を適用する」書き方です.)

`eval` の再帰は構築子の形をそのままなぞります. これは[第6章](fp6.html)の畳み込みや[第8章](fp8.html)の `fold` の親戚で, 初代数から結果の世界 (`Either EvalError Double`) への橋渡しです.

## アプリとして組む — RPN パーサと REPL

定義した代数に触る UI として, 数式を入力すると計算結果を返す **電卓 REPL** を作ります. 入力は **逆ポーランド記法 (RPN, Reverse Polish Notation)** とします. RPN は `3 4 +` のように「オペランドを並べてから演算子を置く」記法で, 括弧が要らず, **空白で区切って `words` で分ける**だけでパースできるため, パーサ部分の負担が小さいのが利点です.

このアプリは, 次の流れで全章の道具を使います.

1. 入力文字列を **RPN パース**して **式の木 `Expr`** ([第7章](fp7.html)の再帰的データ型) を組み立てる.
2. 木を **評価** `eval :: Expr -> Either EvalError Double` する. 0 除算は [第9章](fp9.html)の `Either` と [第10章](fp10.html)の `do` 記法で伝播させる.
3. 成功した結果を [第8章](fp8.html)の **モノイド `Stats`** に貯め, 件数・合計・平均を集計する (`:stats` コマンドで表示).
4. これらを `IO` の **REPL ループ** ([第10章](fp10.html)) で繰り返す.

## 仕様

- 入力は 1 行 1 式の RPN. トークンは空白区切りで, **数値** (`Double`) と **二項演算子** `+ - * /` のみ.
- 計算できたら `= 結果` を表示する.
- **エラーは落とさず**メッセージにする: 未知トークン・スタック不足 (演算子過多)・式の残り (オペランド過多)・**0 除算**.
- `:stats` と入力すると, ここまでに成功した計算結果の **件数・合計・平均** を表示する.
- 入力の終端 (EOF, `Ctrl-D`) で最終的な統計を表示して終了する.

実行イメージ:

~~~ text
> 3 4 + 5 *
= 35.0
> 10 2 /
= 5.0
> 1 0 /
エラー: Eval DivByZero
> 3 x +
エラー: Parse (BadToken "x")
> :stats
件数 2 / 合計 40.0 / 平均 20.0
> ^D
--- 評価結果の統計 ---
件数 2 / 合計 40.0 / 平均 20.0
~~~

## 配布される足場

次の **型定義** と **RPN パーサ `parseRPN`** は配布します (触らなくて構いません). パーサは「`words` で分け, 数値はスタックに積み, 演算子はスタックから 2 つ取り出して `Expr` の節を作る」という[第6章](fp6.html)の畳み込みです.

~~~ haskell
import Text.Read (readMaybe)
import Data.Bifunctor (first)
import System.IO (hFlush, stdout, isEOF)

-- 式 (再帰的 ADT)
data Expr
  = Num Double
  | Add Expr Expr
  | Sub Expr Expr
  | Mul Expr Expr
  | Div Expr Expr
  deriving (Show, Eq)

-- 評価時のエラー / パース時のエラー
data EvalError  = DivByZero                              deriving (Show, Eq)
data ParseError = BadToken String | StackUnderflow | LeftoverOperands deriving (Show, Eq)

-- RPN パース: words を畳んでスタック上に Expr 木を組む (配布)
parseRPN :: String -> Either ParseError Expr
parseRPN input = foldStack [] (words input) >>= final
  where
    foldStack stack []       = Right stack
    foldStack stack (t : ts) = step stack t >>= \s -> foldStack s ts

    step stack tok = case tok of
      "+" -> binop Add stack
      "-" -> binop Sub stack
      "*" -> binop Mul stack
      "/" -> binop Div stack
      _   -> case readMaybe tok of
               Just n  -> Right (Num n : stack)
               Nothing -> Left (BadToken tok)

    binop f (b : a : rest) = Right (f a b : rest)
    binop _ _              = Left StackUnderflow

    final [e] = Right e
    final _   = Left LeftoverOperands
~~~

~~~ haskell
import Text.Read (readMaybe)
import Data.Bifunctor (first)
import System.IO (hFlush, stdout, isEOF)
import Test.QuickCheck

-- 式 (再帰的 ADT, fp7)
data Expr
  = Num Double
  | Add Expr Expr
  | Sub Expr Expr
  | Mul Expr Expr
  | Div Expr Expr
  deriving (Show, Eq)

data EvalError  = DivByZero                              deriving (Show, Eq)
data ParseError = BadToken String | StackUnderflow | LeftoverOperands deriving (Show, Eq)

-- 木をたどって評価する. 0 除算は Either で持ち上げて伝播させる (fp9 + fp10).
eval :: Expr -> Either EvalError Double
eval (Num x)   = Right x
eval (Add a b) = do { x <- eval a; y <- eval b; Right (x + y) }
eval (Sub a b) = do { x <- eval a; y <- eval b; Right (x - y) }
eval (Mul a b) = do { x <- eval a; y <- eval b; Right (x * y) }
eval (Div a b) = do
  x <- eval a
  y <- eval b
  if y == 0 then Left DivByZero else Right (x / y)

-- RPN パース (配布)
parseRPN :: String -> Either ParseError Expr
parseRPN input = foldStack [] (words input) >>= final
  where
    foldStack stack []       = Right stack
    foldStack stack (t : ts) = step stack t >>= \s -> foldStack s ts
    step stack tok = case tok of
      "+" -> binop Add stack
      "-" -> binop Sub stack
      "*" -> binop Mul stack
      "/" -> binop Div stack
      _   -> case readMaybe tok of
               Just n  -> Right (Num n : stack)
               Nothing -> Left (BadToken tok)
    binop f (b : a : rest) = Right (f a b : rest)
    binop _ _              = Left StackUnderflow
    final [e] = Right e
    final _   = Left LeftoverOperands

-- 評価結果の統計 (fp8 章末 Stats の Double 版を再利用)
data Stats = Stats { statCount :: Int, statSum :: Double }
  deriving (Show, Eq)

instance Semigroup Stats where
  Stats c1 s1 <> Stats c2 s2 = Stats (c1 + c2) (s1 + s2)

instance Monoid Stats where
  mempty = Stats 0 0

record :: Double -> Stats
record x = Stats 1 x

summarize :: [Double] -> Stats
summarize = foldMap record

mean :: Stats -> Double
mean (Stats c s) = s / fromIntegral c

-- パースと評価の 2 つのエラーを 1 つの直和型にまとめる (fp7 + fp9)
data Error = Parse ParseError | Eval EvalError
  deriving (Show, Eq)

run :: String -> Either Error Double
run input = do
  expr <- first Parse (parseRPN input)
  first Eval (eval expr)

-- REPL 本体 (fp10 IO / do)
showStats :: Stats -> String
showStats st = "件数 " ++ show (statCount st)
            ++ " / 合計 " ++ show (statSum st)
            ++ (if statCount st > 0 then " / 平均 " ++ show (mean st) else "")

runRepl :: Stats -> IO ()
runRepl stats = do
  putStr "> " >> hFlush stdout
  eof <- isEOF
  if eof
    then putStrLn ("\n--- 評価結果の統計 ---\n" ++ showStats stats)
    else do
      line <- getLine
      case line of
        ":stats" -> putStrLn (showStats stats) >> runRepl stats
        _        -> case run line of
          Right v  -> putStrLn ("= " ++ show v) >> runRepl (stats <> record v)
          Left err -> putStrLn ("エラー: " ++ show err) >> runRepl stats

main :: IO ()
main = runRepl mempty

-- ── 検証: 公理をそのまま property に ──

instance Arbitrary Expr where
  arbitrary = sized gen
    where
      gen 0 = Num <$> arbitrary
      gen n = oneof [ Num <$> arbitrary
                    , Add <$> sub' <*> sub', Sub <$> sub' <*> sub'
                    , Mul <$> sub' <*> sub', Div <$> sub' <*> sub' ]
        where sub' = gen (n `div` 2)

prop_num :: Double -> Bool
prop_num x = eval (Num x) == Right x

prop_add :: Expr -> Expr -> Bool
prop_add a b = eval (Add a b) == ((+) <$> eval a <*> eval b)

prop_sub :: Expr -> Expr -> Bool
prop_sub a b = eval (Sub a b) == ((-) <$> eval a <*> eval b)

prop_mul :: Expr -> Expr -> Bool
prop_mul a b = eval (Mul a b) == ((*) <$> eval a <*> eval b)

prop_div_zero :: Expr -> Bool
prop_div_zero a = eval (Div a (Num 0)) == Left DivByZero

prop_div_ok :: Expr -> NonZero Double -> Bool
prop_div_ok a (NonZero y) = eval (Div a (Num y)) == ((/) <$> eval a <*> pure y)

prop_stats_hom :: [Int] -> [Int] -> Bool
prop_stats_hom xs ys =
  summarize (map fromIntegral (xs ++ ys))
    == summarize (map fromIntegral xs) <> summarize (map fromIntegral ys)
~~~

設計の勘所:

- **`eval` の `do` 記法**: `Either` はモナドなので, `x <- eval a` で「失敗していたらそこで `Left` を返して打ち切り, 成功していたら値を取り出す」が 1 行で書けます. これが[第10章](fp10.html)で見た「失敗の連鎖」です. `Div` だけは右辺の値を見てから `0` 判定するため, `if` を挟んでいます.
- **エラーの合流 (`first`)**: パースは `Either ParseError`, 評価は `Either EvalError` と型が違うため, そのままでは `>>=` で繋げません. 直和型 `Error` に包み, `first Parse` / `first Eval` で `Either` の左 (エラー側) だけを変換してから連結します. これは[第9章](fp9.html)の Functor 的な「片側だけ `fmap`」です.
- **統計をモノイドで**: REPL は「現在の統計」を引数で持ち回り, 成功するたびに `stats <> record v` で 1 件分を合成します. `Stats` が[第8章](fp8.html)のモノイドなので, 初期値は `mempty`, 合成は `<>` だけで書け, 件数・合計・平均がそのまま得られます. RPN パーサ自体も「`Either` を畳み込む」点でモノイド的な合成になっています.
- **公理と property の往復**: `prop_add` などは評価マトリクスの各マスをそのまま書き写したものです. 一方 `prop_stats_hom` を `[Double]` でなく `[Int]` から作っているのには理由があります — `Double` の加算は厳密には結合的でない (丸めの入り方が括弧の位置で変わる) ため, ランダムな小数では準同型の等式が **ずれることがある** のです. 公理を property にして回すと, こうした実装の数値的性質まで炙り出されます. これも「仕様を等式で書く」効用のひとつです.

</details>

# 選択課題

必修課題に加えて, 次の課題から 1 つ以上を選んで取り組めます. いずれも「対象を代数的に定義し, 公理を確定してから実装する」点は必修課題と同じです. A〜C は入出力を伴わない純粋な部分 (パース・集計・更新) を先に完成させて最後に `IO` の薄い殻をかぶせる **アプリ課題**, D・E は純粋なライブラリとして完結する **代数課題** です.

## 選択課題A: 台帳 (家計簿) — 自由モノイドと準同型

取引の一覧を読み込み, 残高とカテゴリ別の集計を出力するアプリです. [第7章](fp7.html)の列挙型・レコード, [第8章](fp8.html)のモノイド, [第9章](fp9.html)の `Either` / `Map`, [第11章](fp11.html)の `State` を使います.

### 台帳の代数

台帳とは何か. 本課題では **取引のリスト `[Tx]`** と定義します. リストは `++` と `[]` のモノイドで, 「取引を並べる」以上の公理を何も課していません — このように余計な等式が 1 本もないモノイドを **自由モノイド (free monoid)** と呼びます. 台帳の観測子は集計です.

~~~ text
summarize  : [Tx] → Summary            -- 件数と残高
byCategory : [Tx] → Map Category Int   -- カテゴリ別の合計
~~~

観測子×構築子マトリクス (リストの構築子は `[]` と `tx : txs`) を埋めます.

| | `[]` | `tx : txs` |
|---|---|---|
| `summarize` | `mempty` | `Summary 1 (txAmount tx) <> summarize txs` |
| `byCategory` | `Map.empty` | `?` (演習で) |

このマトリクスから, 集計が **準同型** であることが従います.

~~~ text
summarize  (xs ++ ys) = summarize xs <> summarize ys
byCategory (xs ++ ys) = Map.unionWith (+) (byCategory xs) (byCategory ys)
~~~

「台帳を分割して別々に集計してから合成しても, まとめて集計しても同じ」 — [第8章](fp8.html)の準同型そのものです. `Map.unionWith` の形は, [第8章](fp8.html)「さらに先の利点 (予告)」で触れた `Map` の併合の回収でもあります.

### 仕様

- 入力は 1 行 1 取引で, `カテゴリ 金額` の形式 (例: `food -500`, `income 2000`). 金額は **収入が正・支出が負** の整数.
- カテゴリは `food` / `transport` / `utility` / `income` / `other` のいずれか.
- 壊れた行 (未知カテゴリ・金額が数値でない・語数が違う) は **無視** してメッセージを出す.
- 全行を処理したら, **件数と合計残高**, および **カテゴリ別の合計** を表示する.

~~~ text
$ printf "food -500\nincome 2000\ncandy -100\n" | runghc ledger.hs
記録 Tx {txCat = Food, txAmount = -500} / 件数 1
記録 Tx {txCat = Income, txAmount = 2000} / 件数 2
無視 (UnknownCategory "candy")
合計残高 1500 / 件数 2
~~~

### Exercise CH12-2

**台帳 — 公理から実装へ**

1. **公理の完成** — マトリクスの `?` (`byCategory` の `tx : txs` の欄) を埋めて公理を確定してください.
2. **`parseTx :: String -> Either ParseError Tx`** — `words` で 2 語に分け, カテゴリと金額 (`readMaybe`) をそれぞれ検証する. どれかが失敗したら `Left` (入力行のパースも「未規定を `Either` で全域化した部分関数」です).
3. **`Summary` モノイド** — 件数 `sCount` と残高 `sBalance` を持ち, `<>` で成分加算. `summarize = foldMap (\t -> Summary 1 (txAmount t))`.
4. **`byCategory :: [Tx] -> Map Category Int`** — `Map.fromListWith (+)` でカテゴリ別合計.
5. **公理の検証** — 準同型 property 2 本 (`summarize` / `byCategory`) を埋めて `quickCheck` してください (`Arbitrary Tx` は配布).
6. **`runLedger :: [String] -> ([String], Summary)` と `main`** — 各行を `State [Tx]` で処理して台帳に積み, メッセージ列と最終集計を返す. `main` は標準入力を `lines` で分け, `runLedger` して結果を表示.

    <summary> 回答例 </summary>

~~~ haskell
import Text.Read (readMaybe)
import Control.Monad.State
import qualified Data.Map as Map
import Data.Map (Map)
import Test.QuickCheck

-- カテゴリ (列挙型, fp7/fp8)
data Category = Food | Transport | Utility | Income | Other
  deriving (Show, Eq, Ord, Enum, Bounded)

-- 取引 (金額は 収入 +, 支出 -)
data Tx = Tx { txCat :: Category, txAmount :: Int }
  deriving (Show, Eq)

data ParseError = UnknownCategory String | BadAmount String | BadFormat String
  deriving (Show, Eq)

parseTx :: String -> Either ParseError Tx
parseTx line = case words line of
  [c, a] -> do
    cat <- parseCat c
    amt <- parseAmt a
    Right (Tx cat amt)
  _ -> Left (BadFormat line)
  where
    parseCat "food"      = Right Food
    parseCat "transport" = Right Transport
    parseCat "utility"   = Right Utility
    parseCat "income"    = Right Income
    parseCat "other"     = Right Other
    parseCat s           = Left (UnknownCategory s)
    parseAmt s = maybe (Left (BadAmount s)) Right (readMaybe s)

-- 件数と残高を集計するモノイド (fp8)
data Summary = Summary { sCount :: Int, sBalance :: Int }
  deriving (Show, Eq)

instance Semigroup Summary where
  Summary c1 b1 <> Summary c2 b2 = Summary (c1 + c2) (b1 + b2)

instance Monoid Summary where
  mempty = Summary 0 0

summarize :: [Tx] -> Summary
summarize = foldMap (\t -> Summary 1 (txAmount t))

-- カテゴリ別合計 (fp9 Map)
byCategory :: [Tx] -> Map Category Int
byCategory = Map.fromListWith (+) . map (\t -> (txCat t, txAmount t))

-- 1 行処理: パースできれば台帳に積み, メッセージを返す (fp11 State)
processLine :: String -> State [Tx] String
processLine line = case parseTx line of
  Right tx -> do
    modify (tx :)
    n <- gets length
    return ("記録 " ++ show tx ++ " / 件数 " ++ show n)
  Left err -> return ("無視 (" ++ show err ++ ")")

runLedger :: [String] -> ([String], Summary)
runLedger ls =
  let (msgs, ledger) = runState (mapM processLine ls) []
  in (msgs, summarize ledger)

main :: IO ()
main = do
  contents <- getContents
  let (msgs, summ) = runLedger (lines contents)
  mapM_ putStrLn msgs
  putStrLn ("合計残高 " ++ show (sBalance summ) ++ " / 件数 " ++ show (sCount summ))

-- ── 検証: 集計の準同型を property に ──

instance Arbitrary Category where
  arbitrary = elements [minBound .. maxBound]

instance Arbitrary Tx where
  arbitrary = Tx <$> arbitrary <*> arbitrary

prop_summarize_hom :: [Tx] -> [Tx] -> Bool
prop_summarize_hom xs ys = summarize (xs ++ ys) == summarize xs <> summarize ys

prop_byCategory_hom :: [Tx] -> [Tx] -> Bool
prop_byCategory_hom xs ys =
  byCategory (xs ++ ys) == Map.unionWith (+) (byCategory xs) (byCategory ys)
~~~

勘所: パースは[第10章](fp10.html)の `do` で「カテゴリと金額の両方が成功したときだけ `Tx` を作る」と書けます. 集計が `Summary` のモノイドなので, `foldMap` 一発で件数と残高が同時に出ます ([第8章](fp8.html)). 台帳への積み上げは `State [Tx]` で状態を引き回し, `modify (tx :)` で 1 件追加します ([第11章](fp11.html)). カテゴリ別は `Map.fromListWith (+)` で「同じキーの値を足しながら」集約します. 準同型 property は「台帳をどこで分割して集計しても同じ」ことの機械的な確認で, 金額が `Int` なので浮動小数の問題 (必修課題の勘所参照) は起きません.

</details>

::: note
**発展: 複式簿記の代数 (研究の入り口)**

本課題の金額は正負の整数なので, `Summary` の合成は逆元 (符号反転 = 逆仕訳) を持つ **群** に拡張できます ([第8章](fp8.html)の群). さらに実際の会計 (複式簿記) は, 1 つの取引を借方・貸方の 2 面で記録し, **貸借平衡** (借方合計 = 貸方合計) という等式を常に保ちます. この平衡を公理として持つ代数系で会計を定式化する研究領域 (**交換代数**) があり, 「台帳 = 自由モノイド, 集計 = 準同型」という本課題の見方はその入り口にあたります. 500 年使われてきた簿記というシステムが, 本章の「公理で定義する」流儀でそのまま研究対象になるのです.
:::

## 選択課題B: ログ / CSV 集計 — 部分関数と準同型

アクセスログ (CSV) を 1 行ずつ読み, 件数・総バイト数・ステータス別件数を集計するパイプラインです. [第9章](fp9.html)の `Maybe` / `mapMaybe` / `Map`, [第8章](fp8.html)のモノイドと **準同型・融合** が主役です.

### ログの代数

対象は 1 行のログですが, **すべての文字列がログ行ではありません**. パースは Stack の `top empty` や電卓の 0 除算と同じ **部分関数** で, ここでは `Maybe` で全域化します: `parseHit :: String -> Maybe Hit`. 正しい行については「表示してからパースすると元に戻る」ことが公理になります.

~~~ text
parseHit (show s ++ "," ++ show b) = Just (Hit s b)   -- 往復 (round-trip) の公理
~~~

集計は台帳 (選択課題A) と同じ準同型です.

~~~ text
aggregate []         = mempty
aggregate (xs ++ ys) = aggregate xs <> aggregate ys
byStatus  (xs ++ ys) = Map.unionWith (+) (byStatus xs) (byStatus ys)
~~~

パイプライン全体は「部分関数で濾す (`mapMaybe`) → 準同型で畳む (`foldMap`)」の 2 段になります.

### 仕様

- 入力は 1 行 1 レコードで, `status,bytes` の CSV (例: `200,1024`).
- **壊れた行は捨てる** (`Maybe` を返し `mapMaybe` で除外). 例外で落とさない.
- 全行から, **総件数・総バイト数**, および **ステータスコード別の件数** を集計する.

~~~ text
$ printf "200,1000\nbroken\n404,50\n200,2000\n" | runghc logagg.hs
件数 3 / 総バイト 3050
200: 2
404: 1
~~~

### Exercise CH12-3

**ログ集計 — 部分関数と準同型**

1. **`parseHit :: String -> Maybe Hit`** — カンマで 2 つに分け, 両方が数値なら `Just`, でなければ `Nothing`. `Hit <$> readMaybe s <*> readMaybe b` と書けます.
2. **`Agg` モノイド** — 件数 `aCount` と総バイト `aBytes`. `aggregate = foldMap (\h -> Agg 1 (hitBytes h))`.
3. **`byStatus :: [Hit] -> Map Int Int`** — ステータス別件数.
4. **`summarizeLog :: [String] -> (Agg, Map Int Int)`** — `mapMaybe parseHit` で壊れた行を落としてから集計.
5. **公理の検証** — 往復の公理 (`prop_parse_roundtrip`) と準同型 2 本 (`aggregate` / `byStatus`) を property にして `quickCheck` してください (`Arbitrary Hit` は配布). 準同型は[第8章](fp8.html)で見たとおり, 入力を好きに分割して集計しても結果が変わらない (= 並列・分割集計できる) という性質です.
6. **`main`** — 標準入力を集計して表示.

<details class="protected" data-pass="yakagika">
    <summary> 回答例 </summary>

~~~ haskell
import Text.Read (readMaybe)
import Data.Maybe (mapMaybe)
import qualified Data.Map as Map
import Data.Map (Map)
import Test.QuickCheck

-- アクセスログ 1 行 "status,bytes"
data Hit = Hit { hitStatus :: Int, hitBytes :: Int }
  deriving (Show, Eq)

-- カンマ区切り (自前で分割)
splitComma :: String -> [String]
splitComma s = case break (== ',') s of
  (a, ',' : rest) -> a : splitComma rest
  (a, _)          -> [a]

-- 壊れた行は Nothing で捨てる (fp9 Maybe + Applicative)
parseHit :: String -> Maybe Hit
parseHit line = case splitComma line of
  [s, b] -> Hit <$> readMaybe s <*> readMaybe b
  _      -> Nothing

-- 件数と総バイトを集計するモノイド (fp8)
data Agg = Agg { aCount :: Int, aBytes :: Int }
  deriving (Show, Eq)

instance Semigroup Agg where
  Agg c1 b1 <> Agg c2 b2 = Agg (c1 + c2) (b1 + b2)

instance Monoid Agg where
  mempty = Agg 0 0

aggregate :: [Hit] -> Agg
aggregate = foldMap (\h -> Agg 1 (hitBytes h))

-- ステータス別件数 (fp9 Map)
byStatus :: [Hit] -> Map Int Int
byStatus = Map.fromListWith (+) . map (\h -> (hitStatus h, 1))

-- パイプライン: 壊れた行を mapMaybe で除外して集計
summarizeLog :: [String] -> (Agg, Map Int Int)
summarizeLog ls = let hits = mapMaybe parseHit ls
                  in (aggregate hits, byStatus hits)

main :: IO ()
main = do
  contents <- getContents
  let (agg, codes) = summarizeLog (lines contents)
  putStrLn ("件数 " ++ show (aCount agg) ++ " / 総バイト " ++ show (aBytes agg))
  mapM_ (\(c, n) -> putStrLn (show c ++ ": " ++ show n)) (Map.toList codes)

-- ── 検証: 往復と準同型を property に ──

instance Arbitrary Hit where
  arbitrary = Hit <$> arbitrary <*> arbitrary

prop_parse_roundtrip :: Int -> Int -> Bool
prop_parse_roundtrip s b = parseHit (show s ++ "," ++ show b) == Just (Hit s b)

prop_agg_hom :: [Hit] -> [Hit] -> Bool
prop_agg_hom xs ys = aggregate (xs ++ ys) == aggregate xs <> aggregate ys

prop_byStatus_hom :: [Hit] -> [Hit] -> Bool
prop_byStatus_hom xs ys =
  byStatus (xs ++ ys) == Map.unionWith (+) (byStatus xs) (byStatus ys)
~~~

勘所: `parseHit` は `Maybe` の Applicative (`<$>` / `<*>`) で「両方の数値が取れたときだけ `Hit` を作る」と簡潔に書けます. `mapMaybe` は[第9章](fp9.html)で見た「`Just` だけ残して `Nothing` を捨てる」関数で, 壊れた行を例外なしに除外します. 集計は `Agg` のモノイドなので `foldMap` 一発. しかも `aggregate` は **準同型**なので, ログを何分割して集計してから `<>` で合わせても同じ結果になります. 往復の公理は「`show` と `parseHit` が対になっている」ことの確認で, 表示とパースを別々に直したときに壊れていないかを機械的に見張ってくれます.

</details>

## 選択課題C: うさぎ個体群シミュレータ — 遷移と観測

[第1章](fp1.html)の冒頭で見た「うさぎのつがいの増え方」(フィボナッチ) を, **年齢階級を持つ個体群** と [第11章](fp11.html)の `State` による世代更新で組み直します.

### 個体群の代数 — 遷移と観測

この課題の対象は入れ物ではなく, **時間発展する状態** です. シグネチャは「状態を進める」遷移と「状態を読む」観測からなります.

~~~ text
step                : Population → Population   -- 遷移: 1 か月進める
young, adult, total : Population → Integer      -- 観測
~~~

「若いつがいは成熟し, 成熟つがいは 1 組ずつ産む」という現象の規則は, 観測子×遷移のマトリクスでたった 2 本の等式になります.

| | `step p` |
|---|---|
| `young` | `adult p` (成熟 1 組が若い 1 組を産む) |
| `adult` | `total p` (全員が生き残り成熟する) |

この 2 本と定義 `total p = young p + adult p` から, フィボナッチの再帰が **等式変形だけで** 導けます.

~~~ text
total (step (step p))
  = young (step (step p)) + adult (step (step p))   -- total の定義
  = adult (step p)        + total (step p)          -- 公理 2 本を step p に適用
  = total p               + total (step p)          -- 公理をもう 1 度 p に適用
~~~

「新しい総数 = 前の総数 + 前々の総数」. [第1章](fp1.html)のうさぎ算の正体が, 局所的な公理 2 本の帰結だったと分かります — 公理から大域的な性質を導出する, 代数的定義の醍醐味です.

### 仕様

- 個体群は **若いつがい** `young` と **成熟つがい** `adult` の 2 つの数からなる.
- 1 か月で, 若いつがいは成熟し, 成熟つがいは新たに若いつがいを 1 組ずつ産む.
- 最初は若いつがい 1 組から始め, 各月の **総つがい数** を並べると **フィボナッチ数列** になることを確認する.

~~~ text
runSim 6  ==>  [1,1,2,3,5,8,13]
~~~

### Exercise CH12-4

**個体群 — 公理からフィボナッチへ**

1. **`step :: Population -> Population`** — 公理 2 本 (`young (step p) = adult p`, `adult (step p) = total p`) を満たすように 1 か月更新を実装してください. マトリクスをそのまま写せば `step (Population y a) = Population a (a + y)` になります.
2. **公理の検証** — 公理 2 本と, 導出した帰結 `total (step (step p)) = total (step p) + total p` (フィボナッチ) を property にして `quickCheck` してください (`Arbitrary Population` は配布).
3. **`tick :: State Population Integer`** — `modify step` で 1 か月進め, `gets total` でその月の総数を返す (fp11).
4. **`simulate n = replicateM n tick`** — `n` か月分の総数列.
5. **`runSim :: Int -> [Integer]`** — 初期総数から `n` か月目までの列.
6. **`main`** — シミュレーション結果を表示.

<details class="protected" data-pass="yakagika">
    <summary> 回答例 </summary>

~~~ haskell
import Control.Monad (replicateM)
import Control.Monad.State
import Test.QuickCheck hiding (total)   -- QuickCheck も total という名前を持つため

-- 個体群: 若いつがい young と 成熟つがい adult (fp7 record)
data Population = Population { young :: Integer, adult :: Integer }
  deriving (Show, Eq)

total :: Population -> Integer
total (Population y a) = y + a

-- 1 か月: 若いつがいは成熟し, 成熟つがいは新たな若いつがいを 1 組産む
step :: Population -> Population
step (Population y a) = Population a (a + y)

-- State: 1 か月進めて, その時点の総数を返す (fp11)
tick :: State Population Integer
tick = do
  modify step
  gets total

simulate :: Int -> State Population [Integer]
simulate n = replicateM n tick

initialPop :: Population
initialPop = Population 1 0   -- 最初は若いつがい 1 組

-- 0 か月目から n か月目までの総数列
runSim :: Int -> [Integer]
runSim n = total initialPop : evalState (simulate n) initialPop

main :: IO ()
main = mapM_ print (runSim 12)

-- ── 検証: 遷移の公理を property に ──

instance Arbitrary Population where
  arbitrary = Population <$> (abs <$> arbitrary) <*> (abs <$> arbitrary)

prop_young_step :: Population -> Bool
prop_young_step p = young (step p) == adult p

prop_adult_step :: Population -> Bool
prop_adult_step p = adult (step p) == total p

prop_fib :: Population -> Bool
prop_fib p = total (step (step p)) == total (step p) + total p
~~~

## 選択課題D: Bag と Set — 公理が値を同一視する

Stack の公理は「観測がどう応えるか」を決めるだけでした. この課題では新しい種類の公理 — **構築子どうしの等式** — が登場します. それは「異なる作り方で作った値を同じとみなす」働きをします. 純粋なライブラリ課題で, `IO` はありません.

### シグネチャと公理

**Bag (多重集合)** は「順序は数えない・重複は数える」入れ物です.

~~~ haskell
class BagSig t where
  emptyBag :: t a                       -- 構築子: 空
  insert   :: Eq a => a -> t a -> t a   -- 構築子: 1 つ入れる
  count    :: Eq a => a -> t a -> Int   -- 観測子: y は何個あるか
  size     :: t a -> Int                -- 観測子: 全部で何個か
~~~

観測子×構築子マトリクス:

| | `emptyBag` | `insert x b` |
|---|---|---|
| `count y` | `0` | `?` (`x == y` かどうかで場合分け) |
| `size` | `0` | `1 + size b` |

そしてマトリクスの **外側** に, 構築子どうしの公理を 1 本足します.

~~~ text
insert x (insert y b) = insert y (insert x b)   -- 可換律: 入れる順序は観測できない
~~~

この公理は `1` を入れてから `2` を入れた Bag と, `2` を入れてから `1` を入れた Bag — リストで実装すれば `[2,1]` と `[1,2]` — を **同じ値** と宣言します. すると「等しさ (`==`) をどう定義するか」が問われます. 構造そのままの `deriving Eq` では, この 2 つは別物と判定されて可換律が破れてしまうからです.

### Exercise CH12-5

**Bag — 順序を忘れる入れ物**

1. **公理の完成** — マトリクスの `?` (`count y (insert x b)`) を埋めてください.
2. **`ListBag` の実装** — リストで持つモデル `newtype ListBag a = ListBag [a]` に `BagSig` インスタンスを与えてください. `insert` はリストの先頭に足すだけで構いません.
3. **観測的な等しさ** — `deriving Eq` の代わりに `Eq` インスタンスを手書きしてください: 並べ替えて等しければ等しい (`sort xs == sort ys`. `import Data.List (sort)` と `Ord a` 制約が要ります). これで可換律の両辺が「等しい」と判定できるようになります.
4. **公理の検証** — `count` / `size` / 可換律の property を埋めて `quickCheck` してください.
5. **発展: Set へ** — 公理をもう 1 本足します: `insert x (insert x b) = insert x b` (**冪等律**: 重複も観測できない). まず `ListBag` に対してこの property を走らせ, **反例が表示されて落ちる** ことを確認してください — QuickCheck が「公理を満たさない実装」を検出する瞬間です. そのうえで, 挿入時に重複を捨てるモデル `ListSet` を作り, 冪等律が通ることを確認してください. なお冪等律を足すと `count` と `size` の公理はそのままでは成り立ちません — 公理は独立ではなく, 1 本足すと他の公理を書き直すことになります.

<details class="protected" data-pass="yakagika">
    <summary> 回答例 </summary>

~~~ haskell
import Data.List (sort, nub)
import Test.QuickCheck

class BagSig t where
  emptyBag :: t a
  insert   :: Eq a => a -> t a -> t a
  count    :: Eq a => a -> t a -> Int
  size     :: t a -> Int

-- Bag: リストで持ち, 等しさは「並べ替えて同じ」(観測的 Eq)
newtype ListBag a = ListBag [a] deriving Show

instance Ord a => Eq (ListBag a) where
  ListBag xs == ListBag ys = sort xs == sort ys

instance BagSig ListBag where
  emptyBag              = ListBag []
  insert x (ListBag xs) = ListBag (x : xs)
  count y (ListBag xs)  = length (filter (== y) xs)
  size (ListBag xs)     = length xs

-- Set: 挿入時に重複を捨てる (冪等律を満たすモデル)
newtype ListSet a = ListSet [a] deriving Show

instance Ord a => Eq (ListSet a) where
  ListSet xs == ListSet ys = sort (nub xs) == sort (nub ys)

instance BagSig ListSet where
  emptyBag = ListSet []
  insert x s@(ListSet xs)
    | x `elem` xs = s
    | otherwise   = ListSet (x : xs)
  count y (ListSet xs) = length (filter (== y) xs)
  size (ListSet xs)    = length xs

-- 「任意の Bag/Set」も構築子で作る
instance (Arbitrary a, Eq a) => Arbitrary (ListBag a) where
  arbitrary = foldr insert emptyBag <$> listOf arbitrary

instance (Arbitrary a, Eq a) => Arbitrary (ListSet a) where
  arbitrary = foldr insert emptyBag <$> listOf arbitrary

-- 公理 property
prop_count_empty :: Int -> Bool
prop_count_empty y = count y (emptyBag :: ListBag Int) == 0

prop_count_insert :: Int -> Int -> ListBag Int -> Bool
prop_count_insert y x b =
  count y (insert x b) == (if x == y then 1 else 0) + count y b

prop_size_insert :: Int -> ListBag Int -> Bool
prop_size_insert x b = size (insert x b) == 1 + size b

prop_comm :: (BagSig t, Eq (t Int)) => Int -> Int -> t Int -> Bool
prop_comm x y b = insert x (insert y b) == insert y (insert x b)

prop_idem :: (BagSig t, Eq (t Int)) => Int -> t Int -> Bool
prop_idem x b = insert x (insert x b) == insert x b
~~~

実行例:

~~~ text
ghci> quickCheck (prop_comm :: Int -> Int -> ListBag Int -> Bool)
+++ OK, passed 100 tests.
ghci> quickCheck (prop_idem :: Int -> ListBag Int -> Bool)
*** Failed! Falsified (after 1 test): ...        -- Bag は冪等でない (反例が出る)
ghci> quickCheck (prop_idem :: Int -> ListSet Int -> Bool)
+++ OK, passed 100 tests.
~~~

勘所: 可換律は「作り方の違いを観測できない」と宣言する公理で, 実装側はそれに合わせて **等しさそのものを設計** することになります (`sort` してから比較 = 順序という情報を捨てる). これは[第8章](fp8.html)の `Z3` が「3 で割った余りが同じ数を同一視」したのと同じ発想です — 公理が値の世界を粗くする. 冪等律まで足せば Bag は Set になり, 対応して `Eq` も `nub` (重複除去) を挟む形に変わります. 公理を 1 本増やすたびに, 観測子の公理と実装の両方が連動して変わる — 公理系は 1 本ずつ独立に足せる部品ではない, というのがこの課題の教訓です.

</details>

## 選択課題E: Queue — 観測的等価と実装非依存 (発展)

導入節の Stack では, 2 つのモデルがどちらも「表現の等値 (`deriving Eq` 相当)」で公理を通せました. この課題では **表現が本質的に異なる 2 つのモデル** を書き, 「観測でしか等しさを語れない」状況を体験します. 純粋なライブラリ課題で, `IO` はありません.

### シグネチャと公理

**Queue (待ち行列)** は先入れ先出し (FIFO) の入れ物です.

~~~ haskell
class QueueSig t where
  emptyQ   :: t a
  enqueue  :: a -> t a -> t a   -- 構築子: 末尾に並ぶ
  front    :: t a -> a          -- 観測子: 先頭を見る
  dequeue  :: t a -> t a        -- 派生:   先頭が抜ける
  isEmptyQ :: t a -> Bool       -- 観測子: 空か
~~~

マトリクスを埋めると, Stack との違いが現れます. `front (enqueue x q)` の答えは「`q` が空かどうか」で変わるのです (先に並んでいた人が優先される).

| | `emptyQ` | `enqueue x q` |
|---|---|---|
| `isEmptyQ` | `True` | `False` |
| `front` | (未規定) | `if isEmptyQ q then x else front q` |
| `dequeue` | (未規定) | `if isEmptyQ q then emptyQ else enqueue x (dequeue q)` |

マスの中に **条件分岐と再帰** が現れました — 公理が「先に入れたものが先に出る」という時間的な性質を語るためです.

### Exercise CH12-6

**Queue — 2 つのモデルと観測的等価**

1. **素朴なモデル `SimpleQueue`** — リストの先頭が `front`, 末尾へ `enqueue` (`xs ++ [x]`) するモデルを実装してください.
2. **2 本リストのモデル `TwoListQueue`** — `data TwoListQueue a = TwoListQueue [a] [a]` (前列と後列). `enqueue` は後列の先頭に足すだけ (`++` しない), `front` / `dequeue` は前列から取り, 前列が尽きたら後列を `reverse` して前列に移します. 不変条件「前列が空なら後列も空」を保つ補助関数を作ると書きやすいです.
3. **観測的等価** — `TwoListQueue` では同じキューが複数の表現を持ちます (`TwoListQueue [1] [2]` と `TwoListQueue [1,2] []` はどちらも 1, 2 の順の待ち行列). `deriving Eq` は使えません. 観測列を取り出す `toListQ` (先頭から全部読む) を書き, `q1 == q2 = toListQ q1 == toListQ q2` と **観測で** `Eq` を定義してください.
4. **公理の検証** — マトリクスの公理 3 本を property にして, **両方のモデル** で `quickCheck` してください.
5. **モデル間の一致** — 同じ操作列を 2 つのモデルに与えて観測列が一致する property を確認してください. 「仕様は 1 つ, モデルは複数」の総仕上げです.

<details class="protected" data-pass="yakagika">
    <summary> 回答例 </summary>

~~~ haskell
import Test.QuickCheck

class QueueSig t where
  emptyQ   :: t a
  enqueue  :: a -> t a -> t a
  front    :: t a -> a
  dequeue  :: t a -> t a
  isEmptyQ :: t a -> Bool

-- モデル 1: 素朴 (末尾へ ++)
newtype SimpleQueue a = SimpleQueue [a] deriving (Show, Eq)

instance QueueSig SimpleQueue where
  emptyQ                         = SimpleQueue []
  enqueue x (SimpleQueue xs)     = SimpleQueue (xs ++ [x])
  front (SimpleQueue (x : _))    = x
  front (SimpleQueue [])         = error "front: empty queue"
  dequeue (SimpleQueue (_ : xs)) = SimpleQueue xs
  dequeue (SimpleQueue [])       = error "dequeue: empty queue"
  isEmptyQ (SimpleQueue xs)      = null xs

-- モデル 2: 前列と後列 (enqueue が O(1))
data TwoListQueue a = TwoListQueue [a] [a] deriving Show

-- 不変条件: 前列が空なら後列も空
fixup :: [a] -> [a] -> TwoListQueue a
fixup [] back = TwoListQueue (reverse back) []
fixup f  back = TwoListQueue f back

instance QueueSig TwoListQueue where
  emptyQ                            = TwoListQueue [] []
  enqueue x (TwoListQueue f b)      = fixup f (x : b)
  front (TwoListQueue (x : _) _)    = x
  front (TwoListQueue [] _)         = error "front: empty queue"
  dequeue (TwoListQueue (_ : f) b)  = fixup f b
  dequeue (TwoListQueue [] _)       = error "dequeue: empty queue"
  isEmptyQ (TwoListQueue f _)       = null f

-- 観測列: 先頭から全部読む
toListQ :: QueueSig t => t a -> [a]
toListQ q
  | isEmptyQ q = []
  | otherwise  = front q : toListQ (dequeue q)

-- 観測的等価: 同じキューが複数の表現を持つので, 観測列で比べる
instance Eq a => Eq (TwoListQueue a) where
  q1 == q2 = toListQ q1 == toListQ q2

instance Arbitrary a => Arbitrary (SimpleQueue a) where
  arbitrary = foldr enqueue emptyQ <$> listOf arbitrary

instance Arbitrary a => Arbitrary (TwoListQueue a) where
  arbitrary = foldr enqueue emptyQ <$> listOf arbitrary

-- 公理 property (どのモデルでも同じ式)
prop_isEmpty_enq :: QueueSig t => Int -> t Int -> Bool
prop_isEmpty_enq x q = not (isEmptyQ (enqueue x q))

prop_front_enq :: QueueSig t => Int -> t Int -> Bool
prop_front_enq x q = front (enqueue x q) == (if isEmptyQ q then x else front q)

prop_deq_enq :: (QueueSig t, Eq (t Int)) => Int -> t Int -> Bool
prop_deq_enq x q =
  dequeue (enqueue x q) == (if isEmptyQ q then emptyQ else enqueue x (dequeue q))

-- モデル間の一致: 同じ操作列 → 同じ観測列
prop_models_agree :: [Int] -> Bool
prop_models_agree xs =
  toListQ (mk xs :: SimpleQueue Int) == toListQ (mk xs :: TwoListQueue Int)
  where
    mk :: QueueSig t => [Int] -> t Int
    mk = foldl (flip enqueue) emptyQ
~~~

勘所: `TwoListQueue` は `enqueue` が定数時間になる実用的な設計 (関数型キューの定石) ですが, その代償として **同じキューに複数の内部表現** が生まれます. `TwoListQueue [1] [2]` と `TwoListQueue [1,2] []` は構造としては別物なのに, `front` と `dequeue` で観測する限り区別できません — だから等しさを観測列 (`toListQ`) で定義します. これが **観測的等価** で, 「公理 (観測) に現れないことは仕様に含まれない」の徹底です. `prop_models_agree` は 2 つのモデルが仕様のレベルで交換可能なことを直接確かめています — `SimpleQueue` で正しさを確かめてから `TwoListQueue` に差し替える, という「遅い参照実装 → 速い本実装」の開発手順は, 実務でもそのまま使われます. なお `mk` に型注釈を付けているのは, 注釈なしでは `mk` が 1 つの型に固定されてしまい 2 つのモデルで使い回せないためです.

</details>
