[第5章](fp5.html)で「実は後に出てくる `State` や `ST` など, Haskell でも再代入 (破壊的代入) を扱うことはできます」と予告しました. 本章はその回収です. カウンタ, 連番付け, 疑似乱数, ログのような「**変数を更新しながら進む**」計算を, 純粋性 ([第1章](fp1.html)) を保ったまま書く方法を扱います.

道具立ては[第10章](fp10.html)で完成しています. `Maybe`・`Either`・リスト・`IO` はどれも「自己関手 + $\eta$ + $\mu$」というモナドの骨格に載り, 違いは値に付いてくるパターンの中身だけでした. 本章はこのカタログを広げます. 新しく加わる仲間 (`State`・`Reader`・`Writer`) は, `Maybe` やリストと違って **場合分けのパターンを持ちません**. 構築子は 1 つだけで, 値を 1 つ包むだけのデータ型です. その代わり, 包まれている値そのものが **関数や組** になっていて, そこに「状態の受け渡し」「環境の参照」「ログの蓄積」という仕事が畳み込まれています.

なお, 本講義で「パターン」と呼んできたもの, すなわちモナドごとの `>>=` の振る舞いの違いは, 文献では **効果 (effect)** と呼ばれます. 章題の「効果」はこの意味です. 本章でカタログが広がると, 「`Maybe` は失敗という効果を, `State` は状態という効果を持つ」という文献の言い回しが, そのまま読めるようになります.

# 状態を運ぶ計算

## 再代入という需要

手続き型言語では, 「番号を 1 つ取り出すたびにカウンタを進める」「乱数を 1 つ引くたびに種を更新する」といった計算を, 変数への **再代入** で書きます.

~~~ python
counter = 0          # 隠れた状態

def fresh():
    global counter
    n = counter
    counter = counter + 1   # 再代入
    return n

fresh()   # 0
fresh()   # 1  (同じ呼び出しなのに, 返る値が毎回違う)
~~~

Haskell にこの書き方はありません. [第5章](fp5.html)で見たとおり, `=` は定義であって代入ではなく, 一度束縛した名前を上書きすることはできません. `fresh()` のような「同じ入力 (引数なし) なのに毎回違う値を返す関数」は, 参照透過性 ([第10章](fp10.html)) を壊すからです.

しかし「呼ぶたびに違う番号を返すカウンタ」に相当する計算が書けないわけではありません. 鍵は, 隠れて書き換えられていた `counter` を, **引数と返り値として表に出す** ことです.

## 状態を引数と返り値で運ぶ

純粋関数が状態を扱う道は 1 本しかありません. いまの状態 `s` を **引数で受け取り**, 計算の結果 `a` と **更新後の状態** を **組で返す** ことです. 型は `s -> (a, s)` になります.

~~~ haskell
-- カウンタ: いまの番号を結果として返し, 状態を 1 進める
tick :: Int -> (Int, Int)
tick n = (n, n + 1)

main :: IO ()
main = do
  print (tick 0)   -- (0,1)
  print (tick 5)   -- (5,6)
~~~

`tick` は純粋です. 同じ入力には必ず同じ出力を返します. 「更新」は書き換えではなく, 新しい状態を **値として返す** ことで表しています. 3 回連続で番号を取るには, 返ってきた状態を次の呼び出しへ **手で** 渡します.

~~~ haskell
tick :: Int -> (Int, Int)
tick n = (n, n + 1)

three :: Int -> ((Int, Int, Int), Int)
three s0 =
  let (a, s1) = tick s0
      (b, s2) = tick s1
      (c, s3) = tick s2
  in  ((a, b, c), s3)

main :: IO ()
main = do
  print (three 0)   -- ((0,1,2),3)
~~~

動きはしますが, この書き方には 2 つの問題があります.

- **配管が本体を覆い隠す**: やりたいことは「3 回番号を取る」だけなのに, 行数の大半が `s0`, `s1`, `s2`, `s3` の受け渡しです.
- **取り違えを型が守れない**: 2 行目を誤って `tick s0` と書いても型は合ってしまい, 同じ番号が 2 回出るバグに気づけません.

欲しいものははっきりしています. 「**状態を後ろへ素通しで受け渡しながら, 結果だけを次の計算へつなぐ**」という定型の配管を, 1 つの演算にくくり出すことです. 「結果を次へつなぐ演算」は[第10章](fp10.html)で手作りしました. `bind` です. あれの状態版を作ればよいのです.

# State モナド

## 状態渡しを型にする

まず「状態を運ぶ計算」そのものに型を与えます. `newtype` は[第8章](fp8.html)で使った「既存の型を包んで新しい型と区別を与える」宣言です.

~~~ haskell
newtype State s a = State { runState :: s -> (a, s) }
~~~

`State` は構築子 (型 `(s -> (a, s)) -> State s a` の関数), `runState` は中身の関数を取り出すアクセサです. ここでパターンの目で見ておきます. `Maybe a` には `Nothing` / `Just x` という 2 つのパターンがありました. `State s a` のパターンは `State f` の **1 つだけ** で, 場合分けはありません. その代わり, 包まれている値 `f` が **関数** `s -> (a, s)` です. 場合分けの仕事がない代わりに, 「状態を受け渡す」という配管の仕事が, この関数の形に畳み込まれています.

この型の上で, [第10章](fp10.html)の `bind` の状態版を手作りします.

~~~ haskell
-- (newtype State は上の定義をそのまま使う)
bindS :: State s a -> (a -> State s b) -> State s b
bindS m f = State $ \s0 ->
  let (x, s1) = runState m s0   -- 前の計算を s0 で走らせ, 結果 x と状態 s1 を得る
  in  runState (f x) s1         -- 結果 x から次の計算を作り, s1 で走らせる
~~~

`Maybe` の `bind` が「`Nothing` なら止める / `Just x` なら渡す」という **場合分け** だったのに対し, `bindS` に場合分けはありません. やることは **配管** だけです. 状態 `s0` で前の計算を走らせ, 出てきた結果 `x` を次の計算 `f` に渡し, 更新後の状態 `s1` でその計算を走らせる. これで `three` を書き直せます.

~~~ haskell
-- (newtype State, bindS は上の定義をそのまま使う)
tickS :: State Int Int
tickS = State $ \n -> (n, n + 1)

threeS :: State Int (Int, Int, Int)
threeS =
  tickS `bindS` \a ->
  tickS `bindS` \b ->
  tickS `bindS` \c ->
  State $ \s -> ((a, b, c), s)

main :: IO ()
main = do
  print (runState threeS 0)   -- ((0,1,2),3)
~~~

`s0` から `s3` までの手渡しが本文から消えました. 状態の受け渡しは `bindS` の中に 1 回だけ書かれ, 利用側は「結果 `a`, `b`, `c` を束縛して組を返す」というやりたいことだけを書いています. 最終行の「状態に触らず素の値を返すだけの計算」も, [第10章](fp10.html)の道具でいえば $\eta$ (`pure`) の State 版です. ここまで来れば, 正体は見えています.

## State の正体

[第10章](fp10.html)のレシピをそのまま繰り返します. **関手にして, $\eta$ と $\mu$ を足し, モナド則を確かめる** です. 状態の型 `s` を 1 つ固定すると, 台になる関手は

$$T\,a \;=\; s \to (a \times s)$$

です. Haskell では `State s` (型引数を 1 つ残した部分適用. [第9章](fp9.html)の `Either a` と同じ形) がこれにあたります.

**関手**. `fmap` は「結果の側だけ」を変換します. 状態の配管には触りません.

~~~ haskell
-- (newtype State は上の定義をそのまま使う)
fmapS :: (a -> b) -> State s a -> State s b
fmapS g m = State $ \s ->
  let (x, s') = runState m s
  in  (g x, s')
~~~

**単位 $\eta$**. 素の値を「状態に触らない計算」として包みます.

$$\eta_a : a \to T\,a, \qquad \eta_a(x) = \lambda s.\,(x,\ s)$$

~~~ haskell
pureS :: a -> State s a
pureS x = State $ \s -> (x, s)
~~~

**乗法 $\mu$**. 入れ子 $T\,(T\,a)$ は「走らせると, 続きの計算がもう 1 つ出てくる計算」です. 潰し方は 1 通りしかありません. 外側を走らせ, 出てきた内側の計算を **続きの状態で** 走らせます.

$$\mu_a : T\,(T\,a) \to T\,a, \qquad \mu_a(mm) = \lambda s.\ \mathrm{let}\ (m,\ s') = mm\,s\ \ \mathrm{in}\ \ m\,s'$$

~~~ haskell
joinS :: State s (State s a) -> State s a
joinS mm = State $ \s ->
  let (m, s') = runState mm s
  in  runState m s'
~~~

[第10章](fp10.html)の等式 $\texttt{bind}\ m\ f = \mu(\texttt{fmap}\ f\ m)$ はここでも成り立ちます. `fmapS f m` は「走らせると次の計算が出てくる計算」(型 `State s (State s b)`) を作り, `joinS` がその入れ子を 1 本の配管に潰します. 展開すると, 先ほど手書きした `bindS` とまったく同じ let の連鎖になります.

**モナド則**. 単位律の片側を手で確かめてみます. `joinS (pureS m)` を展開すると, `pureS m` は `\s -> (m, s)` なので, `joinS` はこれを状態 `s` で走らせて組 `(m, s)` を受け取り, `m` を `s` で走らせます. 全体は `\s -> runState m s`, すなわち `m` 自身です. `Maybe` のときのような場合分けは現れず, すべて let の展開だけで両辺が一致します. 結合律ともう片側の単位律も同様です.

## インスタンスを自分の手で書く

[第9章](fp9.html)では `Box` や `Tree` を `Functor` にしました. [第10章](fp10.html)の `Maybe` やリストでは, 標準ライブラリが書いたインスタンスを **使う側** でした. `State` は自作の型なので, 今度は `Functor` → `Applicative` → `Monad` の 3 つを **作る側** に回って書きます. 中身はすべて前節の部品です.

~~~ haskell
newtype State s a = State { runState :: s -> (a, s) }

instance Functor (State s) where
  fmap g m = State $ \s ->
    let (x, s') = runState m s
    in  (g x, s')

instance Applicative (State s) where
  pure x = State $ \s -> (x, s)
  mf <*> mx = State $ \s ->
    let (g, s1) = runState mf s
        (x, s2) = runState mx s1
    in  (g x, s2)

instance Monad (State s) where
  m >>= f = State $ \s ->
    let (x, s1) = runState m s
    in  runState (f x) s1

tickS :: State Int Int
tickS = State $ \n -> (n, n + 1)

threeS :: State Int (Int, Int, Int)
threeS = do
  a <- tickS
  b <- tickS
  c <- tickS
  pure (a, b, c)

main :: IO ()
main = do
  print (runState threeS 0)    -- ((0,1,2),3)
  print (runState threeS 10)   -- ((10,11,12),13)
~~~

読みどころは 3 つです.

- インスタンスになるのは `State s` (状態の型 `s` を固定した 1 引数の型構築子) です. `pure` は `pureS`, `>>=` は `bindS` そのものです.
- `<*>` (独立な計算の組み合わせ) でも, 状態の通り道は 1 本です. `Maybe` の `<*>` が「両方成功したときだけ」だったのに対し, `State` の `<*>` は「左を走らせ, その続きの状態で右を走らせる」という **左から右への順序** を持ちます.
- `Monad` インスタンスが書けた瞬間に, [第10章](fp10.html)の `do` 記法がそのまま使えるようになります. `threeS` は手書き配管の `three` と同じ計算ですが, 状態の名前は 1 つも登場しません.

## 状態を読み書きする部品

`do` の中で状態を読み書きするための小さな部品を 4 つ定義します. どれも中身は 1 行です.

~~~ haskell
-- (newtype State と instance 宣言は上の定義をそのまま使う)
get :: State s s                    -- いまの状態を, 結果として読み出す
get = State $ \s -> (s, s)

put :: s -> State s ()              -- 状態を書き換える (結果は「情報なし」の ())
put s = State $ \_ -> ((), s)

modify :: (s -> s) -> State s ()    -- 関数を適用して状態を更新する
modify f = State $ \s -> ((), f s)

gets :: (s -> a) -> State s a       -- 状態の一部を読み出す
gets f = State $ \s -> (f s, s)
~~~

仕上げに, 計算を走らせる関数を 3 つ揃えます. `runState` は結果と最終状態の両方を返しますが, 片方しか要らない場面が多いためです.

~~~ haskell
-- (newtype State は上の定義をそのまま使う)
evalState :: State s a -> s -> a    -- 結果だけ
evalState m s = fst (runState m s)

execState :: State s a -> s -> s    -- 最終状態だけ
execState m s = snd (runState m s)
~~~

これで冒頭の Python の `fresh` を, そのまま Haskell に翻訳できます.

~~~ haskell
-- (newtype State, instance, get, put は上の定義をそのまま使う)
fresh :: State Int Int
fresh = do
  n <- get         -- いまの番号を読み
  put (n + 1)      -- 1 進めて
  pure n           -- 読んだ番号を結果として返す

main :: IO ()
main = do
  print (runState (do a <- fresh; b <- fresh; pure (a, b)) 0)   -- ((0,1),2)
~~~

Python 版と 1 行ずつ対応していることを確かめてください. `global counter` の代わりに型 `State Int` が「どの状態を触るのか」を宣言し, 再代入の代わりに `put` が新しい状態を **返して** います. 見た目は再代入のプログラムそのままで, 実体は最初に手書きした `tick` の配管です.

## カウンタから疑似乱数まで

部品が揃ったので, 実例を 3 つ見ます.

**連番ラベル付け.** [第10章](fp10.html)の `forM` はリスト専用の道具ではなく, 任意のモナドで使えました. `State` と組むと「リストを回しながら番号を進める」が 1 つの式になります.

~~~ haskell
import Control.Monad (forM)
-- (newtype State, instance, fresh, evalState は上の定義をそのまま使う)

label :: [String] -> [(Int, String)]
label xs = evalState (forM xs step) 0
  where
    step x = do
      n <- fresh
      pure (n, x)

main :: IO ()
main = do
  print (label ["apple", "orange", "grape"])
  -- [(0,"apple"),(1,"orange"),(2,"grape")]
~~~

**疑似乱数.** 乱数列の生成は「種 (seed) を更新しながら 1 つずつ値を取り出す」計算そのもので, 隠れた状態の代表例です. もっとも古典的な **線形合同法 (LCG)** は, 次の漸化式で種を更新します.

$$x_{n+1} = (1103515245\, x_n + 12345) \bmod 2^{31}$$

~~~ haskell
-- (newtype State, instance, get, modify は上の定義をそのまま使う)
lcgStep :: Int -> Int
lcgStep x = (1103515245 * x + 12345) `mod` 2147483648

nextRand :: State Int Int    -- 種を進めて, 新しい種を乱数として返す
nextRand = do
  modify lcgStep
  get

die :: State Int Int         -- サイコロ: 1 から 6 の目
die = do
  r <- nextRand
  pure (r `mod` 6 + 1)
~~~

同じ計算を $n$ 回走らせて結果を集めるには `replicateM :: Applicative m => Int -> m a -> m [a]` (`Control.Monad`) を使います. サイコロを 5 回振る計算が 1 行になります.

~~~ haskell
import Control.Monad (replicateM)
-- (newtype State, instance, die, evalState などは上の定義をそのまま使う)

rolls :: Int -> Int -> [Int]   -- rolls 種 回数
rolls seed n = evalState (replicateM n die) seed

main :: IO ()
main = do
  print (rolls 2026 5)   -- [4,5,4,3,4]
  print (rolls 2026 5)   -- [4,5,4,3,4]  (同じ種からは必ず同じ列)
  print (rolls 1 5)      -- [1,4,5,2,5]
~~~

「いかにも副作用」に見える乱数も, 種の受け渡しを `State` に任せれば純粋関数です. 同じ種からは必ず同じ列が出るので **再現性** があり, テストやシミュレーションではこの性質がむしろ強みになります.

::: note
**標準ライブラリの State.** 本章の `State` は教材用の自作ですが, 定義も API もそのままの形で標準的なパッケージ **mtl** (`Control.Monad.State`) にあります. `get` / `put` / `modify` / `gets` / `runState` / `evalState` / `execState` はすべて同名です. [第12章](fp12.html)の総合演習では `import Control.Monad.State` としてそちらを使いますが, 読み替えは一切要りません.
:::

### Exercise CH11-1

**手書きの配管から State へ**

番号を 2 つ取り出して組にする計算を考えます. まず仕様を等式で定めます.

$$\texttt{runState}\ \texttt{pairFresh}\ s = ((s,\ s + 1),\ s + 2)$$

1. `State` を使わず, 手書きの配管 (本文の `three` と同じ形) で `pairFresh0 :: Int -> ((Int, Int), Int)` を実装してください.
2. 本文の `State` と `fresh` を使い, `pairFresh :: State Int (Int, Int)` を `do` 記法で実装してください.
3. `main` で両者に `0` と `10` を与え, どちらも仕様の等式どおりになることを確かめてください.

<details class="protected" data-pass="yakagika">
    <summary> 回答例 </summary>

~~~ haskell
-- (newtype State, instance, get, put, fresh は本文の定義をそのまま使う)
pairFresh0 :: Int -> ((Int, Int), Int)
pairFresh0 s0 =
  let (a, s1) = tick s0
      (b, s2) = tick s1
  in  ((a, b), s2)
  where
    tick n = (n, n + 1)

pairFresh :: State Int (Int, Int)
pairFresh = do
  a <- fresh
  b <- fresh
  pure (a, b)

main :: IO ()
main = do
  print (pairFresh0 0)            -- ((0,1),2)
  print (runState pairFresh 0)    -- ((0,1),2)
  print (pairFresh0 10)           -- ((10,11),12)
  print (runState pairFresh 10)   -- ((10,11),12)
~~~

2 つの実装は同じ仕様を満たしますが, 手書き版は `s0`, `s1`, `s2` の配管が本文に露出し, `State` 版は配管が `>>=` (do 記法) の中に隠れています.

</details>

  s <- get

# 本物の可変セル

`State` は **シミュレーション** です. メモリを書き換えているわけではなく, 新しい状態の値を作って配管が運んでいるだけです. ほとんどの場面はこれで足りますが, 本当にメモリの 1 箇所を書き換えたい場面もあります. 大きな配列の一部だけを何万回も更新する, プログラム全体で 1 つのカウンタを共有する, といった場面です. Haskell はそのための **可変セル** を用意しています. ただし置き場所によって型が変わります.

## IORef

1 つ目の置き場所は, [第10章](fp10.html)の `IO` の中です. `Data.IORef` の `IORef a` は「型 `a` の値を 1 つ入れられる, 本物の可変セル」です.

~~~ haskell
import Data.IORef

main :: IO ()
main = do
  ref <- newIORef (0 :: Int)   -- セルを作る (初期値 0)
  modifyIORef ref (+ 1)        -- 中身を書き換える
  modifyIORef ref (+ 1)
  n <- readIORef ref           -- 読み出す
  print n                      -- 2
~~~

API は 4 つです. `newIORef :: a -> IO (IORef a)` (セルを作る), `readIORef` (読む), `writeIORef` (書く), `modifyIORef` (関数で更新する). 4 つとも返り値が `IO` に包まれていることに注意してください. 本物の書き換えは実行順に意味がある **外の世界への作用** なので, `IO` のアクションとしてしか触れないのです.

リストの合計を, わざと `IORef` で書いてみます.

~~~ haskell
import Data.IORef
import Control.Monad (forM_)

sumWithRef :: [Int] -> IO Int
sumWithRef xs = do
  ref <- newIORef 0
  forM_ xs $ \x ->
    modifyIORef ref (+ x)
  readIORef ref

main :: IO ()
main = do
  total <- sumWithRef [1 .. 100]
  print total   -- 5050
~~~

動きますが, 型を見てください. `sumWithRef :: [Int] -> IO Int` です. 中身はただの足し算なのに, 型の上では `getLine` や `print` と同じ「外の世界に触るかもしれない計算」になってしまいました. [第10章](fp10.html)で手に入れた「副作用は型で区別する」の恩恵, つまり型を見れば純粋と分かる保証が失われ, しかもこの `IO` は `sumWithRef` を呼ぶ側にも伝染していきます.

## ST モナド

「可変セルは使いたい. しかし書き換えはこの関数の中に閉じていて, 外から見れば純粋な関数のはずだ」という場面のための道具が **ST モナド** (`Control.Monad.ST`) です. 同じ合計を `ST` で書きます.

~~~ haskell
import Control.Monad.ST
import Data.STRef
import Control.Monad (forM_)

sumWithCell :: [Int] -> Int      -- IO が付かない!
sumWithCell xs = runST $ do
  ref <- newSTRef 0
  forM_ xs $ \x ->
    modifySTRef ref (+ x)
  readSTRef ref

main :: IO ()
main = do
  print (sumWithCell [1 .. 100])   -- 5050
~~~

中身は `sumWithRef` と 1 対 1 です (`IORef` が `STRef` に変わっただけ). 違いは最後に `runST` で計算を **走らせて値を取り出している** ことと, その結果, 型から `IO` が消えていることです. `sumWithCell` は型の上でも純粋な関数で, どこからでも呼べます.

これを可能にしているのが `runST` の型です.

$$\texttt{runST} :: (\forall s.\ \texttt{ST}\ s\ a) \to a$$

型変数 `s` はセルが属する **領域 (region)** の目印で, 対応する値を持ちません (このような型変数を **ファントム型** と呼びます). 引数の位置に付いた `forall s.` は「**どの領域でも同じように動く計算だけを受け付ける**」という条件で, これによって「セル (`STRef s a`) が領域の外へ漏れていないこと」を型検査器が見張ります. 例えばセル自体を返そうとする `runST (newSTRef 0)` は型エラーになります. 引数の中に `forall` を書くこの形は **rank-2 多相** と呼ばれる発展機能ですが, 本講義では名前の紹介に留めます.

これで[第5章](fp5.html)の予告 (`State` や `ST` で再代入を扱える) は, すべて回収できました.

## 三者の使い分け

| 道具 | 実体 | 型 | 使い所 |
| --- | --- | --- | --- |
| `State s` | 状態渡し `s -> (a, s)` の配管 (書き換えない) | 純粋 | 状態の引き回し. まずはこれ |
| `ST s` | 本物のセル. 領域 `s` に閉じ込める | 純粋 (`runST` で取り出す) | 局所的に性能が欲しいアルゴリズム |
| `IORef` | 本物のセル. 外の世界と共有する | `IO` | プログラムの寿命と共にある共有状態 |

迷ったら `State` です. 純粋でテストしやすく, [第12章](fp12.html)の総合演習でも主役です. 測ってみて性能が足りないときに `ST` を検討し, プログラム全体で共有する状態 (サーバのコネクション数など) だけを `IORef` にします.

::: note

### Exercise CH11-3

**同じ計算を State と ST で**

空でないリストの最小値と最大値を, 1 回の走査で同時に求めます. 仕様は次の等式です (`xs` は空でないとします).

$$\texttt{minMax}\ xs = (\min xs,\ \max xs)$$

1. `State` 版 `minMaxState :: [Int] -> (Int, Int)` を実装してください. 状態は「(これまでの最小, これまでの最大)」の組とし, 先頭要素で初期化して残りを `forM_` で回し, `execState` で最終状態を取り出します.
2. `ST` 版 `minMaxST :: [Int] -> (Int, Int)` を実装してください. `STRef` を 2 本使います.
3. 2 つの実装の型を見比べ, どちらにも `IO` が現れないことを確かめてください.

<details class="protected" data-pass="yakagika">
    <summary> 回答例 </summary>

~~~ haskell
import Control.Monad (forM_)
import Control.Monad.ST
import Data.STRef
-- (newtype State, instance, modify, execState は本文の定義をそのまま使う)

minMaxState :: [Int] -> (Int, Int)
minMaxState (x : xs) = execState (forM_ xs step) (x, x)
  where
    step y = modify (\(lo, hi) -> (min lo y, max hi y))
minMaxState [] = error "empty list"

minMaxST :: [Int] -> (Int, Int)
minMaxST (x : xs) = runST $ do
  lo <- newSTRef x
  hi <- newSTRef x
  forM_ xs $ \y -> do
    modifySTRef lo (min y)
    modifySTRef hi (max y)
  l <- readSTRef lo
  h <- readSTRef hi
  pure (l, h)
minMaxST [] = error "empty list"

main :: IO ()
main = do
  print (minMaxState [3, 1, 4, 1, 5, 9, 2, 6])   -- (1,9)
  print (minMaxST    [3, 1, 4, 1, 5, 9, 2, 6])   -- (1,9)
~~~

どちらも型は `[Int] -> (Int, Int)` で, `IO` は現れません. `State` 版は組の値を作り直しながら配管が運び, `ST` 版は 2 本のセルを本当に書き換えますが, 書き換えは `runST` の中に閉じているため, 外から見える性質は同じです.

</details>

:::

# Reader と Writer

`State` は状態の **読み書き両方** ができました. これを「読み取り専用」「書き込み (追記) 専用」に絞った仲間が `Reader` と `Writer` です. どちらも構築子は 1 つで, 包まれた値の形が仕事を決めます.

## Reader モナド

**需要**: 設定 (環境) を, 計算のあちこちで参照したい. 素直には引数で手渡すことになりますが, 深い呼び出しの奥で設定が要ると, **設定を使わない中間の関数にまで** 引数が伝染します. そこで「環境から値への関数」そのものを計算とみなします. 台は `r -> a` です.

~~~ haskell
newtype Reader r a = Reader { runReader :: r -> a }

instance Functor (Reader r) where
  fmap g m = Reader $ \r -> g (runReader m r)

instance Applicative (Reader r) where
  pure x = Reader $ \_ -> x
  mf <*> mx = Reader $ \r -> (runReader mf r) (runReader mx r)

instance Monad (Reader r) where
  m >>= f = Reader $ \r -> runReader (f (runReader m r)) r

ask :: Reader r r                -- 環境そのものを読む
ask = Reader $ \r -> r

asks :: (r -> a) -> Reader r a   -- 環境の一部を読む
asks f = Reader f
~~~

$\eta$ と $\mu$ を数式で見ると, `State` との違いが際立ちます.

$$\eta_a(x) = \lambda r.\ x, \qquad \mu_a(mm) = \lambda r.\ mm\,r\,r$$

$\eta$ は環境を **見ない** 計算, $\mu$ は **同じ環境 `r` を外側と内側の両方に配る** 配管です. `State` と違って環境が更新されて流れていくことはなく, 全員に同じものが素通しで配られます (`put` のない `State` と言ってもよいです).

使ってみます. 税率と通貨記号を設定として持ち, 価格の表示文字列を作る計算です.

~~~ haskell
import Control.Monad (forM)
-- (newtype Reader, instance, asks は上の定義をそのまま使う)

data Config = Config { taxRate :: Double, currencyMark :: String }

priceLabel :: Int -> Reader Config String
priceLabel price = do
  rate <- asks taxRate
  mark <- asks currencyMark
  let total = round (fromIntegral price * (1 + rate)) :: Int
  pure (mark ++ show total)

receipt :: Reader Config [String]
receipt = forM [120, 350, 80] priceLabel

main :: IO ()
main = do
  mapM_ putStrLn (runReader receipt (Config 0.10 "¥"))
  -- ¥132
  -- ¥385
  -- ¥88
  mapM_ putStrLn (runReader receipt (Config 0.08 "¥"))
  -- ¥130
  -- ¥378
  -- ¥86
~~~

(`mapM_` は[第10章](fp10.html)の `forM_` の引数順を入れ替えたものです.) `priceLabel` にも `receipt` にも, 設定を運ぶ引数はありません. それでいて, 最後に `runReader` へ渡す環境 1 つで全体の挙動が切り替わります. 環境の受け渡しは型 `Reader Config` の配管に畳み込まれ, 必要な関数だけが `asks` で取り出しています.

## Writer モナド

**需要**: 計算の本筋とは別に, ログ (メッセージの列や回数) を **追記** していきたい. 台は「値とログの組」`(a, w)` です.

~~~ haskell
newtype Writer w a = Writer { runWriter :: (a, w) }

instance Functor (Writer w) where
  fmap g (Writer (x, w)) = Writer (g x, w)

instance Monoid w => Applicative (Writer w) where
  pure x = Writer (x, mempty)
  Writer (g, w1) <*> Writer (x, w2) = Writer (g x, w1 <> w2)

instance Monoid w => Monad (Writer w) where
  Writer (x, w1) >>= f =
    let Writer (y, w2) = f x
    in  Writer (y, w1 <> w2)

tell :: w -> Writer w ()   -- ログに 1 件追記する
tell w = Writer ((), w)
~~~

インスタンス宣言の `Monoid w =>` に注目してください. ここに[第8章](fp8.html)の **モノイドが部品として** 現れます.

- $\eta$ (`pure`) は「ログなし」を添えます. 「なし」の正体は **単位元 `mempty`** です.
- $\mu$ (`>>=`) は前後のログを **演算 `<>`** で結合します.

つまり `Writer` がモナド則を満たすことは, `w` の **モノイド則から直接従います**. 結合律は `<>` の結合律, 単位律は `mempty` の単位元律そのものです. [第8章](fp8.html)で「組 + 法則」として定義した代数構造が, ここではモナドという別の構造の部品になり, その法則がモナド則の成立を肩代わりしているわけです.

使ってみます. コラッツの操作 (偶数なら 2 で割る, 奇数なら 3 倍して 1 を足す, 1 になったら止める) に, 途中経過のログを付けます.

~~~ haskell
-- (newtype Writer, instance, tell は上の定義をそのまま使う)
step :: Int -> Writer [String] Int
step n
  | even n    = do
      tell [show n ++ " は偶数: 2 で割る"]
      pure (n `div` 2)
  | otherwise = do
      tell [show n ++ " は奇数: 3 倍して 1 を足す"]
      pure (3 * n + 1)

collatz :: Int -> Writer [String] Int
collatz 1 = pure 1
collatz n = step n >>= collatz

main :: IO ()
main = do
  let (result, logs) = runWriter (collatz 6)
  print result          -- 1
  mapM_ putStrLn logs
  -- 6 は偶数: 2 で割る
  -- 3 は奇数: 3 倍して 1 を足す
  -- 10 は偶数: 2 で割る
  -- 5 は奇数: 3 倍して 1 を足す
  -- 16 は偶数: 2 で割る
  -- 8 は偶数: 2 で割る
  -- 4 は偶数: 2 で割る
  -- 2 は偶数: 2 で割る
~~~

`collatz` の本文にログを運ぶ変数はありません. `tell` した断片を `>>=` が `<>` でつないでいきます.

ここでモノイドを **取り替えて** みます. ログを「メッセージの列 `[String]`」から「回数 `Sum Int`」に変えると, 同じ骨組みのまま集計が変わります. `Sum` は[第8章](fp8.html)で自作した `Add` (足し算モノイド) の標準ライブラリ版です (`Data.Monoid`).

~~~ haskell
import Data.Monoid (Sum (..))
-- (newtype Writer, instance, tell は上の定義をそのまま使う)

countStep :: Int -> Writer (Sum Int) Int
countStep n = do
  tell (Sum 1)                                     -- 1 回ぶんを追記
  pure (if even n then n `div` 2 else 3 * n + 1)

countCollatz :: Int -> Writer (Sum Int) Int
countCollatz 1 = pure 1
countCollatz n = countStep n >>= countCollatz

main :: IO ()
main = do
  print (getSum (snd (runWriter (countCollatz 6))))    -- 8
  print (getSum (snd (runWriter (countCollatz 27))))   -- 111
~~~

再帰の骨組み (`countCollatz`) は `collatz` と同じで, 変えたのは `tell` に渡すモノイドだけです. `[String]` なら履歴が残り, `Sum Int` なら回数が集計されます. どちらになるかを決めているのは, [第8章](fp8.html)で見た「台と演算の選び方」そのものです.

::: note
**組み合わせたくなったら (モナド変換子).** 「状態も IO も使いたい」のように, 2 つのパターンを同時に使いたくなることがあります. そのための仕組みが **モナド変換子 (monad transformer)** で, 例えば `StateT Int IO a` は「`Int` の状態を運びながら IO もできる計算」です. mtl / transformers パッケージが `State` / `Reader` / `Writer` それぞれの変換子版 (`StateT` / `ReaderT` / `WriterT`) を提供しています. 本講義では名前の紹介に留めます.
:::

::: note

### Exercise CH11-4

**ユークリッドの互除法にログを付ける**

import Data.Monoid (Sum (..))

gcdLog :: Int -> Int -> Writer [String] Int
gcdLog a 0 = do

gcdLog a b = do

# 構造を走査する

最後の部は, 新しいモナドではなく, ここまでのカタログ全体を横断する道具です.

## traverse

[第10章](fp10.html)の `forM` を思い出します (リストに特殊化した型で再掲します).

~~~ haskell
forM :: Monad m => [a] -> (a -> m b) -> m [b]
~~~

これは「リストという **構造をなぞり**, 各要素にパターン付き計算を流し, **構造の形を保ったまま** 結果を集める」道具でした. 標準ライブラリにはこの一般形があり, **`traverse`** と呼ばれます. 引数の順序が入れ替わり, 要求が `Monad` から `Applicative` に弱まっています (弱まっている理由は本部の最後で見ます).

~~~ haskell
traverse :: Applicative f => (a -> f b) -> [a] -> f [b]   -- リストに特殊化した型
~~~

`Maybe` を流すと「**一括検証**」になります. 全要素が成功したときだけ, 全体が成功します.

~~~ haskell
halve :: Int -> Maybe Int
halve n = if even n then Just (n `div` 2) else Nothing

main :: IO ()
main = do
  print (traverse halve [2, 4, 6])   -- Just [1,2,3]
  print (traverse halve [2, 3, 6])   -- Nothing (3 で失敗すると全体が失敗)
  print (sequenceA [Just 1, Just 2, Just 3])    -- Just [1,2,3]
  print (sequenceA [Just 1, Nothing, Just 3])   -- Nothing
~~~

相棒の `sequenceA :: [f a] -> f [a]` は「構造とパターンの **入れ替え**」です (リストの中に `Maybe` が並んでいたのを, `Maybe` の中にリストが入った形へ). 2 つは互いに定義し合えます: `sequenceA = traverse id`, `traverse f = sequenceA . fmap f`.

## 木を走査する

同じことをリスト以外でもやってみます. [第9章](fp9.html)の二分木です.

~~~ haskell
data Tree a = Leaf | Node (Tree a) a (Tree a) deriving Show

traverseTree :: Applicative f => (a -> f b) -> Tree a -> f (Tree b)
traverseTree _ Leaf         = pure Leaf
traverseTree g (Node l x r) =
  Node <$> traverseTree g l <*> g x <*> traverseTree g r
~~~

`Leaf` はそのまま `pure` で包み, `Node` は「左部分木を走査し, 値に `g` を流し, 右部分木を走査し, 3 つの結果を `Node` で組み立て直す」と読みます. 3 引数構築子 `Node` の持ち上げが, ちょうど[第10章](fp10.html)の `liftA3` の形 (`g <$> x <*> y <*> z` のイディオム) になっていることを確かめてください. **走査とは, 構築子を Applicative の世界で組み立て直すこと** です.

~~~ haskell
-- (Tree, traverseTree, halve は上の定義をそのまま使う)
main :: IO ()
main = do
  let t = Node (Node Leaf 2 Leaf) 4 (Node Leaf 6 Leaf)
  print (traverseTree halve t)
  -- Just (Node (Node Leaf 1 Leaf) 2 (Node Leaf 3 Leaf))
  let t' = Node (Node Leaf 2 Leaf) 3 (Node Leaf 6 Leaf)
  print (traverseTree halve t')   -- Nothing (3 で失敗すると木ごと失敗)
~~~

流す計算は `Maybe` に限りません. **`State` を流す** と, 「カウンタから疑似乱数まで」の連番ラベル付けが, そのまま木に一般化されます.

~~~ haskell
-- (newtype State, instance, fresh, evalState, Tree, traverseTree は上の定義をそのまま使う)
labelTree :: Tree String -> Tree (Int, String)
labelTree t = evalState (traverseTree step t) 0
  where
    step x = do
      n <- fresh
      pure (n, x)

main :: IO ()
main = do
  print (labelTree (Node (Node Leaf "a" Leaf) "b" (Node Leaf "c" Leaf)))
  -- Node (Node Leaf (0,"a") Leaf) (1,"b") (Node Leaf (2,"c") Leaf)
~~~

`step` はリスト版の `label` とまったく同じで, 変わったのは走査する構造だけです. 番号は「左部分木 → 節 → 右部分木」の順に振られています. この順路を決めたのは `traverseTree` の定義 (どの順で `<*>` を並べたか) です.

## Traversable クラス

「走査できる」という能力も, これまでどおり型クラスになっています.

~~~ haskell
-- 標準ライブラリの定義 (読むための抜粋)
class (Functor t, Foldable t) => Traversable t where
  traverse :: Applicative f => (a -> f b) -> t a -> f (t b)
~~~

前提が 2 つあります. `Functor` ([第9章](fp9.html)) と, [第8章](fp8.html)の `foldMap` の節で登場した `Foldable` (構造を畳み込めること) です. `Tree` を `Traversable` にするには, この 2 つを埋めてから, さきほど手作りした `traverseTree` をそのまま登録します.

~~~ haskell
-- (Tree, traverseTree, halve は上の定義をそのまま使う)
instance Functor Tree where
  fmap _ Leaf         = Leaf
  fmap g (Node l x r) = Node (fmap g l) (g x) (fmap g r)

instance Foldable Tree where
  foldr _ z Leaf         = z
  foldr g z (Node l x r) = foldr g (g x (foldr g z r)) l

instance Traversable Tree where
  traverse = traverseTree

main :: IO ()
main = do
  let t = Node (Node Leaf 2 Leaf) 4 (Node Leaf (6 :: Int) Leaf)
  print (traverse halve t)   -- Just (Node (Node Leaf 1 Leaf) 2 (Node Leaf 3 Leaf))
  print (sum t)              -- 12 (Foldable の恩恵: 集計関数がそのまま使える)
  print (length t)           -- 3
~~~

インスタンスにした瞬間, `traverse` だけでなく `sum` / `length` / `foldMap` などの集計関数 (`Foldable` 一族) も木に使えるようになります. 3 つのクラスの役割を並べておきます.

| クラス | 代表メソッド | 構造 | できること |
| --- | --- | --- | --- |
| `Functor` | `fmap` | 保つ | 各要素を変換する (パターンなし) |
| `Foldable` | `foldr` / `foldMap` | 潰す | モノイドで集計する ([第8章](fp8.html)) |
| `Traversable` | `traverse` | 保つ | 各要素にパターン付き計算を流す |

`foldMap` が「構造を **潰して** 1 つの値に集計する」のに対し, `traverse` は「構造を **保ったまま** 各要素に計算を流す」道具です. `fmap` と `foldMap` の中間ではなく, 両方の能力を前提にした上位の能力なので, クラスの階層も `Functor`, `Foldable` の 2 つを前提にしています.

## なぜ Applicative で十分か

`traverse` の型をもう一度見ます. 要求しているのは `Monad f` ではなく `Applicative f` です.

理由は `traverseTree` の定義に書いてあります. 「左 → 値 → 右」という走査の順路は **入力の木の形だけから決まり**, 途中の計算結果が「次にどこを走査するか」を変えることはありません. 各要素に流す計算は互いに **独立** で, 必要なのはそれらを組み合わせる力, つまり[第10章](fp10.html)の「パターン付き計算の複数化」(Applicative) だけです. 「結果に応じて次の計算を **作る**」という `>>=` の力は使い所がないのです.

対比として, [第10章](fp10.html)のリストモナドの依存 2 重ループ (`[x .. 4]` のように, 前の結果が次の候補集合を決める) を思い出してください. あちらは `>>=` が本質的で, `<*>` には書けませんでした. 走査はその力を使いません. [第10章](fp10.html)の使い分けの指針 (依存がなければ Applicative) が, `traverse` という 1 つの関数の型に刻まれているわけです. おかげで `traverse` には, `Maybe` (一括検証) も `State` (連番付け) も `IO` も, **Applicative でありさえすればどんなパターンでも** 流せます.

# まとめ

本章で増えた仲間を, 地図の形で回収します.

| 道具 | 包まれた値の形 | 仕事 | 部品の出どころ |
| --- | --- | --- | --- |
| `State s a` | `s -> (a, s)` | 状態の受け渡し | 配管を `>>=` にくくり出す |
| `IORef a` / `STRef s a` | 本物のセル | 破壊的な書き換え | `IO` / `runST` が境界を見張る |
| `Reader r a` | `r -> a` | 環境の参照 | 同じ環境を全員に配る |
| `Writer w a` | `(a, w)` | ログの追記 | [第8章](fp8.html)のモノイド |
| `traverse` | (道具) | 構造を保って計算を流す | [第10章](fp10.html)の Applicative |

どの仲間も, [第10章](fp10.html)の骨格 (自己関手 + $\eta$ + $\mu$ + モナド則) に **別の台を与えただけ** です. `Maybe` やリストと違って場合分けのパターンは持ちませんが, `>>=` が何を配管するか (状態を流す, 環境を配る, ログをつなぐ) が型ごとに違い, その違いこそが冒頭で触れた文献語彙の「効果」です. そして `Writer` のモノイド, `traverse` の Applicative のように, これまでの章で「組 + 法則」として整備した部品が, そのまま新しい構造の材料になりました.

[第12章](fp12.html)は総合演習です. 仕様を等式で書き, ここまでの道具 (代数的データ型, 型クラス, モナド, そして本章の `State`) で実装します.
