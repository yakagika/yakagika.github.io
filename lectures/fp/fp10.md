# モナド (Monad)

## Functor の復習

[第9章](fp9.html) で見たとおり, 関手 `f` は `fmap :: (a -> b) -> f a -> f b` を備え, 「入れ物 `f` の形を保ったまま, 中身に関数を作用させる」ものでした. これは「**1 引数関数 `a -> b` を関手の世界へ持ち上げる**」操作と読めます.

~~~ haskell
-- 復習: fmap は 1 引数関数を関手に持ち上げる
main :: IO ()
main = do
  print (fmap (+ 1) (Just 3))          -- Just 4
  print (fmap (* 2) [1, 2, 3 :: Int])  -- [2,4,6]
~~~

ところが `fmap` だけでは届かない計算が 2 種類あります.

1. **2 つの入れ物を組み合わせたい**. `Just 2` と `Just 3` を足して `Just 5` にしたいとします. しかし `fmap (+) (Just 2)` は `Just ((+) 2) :: Maybe (Int -> Int)` — 関数が入れ物の中に閉じ込められてしまい, これを `Just 3` に適用する術が `fmap` にはありません.
2. **前の結果の値に応じて, 次の計算そのものを選びたい**. 「`safeDiv 100 x` が成功したら, その値をさらに割る」ように, 次に何を計算するかが前の結果に依存します. `fmap` は中身に固定の関数を作用させるだけで, 「中身を見て次の計算を差し替える」ことはできません.

前者を解くのが **Applicative**, 後者を解くのが **Monad** です. Functor をこの 2 段階で強めていきます.

## Applicative — 複数の関手値を組み合わせる

上の 1. をもう一度見ます. `fmap (+) (Just 2)` は `Just ((+) 2) :: Maybe (Int -> Int)`, すなわち **入れ物に入った関数** になります. 欲しいのは, この `Maybe (Int -> Int)` を `Maybe Int` に適用して `Maybe Int` を得る操作 — 型でいえば `f (a -> b) -> f a -> f b` です. これを与えるのが **Applicative** (適用可能関手) 型クラスです.

~~~ haskell
class Functor f => Applicative f where
  pure  :: a -> f a
  (<*>) :: f (a -> b) -> f a -> f b
~~~

- `pure` は「素の値を, 余計な効果のない最小限の入れ物に入れる」ものです. `Maybe` なら `pure 3 = Just 3`, リストなら `pure 3 = [3]`.
- `(<*>)` (「apply」と読む) は「**入れ物に入った関数を, 入れ物に入った引数に適用する**」ものです. superclass 制約 `Functor f =>` があるので, Applicative は必ず Functor でもあります.

`Maybe` で試します. `<$>` は `fmap` の中置別名 ([第9章](fp9.html)) であることを思い出すと, 次のイディオムが読めます.

~~~ haskell
main :: IO ()
main = do
  print (Just (+ 1) <*> Just 3)            -- Just 4
  print (pure (+) <*> Just 2 <*> Just 3)   -- Just 5
  print ((+) <$> Just 2 <*> Just 3)        -- Just 5   (<$> は fmap)
  print ((+) <$> Just 2 <*> Nothing)       -- Nothing  (一方でも欠ければ全体が失敗)
~~~

`(+) <$> Just 2 <*> Just 3` は次のように読みます. まず `<$>` (= `fmap`) が `(+)` を `Maybe` に持ち上げ `Just ((+) 2)` を作ります. 次に `<*>` がその「箱に入った関数」を `Just 3` に適用して `Just 5` を得ます. これが「**n 引数関数を n 個の入れ物に一斉に適用する**」定石で, どれか一つでも `Nothing` なら全体が `Nothing` に短絡します.

リストの `<*>` は「関数のリストと引数のリストの **すべての組合せ**」を作ります.

~~~ haskell
main :: IO ()
main = do
  print ([(+ 1), (* 10)] <*> [1, 2 :: Int])   -- [2,3,10,20]
  print ((,) <$> [1, 2] <*> "ab")             -- [(1,'a'),(1,'b'),(2,'a'),(2,'b')]
~~~

`(,)` はペアを作る構築子で, `(,) <$> [1,2] <*> "ab"` は 2 つのリストの直積 (デカルト積) を与えます. リストというモナド的な入れ物では, `<*>` が「非決定的にすべての候補を試す」効果を表します.

Functor との関係も明快で, `fmap` は Applicative の特別な場合になっています.

$$\mathrm{fmap}\ f\ x \;=\; \mathrm{pure}\ f \mathbin{<\!\!*\!\!>} x$$

Applicative が満たすべき **Applicative 則** は次の 4 つです.

$$
\begin{aligned}
\text{恒等:} &\quad \mathrm{pure}\ \mathrm{id} \mathbin{<\!\!*\!\!>} v = v \\
\text{準同型:} &\quad \mathrm{pure}\ f \mathbin{<\!\!*\!\!>} \mathrm{pure}\ x = \mathrm{pure}\ (f\ x) \\
\text{交換:} &\quad u \mathbin{<\!\!*\!\!>} \mathrm{pure}\ y = \mathrm{pure}\ (\lambda g.\ g\ y) \mathbin{<\!\!*\!\!>} u \\
\text{合成:} &\quad \mathrm{pure}\ (\circ) \mathbin{<\!\!*\!\!>} u \mathbin{<\!\!*\!\!>} v \mathbin{<\!\!*\!\!>} w = u \mathbin{<\!\!*\!\!>} (v \mathbin{<\!\!*\!\!>} w)
\end{aligned}
$$

直感的には, **恒等則** は「`pure id` を適用しても何も変わらない」, **準同型則** は「素の値どうしの適用は, 先に計算して `pure` で包んでも同じ」であることを言います. 残る交換則・合成則とあわせて, 「`pure` は余計な効果を持ち込まず, `<*>` の適用は素直に振る舞う」ことを保証しています.

::: warn
[第8章](fp8.html)・[第9章](fp9.html) の代数則・関手則と同じく, **Applicative 則もコンパイラは検査しません**. 法則を破るインスタンスを書いてもコンパイルは通ります. 守るのはプログラマの責任で, [第8章](fp8.html) のコラムで触れた QuickCheck で性質として確認できます.
:::

::: note

### Exercise CH10-1

**`<*>` で 2 つの `Maybe` を掛け合わせる**

2 つの `Maybe Int` を受け取り, 両方が `Just` なら中身の積を `Just` で返し, 一方でも `Nothing` なら `Nothing` を返す関数 `mulMaybe :: Maybe Int -> Maybe Int -> Maybe Int` を, `if` やパターンマッチを使わず `<$>` と `<*>` だけで実装してください.

~~~ haskell
-- 実行例
main :: IO ()
main = do
  print (mulMaybe (Just 6) (Just 7))       -- Just 42
  print (mulMaybe (Just 6) Nothing)        -- Nothing
  print (mulMaybe Nothing  (Just 7))       -- Nothing
~~~

<details class="protected" data-pass="yakagika">
    <summary> 回答例 </summary>

~~~ haskell
mulMaybe :: Maybe Int -> Maybe Int -> Maybe Int
mulMaybe x y = (*) <$> x <*> y

main :: IO ()
main = do
  print (mulMaybe (Just 6) (Just 7))   -- Just 42
  print (mulMaybe (Just 6) Nothing)    -- Nothing
  print (mulMaybe Nothing  (Just 7))   -- Nothing
~~~

`(*) <$> x` で `Maybe (Int -> Int)` を作り, `<*> y` でそれを `y` に適用します. `x` か `y` が `Nothing` なら `<*>` が自動的に `Nothing` へ短絡するので, 場合分けを一切書かずに済みます. これが Applicative の「複数の入れ物を組み合わせる」力です.

</details>

## Monad — `>>=` と `return`

Applicative は「**互いに独立な** 入れ物どうし」を組み合わせます. しかし Functor の限界としてもう一つ挙げた「前の結果の **値** に応じて次の計算を選ぶ」— 計算どうしが独立でなく依存する場合 — はまだ扱えません. たとえば `safeDiv 100 x` の結果が `Just 20` か `Nothing` かによって, その先を続けるかどうか, 続けるなら何で割るかが変わります. これを可能にするのが **Monad** です.

~~~ haskell
class Applicative m => Monad m where
  return :: a -> m a
  (>>=)  :: m a -> (a -> m b) -> m b
~~~

- `return` は `pure` と同じです (`return = pure`. 歴史的経緯で別名が残っています).
- `(>>=)` (「bind」と読む) が主役です. `m a` から中身 `a` を取り出し, それを **「次の計算 `a -> m b`」に手渡します**. 次の計算が `m b` を返すので, 効果 (失敗・入出力など) を保ったまま連鎖できます.

`Maybe` で見ます. 「100 を `x` で割り, その結果をさらに 2 で割る」計算を `>>=` で繋ぎます.

~~~ haskell
safeDiv :: Int -> Int -> Maybe Int
safeDiv _ 0 = Nothing
safeDiv x y = Just (x `div` y)

calc :: Int -> Maybe Int
calc x = safeDiv 100 x >>= \r -> safeDiv r 2

main :: IO ()
main = do
  print (calc 5)   -- Just 10   (100/5 = 20, 20/2 = 10)
  print (calc 0)   -- Nothing   (最初の割り算で失敗 → 連鎖が止まる)
~~~

`safeDiv 100 x >>= \r -> safeDiv r 2` を追います. `safeDiv 100 x` が `Just 20` なら, `>>=` が中身 `20` を `\r -> safeDiv r 2` に渡し, `safeDiv 20 2 = Just 10` を得ます. もし `Nothing` なら, `>>=` は **後ろの関数を呼ばずに `Nothing` を素通し** します — これが「失敗の連鎖」で, `if` の入れ子や `case` を書かずに済みます.

**圏の言葉での見方.** 返り値が入れ物に入った関数 `a -> m b` を **Kleisli 射 (Kleisli arrow)** といいます. 通常の関数合成 `(.)` は `a -> b` どうしを繋ぎますが, Kleisli 射は返り値が `m b` なので `(.)` では繋げません. これを繋ぐのが **Kleisli 合成** `(>=>)` (`Control.Monad` にあります) です.

~~~ haskell
(>=>) :: Monad m => (a -> m b) -> (b -> m c) -> a -> m c
f >=> g = \x -> f x >>= g
~~~

`safeDiv 100 :: Int -> Maybe Int` も `\r -> safeDiv r 2` も Kleisli 射なので, `>=>` で合成できて `calc` と同じものになります.

~~~ haskell
calc' :: Int -> Maybe Int
calc' = safeDiv 100 >=> \r -> safeDiv r 2   -- calc とまったく同じ
~~~

モナドとは「Kleisli 射を合成する仕組み `>=>` と, 何もしない Kleisli 射 `return` を備えた構造」と見ることができます. [第9章](fp9.html) で型を **対象**, 関数を **射** とみて圏を作りましたが, その上にもう一段, Kleisli 射を射とする圏 (Kleisli 圏) を載せたのがモナドです. なお, 前の結果の値を使わずただ順に繋ぎたいときのために `(>>)` があり, `m >> k = m >>= \_ -> k` と定義されます.

## do 記法 — `>>=` の脱糖

`>>=` とラムダを重ねると, 連鎖が長くなるほど読みにくいです. Haskell は同じことを **`do` 記法** で書けます. `do` は `>>=` / `>>` への **糖衣構文 (syntactic sugar)** にすぎず, コンパイラが機械的に脱糖 (desugar) します.

~~~ haskell
-- do 記法で書いた calc
calc :: Int -> Maybe Int
calc x = do
  r <- safeDiv 100 x     -- x <- e : e の結果を x に束縛
  safeDiv r 2            -- ブロック最後の式が全体の値

-- 上は次の >>= 版とまったく同じ (機械的にこう脱糖される)
calc2 :: Int -> Maybe Int
calc2 x =
  safeDiv 100 x >>= \r ->
  safeDiv r 2
~~~

脱糖規則は 3 つだけです.

- `do { x <- e; rest }`  →  `e >>= \x -> do { rest }`  (結果を `x` に束縛して続ける)
- `do { e; rest }`  →  `e >> do { rest }`  (結果を捨てて続ける)
- `do { e }`  →  `e`  (最後の式)

肝心なのは, **`do` はモナドでありさえすれば何にでも使える** という点です. [第4章](fp4.html) 以降 `main = do ...` と書いてきたのは `IO` モナドの `do` であり, ここで見た `Maybe` の `do` とまったく同じ仕組みでした. `do` は `IO` 専用の構文ではありません (この事実は後半「入出力」で正式に回収します).

::: note

### Exercise CH10-2

**`do` 記法で連想リストを 2 回引く**

キーと値の連想リスト `[(String, Int)]` を受け取り, キー `"x"` と `"y"` の値を `lookup` (返り値は `Maybe`) で引いて, 両方あれば和を `Just` で, 片方でも無ければ `Nothing` を返す関数 `addLookup :: [(String, Int)] -> Maybe Int` を, `do` 記法で実装してください.

~~~ haskell
-- 実行例
main :: IO ()
main = do
  print (addLookup [("x", 3), ("y", 4)])   -- Just 7
  print (addLookup [("x", 3)])             -- Nothing
  print (addLookup [("y", 4)])             -- Nothing
~~~

<details class="protected" data-pass="yakagika">
    <summary> 回答例 </summary>

~~~ haskell
addLookup :: [(String, Int)] -> Maybe Int
addLookup env = do
  x <- lookup "x" env
  y <- lookup "y" env
  return (x + y)

main :: IO ()
main = do
  print (addLookup [("x", 3), ("y", 4)])   -- Just 7
  print (addLookup [("x", 3)])             -- Nothing
  print (addLookup [("y", 4)])             -- Nothing
~~~

`x <- lookup "x" env` は「`lookup` が `Just` を返せば中身を `x` に束縛して続け, `Nothing` なら全体を `Nothing` にして止める」ものです. `y` も同様で, どちらか一方でも見つからなければ `return (x + y)` に到達しません. 脱糖すれば `lookup "x" env >>= \x -> lookup "y" env >>= \y -> return (x + y)` で, `Maybe` モナドの `>>=` がすべての失敗を短絡させています.

</details>

## Maybe / Either モナド — 失敗の連鎖

ここまでの `Maybe` モナドは「失敗が一つでもあれば全体が失敗」という短絡を `>>=` に埋め込んだものでした. 便利ですが, `Maybe` は「**失敗した**」ことしか伝えられません — `Nothing` に理由は載りません.

**なぜ失敗したか** を運ぶには `Either e a` を使います. 慣習として `Left` に **エラーを表す専用の列挙型** を, `Right` に成功値を置きます (エラーを `String` で表すこともできますが, 型で場合分けできる専用の列挙型のほうが安全で, どんな失敗があり得るかがシグネチャから読めます).

~~~ haskell
-- なぜ失敗したかを型で表す (String でなく専用の列挙型)
data CalcError
  = DivByZero   -- 0 で割ろうとした
  | Negative    -- 負の入力は許さない
  deriving (Show, Eq)

safeDivE :: Int -> Int -> Either CalcError Int
safeDivE _ 0 = Left DivByZero
safeDivE x y = Right (x `div` y)

checkPos :: Int -> Either CalcError Int
checkPos n
  | n < 0     = Left Negative
  | otherwise = Right n

-- 2 つの入力を検査してから割る. どこで失敗しても, 最初のエラーが返る.
calcE :: Int -> Int -> Either CalcError Int
calcE x y = do
  x' <- checkPos x
  y' <- checkPos y
  safeDivE x' y'

main :: IO ()
main = do
  print (calcE 100 5)    -- Right 20
  print (calcE 100 0)    -- Left DivByZero
  print (calcE (-1) 5)   -- Left Negative
~~~

`Either e` の `>>=` は, `Left e` が出た時点で後続を素通しして その `Left e` を返し, `Right` の間はふつうに値を繋ぎます. `Maybe` の「失敗の連鎖」に **失敗理由を添えた** ものが `Either` モナドです. [第12章](fp12.html) の式評価器も, この `Either` モナドで 0 除算エラーを伝播させています.

::: note

### Exercise CH10-3

**専用エラー型での検証チェーン (口座からの連続引き出し)**

残高 `balance` から `amount` を引く関数 `withdraw :: Int -> Int -> Either BankError Int` を考えます. `amount` が負なら `Left Negative`, 残高不足なら `Left NotEnough`, それ以外は引いた後の残高を `Right` で返します. これを使って, 初期残高から 2 回続けて引き出す `twice :: Int -> Int -> Int -> Either BankError Int` を `do` 記法で実装してください (1 回目の引き出し後の残高から 2 回目を引きます).

~~~ haskell
data BankError = NotEnough | Negative deriving (Show, Eq)

-- 実行例
main :: IO ()
main = do
  print (twice 100 30 50)    -- Right 20
  print (twice 100 30 80)    -- Left NotEnough
  print (twice 100 (-1) 0)   -- Left Negative
~~~

<details class="protected" data-pass="yakagika">
    <summary> 回答例 </summary>

~~~ haskell
data BankError = NotEnough | Negative deriving (Show, Eq)

withdraw :: Int -> Int -> Either BankError Int
withdraw balance amount
  | amount < 0       = Left Negative
  | amount > balance = Left NotEnough
  | otherwise        = Right (balance - amount)

twice :: Int -> Int -> Int -> Either BankError Int
twice balance a b = do
  b1 <- withdraw balance a
  withdraw b1 b

main :: IO ()
main = do
  print (twice 100 30 50)    -- Right 20   (100-30=70, 70-50=20)
  print (twice 100 30 80)    -- Left NotEnough  (2 回目で 70<80)
  print (twice 100 (-1) 0)   -- Left Negative   (1 回目で負の額)
~~~

`b1 <- withdraw balance a` が 1 回目の引き出し後の残高を `b1` に束縛し, `withdraw b1 b` がそこから 2 回目を引きます. どちらかで `Left` が出れば, 続く引き出しは実行されずにその理由がそのまま返ります. `Maybe` では「失敗した」しか言えませんが, `BankError` により「残高不足なのか負の額なのか」を型で区別できます.

</details>

## モナド則

[第8章](fp8.html) の代数則・[第9章](fp9.html) の関手則と同様に, モナドにも守るべき **モナド則** があります. `>>=` と `return` で書くと次の 3 つです.

$$
\begin{aligned}
\text{左単位元:} &\quad \mathrm{return}\ a \mathbin{>\!\!>\!\!=} f = f\ a \\
\text{右単位元:} &\quad m \mathbin{>\!\!>\!\!=} \mathrm{return} = m \\
\text{結合律:} &\quad (m \mathbin{>\!\!>\!\!=} f) \mathbin{>\!\!>\!\!=} g = m \mathbin{>\!\!>\!\!=} (\lambda x.\ f\ x \mathbin{>\!\!>\!\!=} g)
\end{aligned}
$$

これらは Kleisli 合成 `>=>` で書き直すと, 見慣れた形になります.

$$
\mathrm{return} >\!\!=\!\!> f = f, \qquad f >\!\!=\!\!> \mathrm{return} = f, \qquad (f >\!\!=\!\!> g) >\!\!=\!\!> h = f >\!\!=\!\!> (g >\!\!=\!\!> h)
$$

左の 2 つは「`return` が合成 `>=>` の **単位元** (恒等射) である」, 右は「`>=>` が **結合的** である」ことを言っています. これはまさに [第9章](fp9.html) で見た **圏の公理** (恒等射をもち, 合成が結合的) を, Kleisli 射 `a -> m b` が満たすということです. モナド則とは「Kleisli 射が圏 (Kleisli 圏) を成す」条件に他なりません. [第9章](fp9.html) で圏を「対象 1 つのモノイド ([第8章](fp8.html)) の一般化」と述べましたが, モナド則も同じ圏の言葉で理解できます — `Maybe` の失敗連鎖も `Either` のエラー伝播も, この共通の骨格の上に乗っています.

::: warn
モナド則もコンパイラは検査しません. 法則を破る `>>=` を書いてもコンパイルは通ります. 標準ライブラリの `Maybe` / `Either` / `[]` / `IO` はすべて則を満たしますが, 自作のモナドでは自分で保証する必要があります (QuickCheck で `return a >>= f == f a` などを性質として確かめられます).
:::

::: note
**モナドの構文糖と圏論の対応 (まとめ)**

| 概念 | 記号 | 圏論での役割 |
| --- | --- | --- |
| 値を入れ物に入れる | `return` / `pure` | 恒等な Kleisli 射 (単位元) |
| 効果を保って連鎖 | `>>=` (bind) | Kleisli 射への値の受け渡し |
| Kleisli 射の合成 | `>=>` | Kleisli 圏の射の合成 |
| 連鎖の構文糖 | `do` | `>>=` / `>>` の見た目を整えるだけ |

`Maybe`・`Either`・リストで固めたこの骨格が, 後半で扱う `IO` にもそのまま当てはまります.
:::

# 入出力 (IO)

::: note
**本節 (入出力) は後半として次のセッションで執筆します.** ここまで `Maybe` / `Either` で固めた `>>=` ・ `do` ・モナド則の仕組みが, そのまま `IO` — 副作用を値 `IO a` として扱う典型的なモナド — に当てはまることを見ていく予定です.

予定している構成: `IO` モナド (アクションと `IO a`) / 参照透過性 (なぜ型で副作用を分けるか) / 標準入出力 (`getLine` / `putStrLn` / `interact`) / `main` の構造と `do`.
:::
