## 目的

1. 講義資料の主張 (定義, 手法の推奨, 経緯の記述) が, 本文を確かめた文献に裏付けられている状態にする.
2. 方法論で立場が分かれる箇所では, 立場が分かれる経緯と資料がとる立場を本文に書き, 扱う内容をその立場から決める.

## 設計

### A. 仕組み (全章に共通)

1. **文献の正本は論文 DB**. 講義で引用する文献は論文 DB に取り込み, project tag (例 `blog-lectures`) を付ける. 本文の照合は skill `lit-verify` の手順で行い, 検証の水準を DB の `verification` に記録する.
2. **repo 内の bib**. `scripts/make_lecture_bib.sh` が論文 DB の `projects: blog-lectures` の文献すべてから `bib/lectures.bib` を生成する. サイトの build を repo の外に依存させないため, 生成物を commit する. 水準による絞り込みは bib の生成ではせず, 検査 (5) が引用ごとに判定する. 論文 DB の `make_bib.py` は水準の順序に identity を持つが, `--min-verification` の選択肢に identity が無いため, identity 以上での絞り込みができない (2026-11-20 に確認. 本人へ報告した).
3. **本文の引用の書き方** (Phase 0 で実装済み). 章の front matter に `bibliography: lectures` を書き, 本文で `[@key]` (括弧の引用), `[@key, p. 12]` (頁つき), `@key` (文中の引用) を使う. 文献表は本文の `::: {#refs}` の位置に入る. CSL は APA 第 7 版 (`bib/apa.csl`, CSL の公式 repo から取得). 表示は「(Shmueli, 2010)」「佐和 (1979)」「Heinze et al. (2018)」. 文献表の和文の書名と誌名は, 生成器が斜体を外して 『』 で囲む. 既知の制約: 和文の文献でも APA の英語の規則で並ぶ (「佐和隆光. (1979). 『回帰分析』. 朝倉書店.」, 叢書名は出ない, 著者 3 名以上の和文の文献は文中で「et al.」になる).
4. **文献表と読書案内**. citeproc が出す文献表は 1 章に 1 つなので, 章末を次の 2 つにする (2026-11-20 Phase 0 で変更. 当初は文献表を 2 つに分ける案だった).
   - 「さらに学ぶための文献」の節: 学生向けの推薦を, 引用 (`[@key]`) と 1〜2 文の紹介で書く. 邦訳があれば併記する.
   - 「参考文献」の節: `::: {#refs}` を置き, 本文と読書案内で引用したすべての文献を citeproc が並べる.
5. **検査**. 全章の引用キーを bib と論文 DB の検証の水準に突き合わせる script を置き, publish の前に走らせる (lit-verify の手順 0).
   - 実装: `scripts/check_citations.py`. `publish.sh` の先頭で走る.
   - 失敗 (publish を止める): bib に無いキー, 論文 DB に note が無いキー, 書誌の実在を確かめていないキー (`none`).
   - 警告 (publish は止めない): 本文を確かめていないキー (`identity` か `abstract`) を「未照合の引用」として `writing/citations/unverified.md` に書き出す. 文献表の位置 (`::: {#refs}`) が無い章, bibliography の指定が無い章の `[@key]` も警告する.
   - 頁や節の記録の有無の検査は, 対応表 (7) を章に置いた後で加える.
6. **未照合の引用の扱い** (2026-11-20 本人裁定). 講義資料は論文ではないので, 本文を確かめる前でも引用して公開してよい. 未照合の引用は後の作業として残し, 本文を確かめてから記述を直す. 一覧は検査の script が書き出し, この計画の「未照合の引用」の節と Todoist の 1 件の task で追う. lit-verify の「本文を確かめるまで引用しない」はこの repo の講義資料には適用しない (論文の原稿には従来どおり適用する). 書誌の実在だけは公開前に確かめる (記憶から挙げた書誌が誤っている場合に, 存在しない文献を学生に示さないため).
7. **主張と文献の対応表**. 章ごとに「本文の主張 → 文献 → 頁または節」を記録する (例 `writing/citations/dsp5.tsv`). 改稿のときに, どの主張がどの文献に依っていたかを追えるようにする. 公開する資料には出さない.

### B. 章ごとの進め方

1. 章の主張を棚卸しし, 3 種類に分ける: (a) 標準的な定義と計算 (教科書 1 冊で足りる), (b) 手法の推奨や注意 (根拠となる論文か専門書が要る), (c) 経緯や分野の状況の記述 (総説か原典が要る).
2. (b) と (c) を優先して文献を探し, 書誌の実在を確かめて引用する. 本文を確かめた文献はその場で記述を直し, 確かめていない文献は未照合の引用として残す. 入手できないものは調達の手順 (lit-verify の手順 4) に回す.
3. 未照合の引用を順に照合し, 文献と食い違う記述を直す.
4. 検査を通して publish する.

着手の順: 第5章 (モデル選択) → 第13章 (一般化線形モデル) → 第16章 (因果推論) → 第14章 (質問紙調査) → 残りの章. 第5章を先に済ませ, 仕組みの使い勝手をそこで確かめてから他の章へ広げる.

### C. 第5章のモデル選択の節 (最初の適用)

節の構成案 (現行の「モデル選択」「AIC について」の節を置き換える):

1. **回帰分析の目的は 3 つある**: 説明 (特定の係数の因果効果を推定する), 予測 (新しいデータの値を当てる), 探索 (次に確かめる仮説を見つける). 目的によって, 変数の選び方と結果の報告の仕方が変わる [Shmueli 2010].
2. **同じデータで選んで同じデータで検定すると何が起きるか**: 効果の無いデータで, 有意でない変数を落とす手順を繰り返すと, ほぼ毎回「全変数が有意なモデル」が残ることをシミュレーションで示す [Freedman 1983; Harrell 2015 第4章].
3. **経緯**: 同じ問題が, 計量経済学 (specification search, general-to-specific), 統計学 (選択後の推論), 疫学 (調整変数の選択と Table 2 fallacy), 機械学習 (過学習と hold-out), 心理学 (事前登録) で別々に扱われてきたことを, 表 1 枚と短い説明で示す.
4. **この講義の立場** (2026-11-20 本人裁定): 目的を先に決める. 説明が目的なら, 変数を事前に決めて注目する係数を CI で報告する. 予測が目的なら, 訓練データとテストデータ (または交差検証) で選ぶ. 探索が目的なら, 選んでよいが結論にはせず, **別のデータで確かめるところまで行うことを推奨する**. 現行の手順 (有意でない変数を除き, 全変数が有意なモデルから結論する) は「探索の手順としては使えるが, そのままでは結論にできない」と位置づけ直し, シミュレーションで理由を示す. 確かめ方は, 新しいデータ, 事前に分けた確認用のデータ (パネルでは個体か時期で分ける), 選択後の推論の補正の 3 つを示す.
5. **この講義で扱うこと, 扱わないこと**: 立場から決める. 扱わないものは発展か「さらに学ぶための文献」へ送る.
6. **例題の書き直し**: 現行の GPA のデータを使い, 目的ごとに手順を分けて示す. 予測なら訓練データとテストデータで比べる (第5章の既存の「回帰の評価」の節と「テスト MSE で比べる」の発展の節につなぐ). 説明なら, 変数を事前に決めて注目する係数を CI で報告する. 探索なら, データを探索用と確認用に分け, 探索用で選んだモデルを確認用で推定し直す.

必修と発展の区分は, 親計画で本人が授業設計から組み直す方針になっている (dsp-course-material の未解決事項). この節もその方針に従い, 区分は本人が決める.

- **食い違いの補足 (2026-11-20, 本人の質問「多重共線性が見かけのものなのか, 除外しなくてよい基準に当たるのか」への回答の材料)**:

  - 外したときの変化は欠落変数の公式で説明できる: 0.273 = 0.220 + (-0.089) × (-0.600). -0.600 は奨学生と勉強時間でアルバイト時間を回帰したときの勉強時間の係数.
  - これが「バイアス」かは, 勉強時間とアルバイト時間の因果の向きで決まる. アルバイトが勉強時間を圧迫する (アルバイト → 勉強) なら, アルバイト時間は交絡因子で, 外すと勉強時間の効果が偏る. 勉強するほどアルバイトを減らす (勉強 → アルバイト) なら, アルバイト時間は中間変数で, 外したモデルは勉強時間の総合効果を推定する. データだけではどちらか決まらない.
  - データを作ったコード (`slds_code/ch11/multi.py`) は `part_time_work = 20 - 0.6 * study_hours + ノイズ` (勉強 → アルバイトの式) だが, コメントは「勉強時間をある程度圧迫するという仮定」(アルバイト → 勉強の意図) で, 式と意図が逆. GPA の真の係数は勉強時間 0.25, アルバイト時間 -0.1 で, 式どおりなら総合効果は 0.25 + 0.06 = 0.31. 推定値 0.220 が 0.25 を下回るのは, GPA を 0〜4 で打ち切っている (100 人中 11 人) ため.
