## 概要

講義資料の内容を, 教科書の形で通読できる「分野」と, その中の「ブロック」に分ける. データサイエンス実践とデータ活用の統計学は, ブロックの並びから講義のナビと回のページを生成する. 特別講義とゼミは, 講義のページからブロックへリンクするだけにする.

## 動機

本人が挙げた問題 (2026-11-20).

- 第5章 (回帰分析) が約 2100 行になり, これ以上の内容を入れる場所がない.
- 因果推論などを扱うと, 章の順序の再編が要る (例: 交絡と因果の概念を重回帰より前に置く計画).
- 統計学, ゼミ, 特別講義で同じ技術を扱う.
- 同じ技術を扱っても, 講義ごとに演習や課題が共通しない場合がある.
- 必修と発展の区分が講義によって違う (いまは章の本文に「(発展)」と書いているので, 講義ごとに変えられない).

### source の配置, 出力の URL, 一意性の検査

- 新しい source は `lectures/` の外に置く (例: `fields/<分野>/<ブロック>.md`). 今の `lectures/**.md` の規則が新しい file を拾い, 分割前の全文を `lectures/<basename>.html` に出してしまうのを避けるため (`src/Main.hs:351`).
- 所属する分野は dir から決め, front matter には書かない.
- ページの URL は, 分割した見出しの固定の ID から作る (例: `/fields/regression/reg-simple/fitting.html`). 通し番号 (`reg-simple-2.html`) にしない. 前に節を足すと, 同じ URL が別の内容を指すようになるため.
- build は, 旧ページ, 分割したページ, 分野の目次, 講義の目次, 回のページを含めた**最終の出力 path** が重ならないかを検査し, 重なったら止める (basename の検査だけでは足りない).
- Hakyll では, 規則を登録するときに見出しから出力するページの `Identifier` を列挙し, 各ページは親の原稿と講義の並びの file を依存として読む. 見出しの追加と削除, 講義の並びの file だけの編集が, `watch` のプレビューにも反映されることを受入の条件にする.

### ブロックの front matter と前提

- `title`, 前提のブロック (`requires`), 種類 (理論かコードか), `open`, `bibliography`.
- `requires` は「これを読まないとこのブロックを履修できない」ものに限る. 導出への参照や先の話題への参照は普通のリンクにする.
- 検査: 未定義の名前と循環を止める. 講義の並びでは, 必修のブロックの前提が, それより前の**必修**のブロックで満たされるかを調べる (前の回の発展のブロックは履修済みに数えない). 分野の教科書では分野内の前後を調べ, 分野の外の前提は教科書の入口に書く.
- この検査が保証するのは, 宣言した前提までである. 本文が未説明の手法を使っていないかは, 今までどおり教材のレビューで確かめる.

### ナビの生成

- 今の章ナビ (`previousChapter` / `nextChapter` を 1 つずつ持つ鎖. `src/Main.hs:355`, `:723`, `:750`) は新しい系では使わない. 1 つの鎖には, 講義ごとに違う「次」を書けないため.
- 分野の順は分野の dir の目次の file から, 講義の順は講義の並びの file から直接生成する. 講義の中の位置は (講義, 回, 回の中の位置) で決める. 同じブロックを後の回でもう一度読む場合も, 戻る先が決まる.
- ページには「ブロックの中の次のページ」と「この講義で次に読むブロック」を分けて出す. 特別講義とゼミから開いた学生は, 分野の順で読む.

### 共有するブロックの見え方 (2026-11-20 本人が案 B に決定)

- ブロックのページの URL は 1 つにし, ページの上部に所属する講義の一覧と, 講義ごとの前後のリンクを並べる.
- 却下した案 A (講義ごとに別のページを生成する) は, 本文の複製, 検索結果の重複, 講義ごとのリンクの書き換えが要るため採らない. 両案を実装して比べる手順も削った (codex の削る候補).

### 公開の制御 (`open`)

- 今は原稿の `open` を読み, 閉じていれば本文を空にして snapshot を保存し, 準備中のページと `noindex` を出す (`src/Main.hs:372`). `isOpen` はキーが無いと公開扱いにし (`:469`), `filterOpen` は item 自身の ID を見る.
- 新しい系では, 分割したページの公開の状態を**親の原稿の `open`** から決め, 本文, 回のページのリンク, 分野の目次, tag の RSS, sitemap で同じ判定を使う. 生成したページの ID に親のメタデータを引き継がずに今の判定を当てると, 閉じたブロックを公開扱いにする経路ができる.
- 受入の例: 公開中の回が閉じたブロックを参照しても, 回のページには「準備中」と出て, 個別の URL と feed のどちらにも本文と回答が出ない.
- sitemap は公開する正規の URL を明示して作る. トップの `rss.xml` は今どおり投稿だけにする.

### 文献表

- 今は原稿の全体を 1 度だけ citeproc に通し (`src/Main.hs:144`, `:158`), `#refs` の和文の書名と人名を整形している. 生成した HTML を切ると, 引用と文献表が別のページに分かれる.
- 新しい系では, ブロック全体を Pandoc で読んで ID を確定し, 分割した後の各 Pandoc 文書に親の `bibliography` と同じ CSL を渡して, 引用のあるページにだけ文献表を出す. 元の原稿の `# 参考文献` が中身の無いページにならないようにする.
- `scripts/check_citations.py` は `lectures/**/*.md` を読むので, 新しい source の置き場も読むように直す.

### リンクと公開前の検査

- 分割で最も壊れやすいのは見出しへのリンクである. 今の `scripts/check_local_refs.py` は, `#id` だけのリンクを検査せず, `page.html#id` は `page.html` があるかしか見ない (`:40`). 例えば凍結した `slds11.md` から `dsp5.html#model-selection` へのリンクがあり, 節を移して旧 file だけ残しても `publish.sh` は通る.
- そこで, 検査を生成した HTML の fragment (同じページと別のページの両方) まで広げる. これは新しい系に限らず, 今のサイトの検査の穴なので, Phase 1 の最初に直す.
- リンクの書き換えは, ブロック全体を Pandoc で読んで「元の ID → 分割先の URL と ID」の対応を作ってから行う. 日本語の ID, 演習から本文への戻り, 凍結したページからのリンクを試す.
- 旧ページの本文とアンカーは年度中は残す. 切り替えた後も, 旧 URL からその節に着ける経路 (転送のページか, 節ごとのリンクの一覧) を残す.

### 回答, 数式, 演習の番号

- 回答 (`<details class="protected">`) と KaTeX は分割と両立する. 条件は, 分割の境界を本文の最上位の指定した深さの見出しに限り, コードフェンス, `::: note`, 回答の開始と終了の間を一体で扱うこと.
- 演習の番号はブロックの名前で付ける (例: `Exercise REG-SIMPLE-1`). 提出の file 名は講義ごとに違ってよいので, 講義の並びの file で決める (今は `dsp5-1.py` を本文に直接書いている).

### コード例の実行

- 第5章では, 前の節で `result = sm.OLS(y, X).fit()` を実行し, 次の節が `result.predict(X)` から始まる. 次の節を講義の入口にすると, 新しい Python の session には `result` も `X` も無い.
- 講義の並びで入口になりうるブロックは, 配布するデータと, ブロックの冒頭に明示した準備の手順だけで実行できるようにする. 回帰分析の試験移行で, 入口のコードを実際に走らせて確かめる.
- 例題データの置き場は, 試験移行では今の `slds_data/` を使う (配布リンクと Hakyll の静的コピー `src/Main.hs:216` を変えないため). 分野ごとの dir へ移すかは, 試験移行の後で決める.

### 付随する記録と規則

- モデルカリキュラムの対応表 (`plan/landed/2026-11-20-dsp-curriculum-matrix.md`) は, 34 項目の節へのリンクと, 評価に使う演習を記録している. 回帰分析の試験移行で 1 項目について「旧節 → 新しいページの節 → dsp が課す演習」を通し, 全件の付け替えは dsp の切り替えの条件にする.
- 講義一覧 (`pages/lectures.markdown`) の dsp の入口は手で書いているので, 切り替えの日の作業に含める.
- `CLAUDE.md` の dsp と slds の規則 (演習の見出し, 章ナビ, 演習の配置) を, ブロックと講義の並びの規則に書き換える. 各 Phase で, その Phase で移した範囲に合わせて行う.

### Phase 1 で決めた入力の形式 (2026-11-20, ac7932d)

見本は `fixtures/` にある (`BLOG_FIXTURES=1 stack exec main rebuild` で `_fixture_site/` に出る. 試験は `scripts/test_block_site.py`).

- 分野: `fields/<field>/field.yaml` に `title`, `description`, `blocks` (教科書の順のブロック名).
- ブロック: `fields/<field>/<block>.md`. front matter は `title`, `kind` (`theory` か `code`), `requires` (省略可), `open` (省略時は false), `bibliography` (省略可). 最上位の `#` 見出しでページに分け, その見出しには `{#id}` (`[a-z0-9-]+`) を必ず付ける. 最初の `#` より前は導入のページになる. `::: {#refs}` は書かない (引用のあるページに文献表が付く). 演習は `# 演習 {#exercises}` のページに `## Exercise XXX-k {#exercise-xxx-k}` で並べる.
- 講義: `courses/<course>.yaml` に `title`, `description`, `open` (真偽値. 省略時は false. 2026-11-22 に 694516b で追加. 下の「閉じた講義」), `sessions` (各回に `title`, `intro` (省略可), `blocks` (`block`, `level` (`required` か `advanced`), `exercises` (`id`, `file`))).
- リンク: 別のブロックへは `[x](block:name)` と `[x](block:name#id)`. 同じブロックの中は `[x](#id)` (別のページにある ID なら build がそのページの URL に直す).
- 出力: `fields/<f>/<b>/index.html`, `fields/<f>/<b>/<id>.html`, `fields/<f>/index.html`, `courses/<c>/index.html`, `courses/<c>/<n>.html`.
- 閉じたブロック: ページは準備中の表示と `noindex` になり, 本文と回答は出ない. ページの題名 (見出しの文字列) と前後のページの題名は, 既存の準備中のページと同じく出る. 見出しも隠すかは, 実際の内容を移してから必要なら決める.
- 閉じた講義: 目次と回のページは題名, 説明, 準備中の表示だけで `noindex` になり, sitemap に載らない. ブロックのページの所属する講義の一覧にも出ない. `intro` のリンクとブロック, 演習の検査は閉じていても走る.
- 受入で確かめたこと: 本番の `docs/` は変わらない (差は file の変更時刻から決まる更新日とトップページの並び, css の版の番号だけ). `watch` で見出しの追加と削除, 講義の yaml だけの編集が出力に反映される.

#### ブロックを書くときの共通の取り決め (段 2 以降の brief はこれを参照する)

1. 立場: 本体は関係の定量化と母集団への推測. 係数は「他の説明変数が同じ個体どうしで, X が 1 違うときの Y の平均の差」として読む. 「影響」「効果」「X を増やすと Y が増える」は介入の意味を持つので, `reg-causal` 以外では係数の読みに使わない (「X が 1 高い個体ほど, Y の平均が〜高い」と書く). 目的の名前に「説明」を使わない (関係の定量化, 予測, 因果推論, 探索と呼ぶ). 説明変数, 目的変数は標準の用語なので使う.
2. 旧ページの立場の規則 (有意でない係数が 1 つでもあれば式を使わない, 自由度調整済み決定係数 0.5 の目安) はブロックに持ち込まない. ブロックでは, 入れる変数は問いで先に決め, 有意でない係数も区間とともに報告する. 決定係数は手元のデータへの当てはまりの要約で, 予測の良さは未使用のデータで測る (`reg-prediction`).
3. 記号: 母数は $\beta_0, \beta_1, \dots, \beta_k$ (添字は説明変数の番号. 単回帰の傾きも $\beta_1$), 推定値は $\hat\beta_j$, 誤差は $\varepsilon_i$, 残差は $e_i = y_i - \hat y_i$, 誤差分散は $\sigma^2$, その推定値は $s^2 = \frac{1}{n-k-1}\sum_i e_i^2$, 標本の大きさは $n$, 説明変数の数は $k$. 確率変数は大文字 ($Y$, $X$), 観測値は小文字 ($y_i$, $x_i$). 条件つき期待値は $E(Y \mid X)$. 記号表は `reg-ols` に置く.
4. GPA: 配布版 `slds_data/ch11/multiple_regression.csv` (0〜4, 100 人) を正本にする. 生成の仕組みを見せるときは `scripts/make_reg_gpa.py` を使い, 打ち切り前の値を「潜在得点」と呼ぶ. 生成式の係数は潜在得点についての値で, 観測した GPA の係数とは違うことを書く.
5. データを分ける順: GPA を読み込んだ直後, 図を出す前に `train_test_split(df, test_size=0.3, random_state=0)` で最終評価用の 30 人を取り分け, 係数表と図は残りの 70 人 (学習用) で作る. 探索用と確認用への分け方 (段 6 で決めた): 探索では学習用の 70 人を `train_test_split(train, test_size=0.5, random_state=0)` で探索用 35 人と確認用 35 人に分け, 確認用では選び直さない. 予測では学習用の 70 人の中の 5 分割の交差検証 (`KFold(n_splits=5, shuffle=True, random_state=0)`) で式を選び, 最終評価用の 30 人は最後に 1 回だけ使う.
6. コードのブロック: 冒頭に準備 (import, CSV の読み込み, 分割) を置き, 前のブロックの変数に頼らない. 出力は実際に走らせた結果を貼る. 図を作る script を `scripts/` に置き, 図は `images/fields/regression/<ブロック>/` に出す. 教材のコードの規則 (`coding/` の Python) に従う. データは旧ページと同じく GitHub の配布リンク (`https://github.com/yakagika/yakagika.github.io/blob/main/slds_data/...`) からダウンロードしてコードと同じフォルダに置く形にし, コードは `pd.read_csv("<file 名>.csv")` で読む.
7. 書式: front matter は「Phase 1 で決めた入力の形式」. 最上位の `#` 見出しでページに分け, `{#id}` を付ける. 「(発展)」と書かない. 他のブロックへは `[x](block:name#id)`. 演習は `# 演習 {#exercises}` の下に `## Exercise REG-XXX-k {#exercise-reg-xxx-k}` (XXX はブロック名から `reg-` を除いて大文字にしたもの), 回答は `<details class="protected" data-pass="yakagika">`. dsp の演習 (DSP5-1 など) を移すときもブロックでは REG-... と呼び, 提出 file 名は講義の並びで決める (段 8). 1 ブロックは 200〜600 行.

### 回帰分析の目的と立場の整理 (2026-11-20. 本人が方向を決定)

決定 (2026-11-20 本人): 回帰分析の分野は, まず素朴に相関の定量化と母集団への推定としての回帰を扱う. ベイズ統計学は, この推定の前提で分かれる立場としてつなげる. その上で予測を考え, 個体差や平均の推定の誤差が含まれることと, それをどう解決するか (変数の選び方, 未使用のデータでの評価など) を扱う. 因果推論は問う内容がさらに異なり, 背景の構造の前提が要ることを扱う. 目的の名前に「説明」は使わない. 以下は決定に至る検討の記録.

本人の方向: 先に回帰分析に与えられている目的と立場を整理し, 教科書の本体はそのうち 1 つの立場で進める. 相関の数値化として導入するのも 1 つの立場. 以下は検討の材料 (coordinator の案. L1).

立場ごとに違うもの: 何をよいモデルとするか, 変数をどう選ぶか, 何を報告するか, 何で確かめるか.

| 立場 | 問い | よいモデル | 変数の選び方 | 報告するもの | 確かめ方 |
|---|---|---|---|---|---|
| 記述 (相関の数値化の延長) | x の違う群で y の平均がどれだけ違うか | データの傾向を偏りなく要約する | 比べたい群の分け方で決める | 係数 (条件つきの平均の差) と区間 | 同じ母集団の別の標本 |
| 予測 | 新しい観測の y はいくつか | 新しいデータでの誤差が小さい | 検証データか交差検証で選ぶ | 新しいデータでの誤差 | 未使用のテストデータ |
| 因果 (説明) | x を変えたら y はどう変わるか | 前提のもとで効果を偏りなく推定する | 因果の構造 (交絡を調整し, 中間の変数は調整しない) から事前に決める | 効果の推定値と区間, 置いた前提 | 前提の検討, 感度分析, 別の設計 |
| 探索 | どの関係が調べる価値があるか | 次に確かめる仮説を出せる | 自由に選んでよい | 候補の仮説 (結論にしない) | 別のデータで確かめる |

組み方の案:
- 案 1 (記述を本体にし, 最後に目的ごとの使い方): 回帰を条件つきの平均の要約として導入し, 単回帰, 重回帰, 多重共線性までを記述の立場で通す. その後に予測, 因果, 探索の使い方を 1 ブロックずつ置き, モデル選択のブロックで立場ごとの選び方を比べる. 統計学 (相関の延長) と今の dsp5 の流れに近い. 因果の言葉を前提なしに使わずに済む.
- 案 2 (最初に目的と立場の地図, 本体は記述, 他の立場は各分野へ渡す): 最初のブロックで上の表を示し, 本体は記述の立場で進める. 予測の手順は機械学習の分野, 因果の手順は因果推論の分野, 探索の手順は分析設計の分野へ渡し, 回帰分析の分野からはリンクする. モデル選択のブロックは立場をまたいで比べる場所になる. 分野とブロックの仕組みに合うが, 回帰分析の分野だけでは立場ごとの手順を読み切れない.
- 案 3 (因果を本体にする): 計量経済学の教科書に近い. 最初に交絡と調整を置き, 係数を効果として読む前提を先に示す. 予測と探索は後に回す. 経済統計のゼミとつながるが, 統計学の講義の流れから離れる.

#### 文献の調査の結果 (2026-11-20, codex Astra の read-only の調査. subagent 2 本, 他のモデルへの照合なし, 開いた配布元は学会誌, 出版社, 著者のサイト)

文献が分ける目的 (codex が本文で確かめたと報告した. L3 は codex の申告で, coordinator の知識とも合うが, 本文の照合は引用の前に行う):

| 文献 | 分け方 | この計画への意味 |
|---|---|---|
| Shmueli (2010), Statistical Science 25(3) | 説明 (理論から導いた因果の仮説の検証), 予測, 記述 (データの構造や関連の要約). 詳しく比べるのは説明と予測 | 「説明・予測・探索」の 3 分類の典拠にはならない. Shmueli の「説明」は因果の検証で, 今の dsp5 の「説明」(関連の大きさの推定) とは意味が違う |
| Hernán, Hsu and Healy (2019), CHANCE 32(1) | 記述, 予測, 反事実の予測 (因果推論). 推測と信頼区間は 3 つのどれにも現れる | 計画の記述, 予測, 因果に最も近い. 「説明」という呼び名は, 効果が分かっても機序が分からない場合があるので避ける |
| Leek and Peng (2015), Science 347 | 記述, 探索, 推測, 予測, 因果, 機序の 6 つ | 探索を独立した問いとして置く根拠になる. 係数の区間まで報告する「記述」は, この分類の「推測」にもまたがる |
| Heinze, Wallisch and Dunkler (2018), Biometrical Journal 60(3) | Shmueli の 3 目的を変数選択に当てはめる (予測は誤差, 説明は効果の偏り, 記述は関連の係数) | 記述を本体にしても, モデル選択を目的ごとに詳しく扱える根拠になる |
| Breiman (2001), Statistical Science 16(3) | 目的は予測と情報 (入力と応答の関係を知ること) の 2 つ. 「2 つの文化」は方法の違い | 「確率モデルなら説明, アルゴリズムなら予測」と教える根拠にはならない |
| Gelman, Hill and Vehtari (2020), Regression and Other Stories, §1.2 | 回帰の用途として予測, 関連の探索, 標本から母集団への外挿, 因果推論を挙げ, 因果推論は第 18〜20 章で詳しく扱う | 案 2 の入口に最も近い. 因果の問いを最初に見せることと, 因果の読み方を教えることを別の時点に置ける |

教科書の順序 (目次で確かめた. L2): Hansen (2022, Econometrics) は条件つき期待値, 最良予測, 線形近似, 因果効果の順に置いてから最小二乗法へ進む. 竹内 (2021, 経営・商学のための統計学入門) は散布図と相関から単回帰, 重回帰へ進む (今の統計学の講義に最も近い). Angrist and Pischke (2009) は因果の問いを先に置くが, 回帰の章でも「教育年数ごとの平均賃金」を計算する段と, 効果として読む条件を示す段を分ける. James ほか (2021, ISLR 第 2 版) は関数を推定する目的を予測と推論に分けて始める.

計画の 4 つの立場の表を直す点 (codex の提案. L1):

1. 「因果 (説明)」は「介入の効果」と呼ぶ. 「説明」は今の dsp5, Shmueli, Hernán ほかで 3 つの意味を持つので, 学生が答える問いを行の名前にする.
2. 探索は, 仮説を見つける問いとしても, 他の目的の途中で行う作業としても示す. 散布図を見ただけで記述や予測が探索になるわけではない.
3. 「誰について述べるか」(手元の標本か, 標本から推定する母集団か) の列を足す. 後者には標本の選び方と不確かさの説明が要る.
4. 「よいモデル」を 1 つの性質で決めない. 記述では比べる集団と条件と関数の形, 介入の効果では総効果か直接効果か, 予測では選ぶデータと評価するデータの区別が要る.

codex の推奨は案 2 の変形 (L1): 冒頭で同じ GPA のデータについて 3 つの問いを並べる (勉強時間だけが違う学生を比べると平均がどれだけ違うか / 別の学生の GPA をどれだけ正確に当てられるか / 勉強時間を増やす介入をしたら平均はどう変わるか). 本体は最初の問い (条件をそろえたときの平均の比較) で進める. 重回帰では係数ごとに「どの条件をそろえた差か」を答えさせる. モデル選択のブロックでは, 同じ変数 (アルバイト時間を入れるか) を, 記述 (誰と誰の比較になるか), 予測 (予測する時点で分かる変数か, 検証データで誤差が減るか), 介入の効果 (介入の前後どちらにある変数か), 探索 (得た仮説を何で確かめるか) の順に扱う. その後に, パネル分析で全変数を入れて p 値で比べる例, ステップワイズ法, 情報量規準, 選んだ後の推論を置く. 案 2 の元の弱点 (回帰分析の分野だけでは目的ごとの手順を読み切れない) は, モデル選択のブロックに目的ごとの判断の例を残すことで補う.

本人の応答 (2026-11-20): 組み方は「1 で良い」(選択肢の 1 番目 = 案 2 の変形か, 案 1 かは次の質問で確かめる). そのうえで, 調査の結果はアカデミアでも合意が無いことを示しているので, この講義と本人の立場をある程度決めておきたい. 調査で挙がった立場を整理した説明を求めた (coordinator が会話で説明し, 次の質問で立場の要素を決める).

本人の整理の案 (2026-11-20): 関係を定量化し, それが母集団でも成り立つかを推測することは, 基本的に合意されている. これを第一の目的とする. 予測まで行う, あるいは因果まで主張する場合は, それぞれ方法論が異なる (ここまでも合意がありそう). よって, まず関係の範囲で説明し, その上で予測とは何か, 因果とは何かを説明する. それぞれで変数の選び方などの方法論が異なり, ステップワイズ法などはその中のどこかにあって, 基本的には第 2 段階の目的のための事前の作業である.

coordinator の補足 (L1, 本人の確認待ち): (a) 教える順序としては段階で良いが, 予測は係数の推測を前提にしない (p 値ではなく新しいデータでの誤差で判断する). 因果は係数を使うが, 前提と設計を足す. (b) 第一の目的にも変数の選択はある. 重回帰の係数は, どの変数をそろえるかで表す比較が変わるので, 入れる変数は問いで先に決める. データを見て選ぶと, 同じデータで計算した p 値が小さく出て, 母集団への推測が成り立たない (全変数を入れて p 値で比べる問題とステップワイズ法の誤用はここで起きる). (c) ステップワイズ法が正当に使えるのは, 予測 (検証データの誤差で判断する探索の道具として) と探索 (得た候補を別のデータで確かめる) で, 因果では使わない (変数は因果の構造で選ぶ). (d) 探索は, 第一の目的をデータを見て選びながら行う場合と位置づけられる. 結果は仮説で, 母集団への推測は別のデータで行う. 文献の候補: Westreich and Greenland (2013, 全変数を入れたモデルの各係数を効果と読む誤り. 論文 DB に登録済み).

本人との検討で確かめた目的の違い (2026-11-20, coordinator の説明. ブロックの本文の下書きの材料):

- 関係の定量化と推測: 標本を取った母集団 (実際の世界) について, 他の変数をそろえて X が違う人を比べたときの Y の平均の差を求め, 区間と検定で母集団へ広げる. 前提は標本が偏りなく取られていること.
- 予測: 同じ母集団から新しく取り出す個体 (標本と同じ分布) の Y を当て, 外れる幅を示す. 予測値は同じ X の個体の平均で, 誤差には平均の推定の誤差 (過学習を含む) と, X で説明できない個体差が入る. 平均の信頼区間と予測区間の違い (statsmodels の `get_prediction().summary_frame()` の mean_ci と obs_ci) で示せる. テストデータは新しい個体の代わり.
- 因果推論: 同じ母集団で X を介入で変えた仮の世界の Y の平均を述べる. 実際の世界と介入した世界をつなぐのは, データの外から持ち込む因果の構造の仮定 (または無作為な割り付けという設計). 構造を仮定として明示し, その仮定のもとで求めたい量が観測の分布から求まるか (識別) を判断し, 求まるなら調整して推定し, 仮定が崩れたときの感度を調べる.
- 別の母集団へ広げること (外的妥当性, 分布シフト, 移転可能性) は 3 つのどれにも加わる前提で, 予測と因果推論を分けるものではない.
- 文献の候補 (書誌は未確認): Pearl and Mackenzie (2018) の関連, 介入, 反事実の 3 段. 予測は 1 段目に入る.

coordinator の見方 (L1): 案 1 と案 2 の違いは, 目的の地図を冒頭に置くか最後に置くかと, 予測と介入の効果の詳しい手順を回帰分析の分野に置くか他の分野に渡すかの 2 点. 案 1 は地図を最後まで出さないので, 学生が最初の傾きを効果と読む余地が残る. codex の案 2 は冒頭の 3 つの問いでこれを防ぐ. 本人の方向 (1 つの立場で進める. 相関の数値化も 1 つの立場) とも合う.
