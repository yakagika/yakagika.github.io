# 講義資料を分野とブロックに分け, 講義はブロックの並びかブロックへのリンクで組む

## メタ情報

- **状態**: in-progress (2026-11-20 起票. 要件は本人との質疑で確定済み. 計画の承認待ち)
- **作成日**: 2026-11-20
- **最終更新**: 2026-11-20
- **関連計画**: [dsp-course-material.md](dsp-course-material.md) (必修と発展の区分, 第5章冒頭の見取り図), [dsp-causal-concepts-before-regression.md](dsp-causal-concepts-before-regression.md), [lecture-literature-grounding.md](lecture-literature-grounding.md), [2026-11-20-dsp5-logistic-regression.md](../landed/2026-11-20-dsp5-logistic-regression.md)
- **出所**: 本人の提案 (2026-11-20) 「データサイエンス実践などで扱っている内容を 1 つの講義の中でまとめるのではなく, 回帰分析, 推測統計学, ベイズ統計学, 機械学習などに分け, かつそれぞれの中身もブロック単位に分ける. 各講義資料ではそのブロックを参照してリンクの順序だけを組み替える」. 同日, 評価を示した後に質疑で要件を詰めた.

## 概要

講義資料の内容を, 教科書の形で通読できる「分野」と, その中の「ブロック」に分ける. データサイエンス実践とデータ活用の統計学は, ブロックの並びから講義のナビと回のページを生成する. 特別講義とゼミは, 講義のページからブロックへリンクするだけにする.

## 動機

本人が挙げた問題 (2026-11-20).

- 第5章 (回帰分析) が約 2100 行になり, これ以上の内容を入れる場所がない.
- 因果推論などを扱うと, 章の順序の再編が要る (例: 交絡と因果の概念を重回帰より前に置く計画).
- 統計学, ゼミ, 特別講義で同じ技術を扱う.
- 同じ技術を扱っても, 講義ごとに演習や課題が共通しない場合がある.
- 必修と発展の区分が講義によって違う (いまは章の本文に「(発展)」と書いているので, 講義ごとに変えられない).

## 用語

| 採用する語 | 定義 | 避ける語 |
|---|---|---|
| 分野 | 教科書の形で頭から通読できる, ブロックのまとまり. 例: 回帰分析, 推測統計 | 科目, モジュール |
| ブロック | 講義が参照する内容の単位で, 本の章くらいの量. 例: 「回帰分析は何を行っているのか」「単回帰分析」 | 小単位, 章 (dsp の第N章と紛れる) |
| ページ | Web に表示する単位. 1 つのブロックを見出しで分けたもの | |
| 講義 | ブロックの並び (またはブロックへのリンク) と, その講義だけの資料 (演習, 課題, 問いの立て方など) を合わせたもの | コース |
| 講義の並び | 講義ごとに, 回ごとに読むブロック, 必修か発展か, 課す演習を書いたもの | シラバス (大学の公式文書と紛れる) |
| 回のページ | 講義の並びから生成する, 1 回の授業で読むブロックと課す演習の一覧のページ | |

## 確定した要件 (2026-11-20 本人)

| 項目 | 決定 |
|---|---|
| 対象の講義 | データサイエンス実践 (dsp), データ活用の統計学 (新規. いまはスライドで講義し, 内容の一部は Obsidian の `Knowledge/統計学` に 14 回分, 約 17000 行ある), 特別講義 (来年度からデータサイエンスプロジェクト), ゼミ. 関数型プログラミングは対象外 |
| 講義の組み方 | dsp と統計学は講義の並びを組み, 並びのナビと回のページを生成する. 特別講義とゼミは講義のページからブロックへリンクするだけで, 並びの生成はしない (ブロックの中では分野の教科書の前後ナビで読む) |
| 特別講義の構成 | 講義のページで直接扱うのは問いの立て方や研究計画など. その後, 順序を示して共通のブロックを読ませ, 学生のテーマに合わせて必要なブロックを個別に案内する |
| ゼミの構成 | 特別講義に近い. 分野をデータサイエンス以外 (経済統計, ABM など. 資料はまだ無い) へ広げる |
| 分野 | 教科書の形で通読できるようにする |
| ブロックの大きさ | 「回帰分析は何を行っているのか」「単回帰分析」くらい (いまの dsp の `##` の節 1 つ, 200〜600 行) |
| 数式とコード | 理論のブロックとコードのブロックに分ける. コードのブロックにもモデルの式と係数の意味は書き, 導出は理論のブロックへリンクする. 記号と例題データは分野ごとに揃える. 統計学は理論を中心に, dsp はコードを中心に並べる |
| 講義が参照する単位 | ブロック. 特定のページだけを読ませたいときは, 講義のページに普通のリンクとして書く |
| ページへの分割 | ブロックは 1 つの md file に書き, build が決めた深さの見出しでページに分ける. ブロック内のリンク (`#見出し`) は build がページへのリンクに書き換える |
| 演習 | ブロックにも教科書の章末問題のように演習を持たせ, 講義が課すものを選ぶ. 共通にできない演習と課題は講義のページに足す |
| 必修と発展 | 講義の並びで指定する. ブロックの本文と分野の教科書には「(発展)」と書かない |
| 切り替え | 年度替わり. 今年度の dsp は旧ページ (`dsp1.html`〜`dsp16.html`) のまま続け, 学生に配った URL は年度中に変えない |
| 移行中の編集 | 旧ページには誤りの修正と今年度の授業に要る変更だけを入れ, 新しい節や大きな書き直しはブロックの側で行う. 例外: 別の session が進めている第5章の書き直し (lecture-literature-grounding の Phase 1) は旧ページで続け, 終わった後にこの計画で引き取ってブロックへ移す |
| 試験的に移す分野 | 回帰分析. 上の書き直しが land した後に着手する |
| 統計学の正本 | 移した後はサイトのブロックを正本にする. Obsidian の資料は役割ごとサイトへ移す (移した後, Obsidian の note は削除するかサイトへのリンクに置き換える) |
| 開講の時期 | 統計学, 特別講義, ゼミは春学期 (2027 年 4 月から). dsp は秋学期 |

## 設計 (案. 本人が計画を読んで直す前提)

### 分野の分け方

| 分野 | 主な出どころ |

| 記述統計 (可視化, 数値化, 相関) | dsp 第3, 4章, 統計学 第3〜5回 |
| 確率と確率分布 | 統計学 第6〜8回 |
| 推測統計 (標本と区間推定, 仮説検定) | 統計学 第9, 10回 |
| 回帰分析 (単回帰, 重回帰, 回帰の評価, 一般化線形モデル) | dsp 第5章, 第13章の一般化線形モデルの節, 統計学 第11回 |
| ベイズ統計学 | dsp 第13章 |
| 機械学習 (枠組み, 決定木, クラスタリング, 次元削減, ニューラルネットワーク) | dsp 第6〜8章 |
| 深層学習とその応用 (自然言語処理, Transformer, 画像認識) | dsp 第8〜11章 |
| 因果推論 | dsp 第16章, 交絡と因果の概念を前に置く計画 |
| 調査データの扱い (質問紙, 欠損値) | dsp 第14, 15章 |
| 分析設計 | dsp 第2章 |
| データの取得 (API) | 特別講義の補足 A〜C |
| プログラミングの基礎 (環境構築, Python, git, エージェント) | いまの共通資料 (`lectures/common/`) |

統計学の第1, 2, 12, 13回の扱いは, 移すときに中身を読んで決める.

### source の配置と名前

- 分野ごとに dir を置く (例: `lectures/fields/regression/`). 分野の dir に, 教科書の順を書いた file と, 記号の表を置く.
- ブロックの名前は, 分野を表す接頭辞と短い英語の名前にする (例: 単回帰の理論は `reg-simple`, Python で行う側は `reg-simple-py`). ページは `reg-simple-1.html` のように番号を付ける.
- `lectures/**` は basename だけで出力先と章の検索を決めているので (`src/Main.hs` の `chapterFileToIdentifier`), basename が重なったら build を止める検査を足す.
- 例題データとコードは分野ごとの dir に置く (いまの `slds_data/`, `slds_code/` との関係は Phase 1 で決める).

### ブロックの front matter

- `title`, 所属する分野, 前提のブロック (`requires`), 種類 (理論かコードか), `open`, `bibliography`.
- 演習はブロックの末尾の `# 演習` に置き, ブロックの名前で番号を付ける (例: `Exercise REG-SIMPLE-1`). 回答は今と同じく `<details class="protected">` で埋め込む.

### 講義の並び

- 講義ごとに 1 つの file (例: `lectures/courses/dsp.yaml`) に, 回ごとに読むブロック, 必修か発展か, 課す演習, 講義だけの資料のページを書く.
- build はこの file から, 並びの前後ナビ, 講義の目次, 回のページを生成する.
- 前提の検査: 講義の並びと分野の教科書の順で, `requires` のブロックが先に来ているかを build で検査する. dsp で守ってきた「新しい章では前の章で教えた手法だけを使う」規則を, この検査で機械的に確かめられる.
- 特別講義とゼミは講義の並びの file を持たず, 講義のページの本文にブロックへのリンクを書く.

### 共有するブロックの見え方 (未決. Phase 2 で決める)

1 つのブロックを dsp と統計学の両方の並びに入れたときの出し方を, 次の 2 案で試して決める.

- 案 A: 講義ごとに別のページを生成する. 本文は同じで, URL とナビ (前後, 目次, 必修か発展かの表示) が講義ごとに違う.
- 案 B: ブロックごとに URL は 1 つにし, ページの上部に所属する講義の一覧と, 講義ごとの前後のリンクを並べる.

### 付随する記録と規則

- モデルカリキュラムの対応表 (`plan/landed/2026-11-20-dsp-curriculum-matrix.md`) は, dsp の並びに対して付け替える.
- 文献表はブロックのページごとに出す (今と同じく `bibliography: lectures`).
- `CLAUDE.md` の dsp と slds の規則 (演習の見出し, 章ナビ, 演習の配置) を, ブロックと講義の並びの規則に書き換える. 書き換えは各 Phase で, その Phase で移した範囲に合わせて行う.
- 特別講義 (slds) は今年度は凍結のまま. 来年度のデータサイエンスプロジェクトの講義のページは新しく作り, 旧 slds のページは残す.

## ロードマップ

1. **Phase 0 (今)**: 本計画を codex に独立レビューに出し, 相違点を裁定して本人の承認を取る. 別の session に移行中の編集の方針を伝える.
2. **Phase 1 (〜2026-12)**: 仕組みを作る. 分野とブロックの dir, ページの自動分割とリンクの書き換え, 分野の教科書の目次と前後ナビ, 講義の並びの file から生成するナビと回のページ, basename と前提の検査. 小さな見本の分野 (2〜3 ブロック) で build を確かめる. Hakyll の変更なので worktree で行う.
3. **Phase 2 (lecture-literature-grounding の Phase 1 の land 後)**: 回帰分析を試験的に移す. 理論の側は統計学 第11回と dsp の第5章の発展の節から, コードの側は dsp 第5章から作る. 第5章冒頭の一般化線形モデルの見取り図 (親計画の未解決事項) と, 交絡と因果の概念を重回帰より前に置く計画は, この分野の設計の中で扱う. 共有するブロックの見え方を決める. 結果を見て仕組みと書き方の規則を直す.
4. **Phase 3 (〜2027-03)**: 統計学の残り (記述統計, 確率と確率分布, 推測統計) を Obsidian から移し, 統計学の講義の並びを作る. 移した note ごとに Obsidian 側の扱い (削除かリンクへの置き換え) を本人に示してから行う.
5. **Phase 4 (〜2027-03)**: データサイエンスプロジェクト (旧 特別講義) とゼミの講義のページを作る. データの取得とプログラミングの基礎の分野を移す.
6. **Phase 5 (2027 春学期〜夏)**: dsp の残りの分野を移し, dsp の講義の並びとモデルカリキュラムの対応表を作る. 秋学期の開始で旧ページから切り替える.
