## 動機

### (1) 統一視座 (討議での合意事項)

- 数学的対象の定義は「組 + 法則」であり, 成分は三分される: **データ** (選ぶもの: 台・演算 — 選び方で対象が変わる) / **性質** (検査されるもの: 結合律等) / **property-like** (あれば一意に決まる: 単位元・恒等射).
- **アリティ**が演算を統一する: 単位元 = 0 項演算, dom/cod = 1 項, `<>`・`∘` = 2 項.
- 普遍代数 → 圏の「飛躍」は 2 点に分解される: (a) 演算の定義域が等式 $\{(g,f)\mid \mathrm{dom}\,g=\mathrm{cod}\,f\}$ で絞られる (部分性 = 引き戻し. **fp7 の内包表記で書ける** = 既習語彙で閉じる), (b) **台が「値」から「射 (前段の写像)」へ持ち上がる**.
- functor は二役: **準同型** (段の内側の写像 — モノイド準同型と同格) / **次の段の台** (関手を台に据えると Cat).
- **俯瞰の階段**: 図1 (点=型, 矢=関数) → 図2 (点=圏, 矢=関手) → 図3 (点=関手, 矢=自然変換). モナド = 最上段でレシピをもう一度回したもの (自己関手の圏のモノイド $(T,\eta,\mu)$) — fp10 の現行対応表が着地点.

| 段 | 台 (= 前段の写像) | 演算 | 単位 |
|---|---|---|---|
| モノイド (fp8) | 値 (1 対象版の雛形) | `<>` | `mempty` |
| 圏 Hask (fp9) | 関数 (集合の写像) | `(.)` (定義域 = 型の合う対) | `id` |
| Cat | 関手 (圏の準同型) | 関手合成 | 恒等関手 |
| 関手圏 (fp10) | 自然変換 | 合成 / 関手合成を積に | 恒等自然変換 / Id |

- 現行 fp7-9 は配信済みで, この視座は note 追記では入りきらない (概念の導入順・語彙という骨格に関わる) → 全面改訂. ユーザ決定 (2026-07-10): 「反映というより統一視座に基づいて作り直す」.

### (2) fp1 の物語 (Phase B の thesis)

- **代数的に定義すること** (正本: fp12 導入節「仕様を等式で書く — 順序の逆転」= シグネチャ / 公理 / モデル. memory `feedback_algebra_first_assignments`).
- **thesis**: 自然言語の記述では「記述できたような錯覚」に陥る. 厳密な構造を書けないものは **理解できない・操作できない・制御できない**. だから数学・工学の手法 (代数的定義・型) が必要であり, **Haskell はそれに非常に向いている**.
- 認知科学的裏付け: reification ([teaching-reification-cognitive-skills](../proposed/teaching-reification-cognitive-skills.md) — 過程を対象として記述できて初めて操作可能になる. Sfard の operational/structural 二重性).

### (3) スコープ境界

「列挙型 → 集合論 → 関数の定義 → その他の代数的データ型 → 代数 → 圏」という完全な再導出体系は **Learn (knowledge layer) 側の営み**とし, fp 講義は講義としての実用平衡 (環境構築・演習・提出) を保つ. v2 はその講義版の近似.

## 設計

### 設計原理 (v2 の背骨)

各章は「数学的定義 ∥ Haskell 実装 ∥ 対応関係」の三本立て (memory `feedback_lecture_math_haskell_parallel`) を維持しつつ:

1. **すべての構造を「組 + 法則」で提示**し, 成分をデータ / property-like / 性質に三分して表で明示する.
2. **演算はアリティで統一**: 単位元 = 0 項演算として導入 (圏では単位が対象ごとの割当 $\forall A.\ \exists\,\mathrm{id}_A$ に一般化される点を fp9 の量化子対比で明示する — 0 項演算のままでは多ソート化を吸収できない).
3. **段の移行は「台に何を据えるか」だけを変える**: 値 → 関数 → 関手 → 自然変換. 新概念のたびにこのレシピ表に戻る. **注意 (codex 指摘 2026-07-10)**: モナドはこの列の「次の段」ではなく**最上段の圏の中の**モノイド — 台 = 自己関手 $T$ (= 前段の射), 積 = 関手合成 $T \circ T$, $\mu$/$\eta$ = 最上段の射 (自然変換). 階段 (圏の列) とモノイド対象 (圏の中) を混同しない (fp10 に区別 note 追加済み).
4. **部分性は内包表記で**: `∘` の定義域 = $\{(g,f)\mid \mathrm{dom}\,g=\mathrm{cod}\,f\}$ (「引き戻し」の名は脚注).
5. **準同型 (構造を保つ写像) を各段の一級市民に**: 関数 → モノイド準同型 → 関手 → 自然変換.
6. 文体は ですます調 (`feedback_lecture_desumasu_tone`), エラーは専用列挙型 (`feedback_error_enum_over_string`), 演習は algebra-first (`feedback_algebra_first_assignments`), 見出しは `### Exercise CHN-K` 規約.
7. **v2 にはエラー修正演習を置かない** (ユーザ判断 2026-07-13: 「あまり意味をなしていない」). v1 由来のエラー修正演習は v2 化の際に削除し, 以降の v2 章 (fp9v2〜) でも新設しない. v1 (fp5/fp7/fp8) 側は現状維持.

**設計原則 8 項 (2026-07-13 ユーザ確認済みの言語化. 以後 fp 全体に適用. memory `fp-lecture-design-principles` と同内容):**

8. **図でわかりやすさを保つ** — 具体的な圏・構造が出てきたら図を入れる (fp9 後半以降も). 図は系列 (図0〜図4) として章をまたいで再登場・発展させ, ラベルは「射」, 成分は Ob=/Mor= 等の定義と照合可能な等式で併記する.
9. **抽象化は具体の後に 1 段ずつ** — 一般定義・型クラスの前に必ず具体的構成を手で作る (fmap は関手より 1 段抽象的だから後. マグマ方式 = クラスなしの構造を先に). 「何の一般化か」を見失わせない.
10. **誤概念の予防は warn でなく構成で** — 誤解を生む導入順序・最初の例そのものを変える (例: リストを最初の関手例にすると関手 ≒ Functor クラスと誤認 → 一点圏関手 length を先に).
11. **比喩の採用基準 = 全実例に同じ言葉が通ること** — 部分的にしか成り立たない比喩 (「f は箱」) は採用しない. 定義から導かれた読み方 (fmap = 適用前の世界の関数を適用後の世界で使える関数へ変換 = 射の対応 = 準同型と同じ) を使う.
12. **少数の例を深く使い回す** — length / fromEnum / リスト / stats / mkZ7 / Frac が章をまたいで新しい見方で再登場する形を優先し, 新概念に新例を持ち込まない.
13. **名前と記法の照合可能性** — 「矢」でなく「射」. 図の注記は定義の組と同じ成分名. 概念操作にも命名して再利用 (「俯瞰」「読み替え」「持ち上げ」).
14. **地図を先に渡して各節で回収** — 章冒頭に完成形のロードマップ (俯瞰の階段など) を置き, 「?」で引っ張るより「どこで確かめるか」を指す.
15. (7 の一般化) **本筋に寄与しない要素は削る** — 概念構築に寄与しない演習・注記は網羅性より純度を優先して削除.

#### fp8v2 の確定骨子 (2026-07-10, ユーザ承認 = 3 案の統合)

1. **型クラスという機構** — Show で class/instance/deriving (法則を持たない「機能」の例として)
2. **構造 = 組 + 法則の一般形** — 台 + 演算/関係, データ/性質/property-like, アリティ再説. 「関係 = Bool への 2 項演算」の読み替え
3. **Eq = 同値関係** (反射・対称・推移) → 同値類・**商集合** (有理数 1 例. custom Eq = 商の選択) → fp12 Bag/Set 予告
4. **Ord = 全順序** → **全順序集合は束** (meet = min, join = max. 束の代数的詳細は発展 note)
5. **代数階層**: マグマ → 半群 → モノイド → 群. 群の例に **ℤ/7ℤ (曜日) — 商集合が群をなす** (3. と合流)
6. **ブール代数 = 二重の合流点** (演算ルートの 2 モノイド = 順序ルートの束の meet/join)
7. Enum・Bounded / Num (現行を継承)
8. **準同型 — 「構造を保つ写像」へ一般化** (モノイド準同型 + 単調写像 = 順序の準同型 + Eq を保つ写像) → fp9v2 関手の前提
9. 利点 (foldMap/stimes/並列) + QuickCheck

**正確化** (評価で確定): 「同値類は群」→ 正しくは群の合同による商 ($\mathbb{Z}/n\mathbb{Z}$) が群 / 「順序集合は束」→ **全順序**なら束 (Haskell の Ord は全順序なので教材の範囲では真). **重量制御**: 商集合は 1 例に絞る, 束は主張 1 つ + 発展 note.

#### fp9v2 の確定骨子 (2026-07-10, ユーザ承認)

1. **導入 — 見方の転換**: 「今までは型 = 値の集合を台としてみていたが, 型の間の関数 (射) を台としてみてみる」(fp7 = 集合, fp8 = 値の上の演算 + 準同型, の総括として)
2. **圏の定義 — 組と法則** (現行 fp9 `adae0fd` の節を移植)
3. **Hask — データ型は対象, 関数は射** (同)
4. **俯瞰の階段 (ロードマップ版)**: 次の段の台 = 圏の写像 = 未定義の「?」→ 関手定義の動機づけ
5. **関手 — 圏の準同型**: 定義 + 最初のモデル = **既習の `[]` / `map`** + モノイド準同型もまた関手
6. **多相データ型 — 関手のモデルたち**: 型構築子の文法 (Box/種) → Maybe (安全な head 等の実用動機は**ここで完全に**語る) → Either (専用エラー列挙型) → リスト再訪 → Map → Tree. 各 `instance Functor` + 基本操作 (`maybe`/`either`/`fromMaybe`)
7. **自然変換 — 関手どうしの変換**
8. **まとめ — 階段のここまで** (fp10 へ)

**構成改訂 (2026-07-13, ユーザ指示)**: 骨子 4 の「?」方式ロードマップは廃止 — (a) **俯瞰の階段 (完成形, 図0〜図3 列つき) は章冒頭の対応表直後へ移設** (「レシピは同じまま台を持ち上げる」も同所. 各段は後続節で回収する地図として提示), (b) 「圏はモノイドの一般化」は末尾の階段を除去し **一点圏の具体例** (リストのモノイド $([\mathrm{Int}], ++, [])$ の成分対応表 — 値が射になる) を配置, (c) **関手導入は具体的構成から**: fmap は関手の一般化で抽象度が 1 段高い, という理由で「手作りの関手」節を新設 (Bool/Int/String の圏 → リスト版の圏への $F$: 対象表 + 射表 + 専用 SVG (圏 C → F → 圏 D) + 恒等・合成保存の実行検査 = spec FunctorConstructSpec) → 一般の定義 → 図1+図2 → リスト関手と fmap (ミニチュアの制限を外す) の順.

**構成改訂 2 (2026-07-13, ユーザ提案 → agent 評価賛成 → AUQ)**: 関手の最初の例からリストを外し, **自作の圏どうしの関手を先に手実装, Haskell の Functor クラスは特殊ケースの型クラス化として最後に置く** (マグマ・群の「標準クラスの有無」パターンと同型に). 節構成 = ①最初の関手 = 一点圏どうし (前節のリスト一点圏 → (Int,+,0) 一点圏への length. クラスなし = 関数+法則, spec LengthFunctorSpec. stats SVG と mkZ7/fromEnum への一般化をここに統合) → ②2 つ目 = リストの世界への複写 (対象対応が非自明な例, 既存) → ③一般の定義 (2 例を抽象) → ④リスト関手と fmap = **Haskell が型クラス化した特殊ケース** (載る条件 3 つ = 自己関手 Hask→Hask / 対象対応が型構築子 / 射対応がパラメトリック 1 本, ＋「標準クラスの有無」表 (一点圏関手・小さな圏の関手 = クラスなし / 自己関手 = Functor / 反変 = Contravariant) ＋発展 note「f は箱」比喩の位置づけ (Reader 反例, a -> f a は Functor の要件でなく pure=η の領分, 比喩は言語制約の反映)). 旧「モノイド準同型もまた関手」節は①と④に吸収して廃止. 動機 = fmap は関手の射対応の一般化で抽象度が 1 段高く, 先に載せると「関手 = fmap を持つ型構築子」と取り違える.

**成立条件** (評価 2026-07-10): (1) **fp8v2 の準同型一級化が前提** — fp9v2 は fp8v2 の後に書く (着手順 fp7v2→fp8v2→fp9v2 で担保), (2) **実用動機はモデル各論に温存** (構造先行 ≠ 動機抜き. fp10/fp12 が Maybe/Either の実用性に依存), (3) **型構築子文法の橋** を関手→多相データ型の継ぎ目に置く. 留意: 「多相データ型は関手の**候補**」(反変位置の counterexample を warn で) を維持.
