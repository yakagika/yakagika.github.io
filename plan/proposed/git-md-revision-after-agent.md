# git.md の修正案 (agent.md の改稿を受けて)

## メタ情報

- **状態**: proposed (修正案. git.md はまだ変更していない)
- **親計画**: [common-agent-literacy-material.md](../in-progress/common-agent-literacy-material.md)
- **根拠**: 2026-10-02 の agent.md の改稿 (`0f606e2` から `8c24fa8` まで). 初日に CLI を使い始め, git をほとんど触ったことのない学生を想定する.
- **対象**: `lectures/common/git.md` (696 行, 見出し 19 節, 演習 GIT-1〜3)

## 背景: agent.md で何が変わったか

1. 差分の確認, 記録するファイルの一覧, commit と push を, 学生がコマンドを打たずに codex へ頼む形にした (`変更したファイルを VSCode で開いてください`, `commit して push してください`).
2. 詳細 (読み込みの順番, 設定の一覧, 補助の操作) を note に移し, 本文を 1 周に必要な内容へ絞った.
3. 「意味を理解していない操作は許可しない」warn を, push の手順の直下に置いた.
4. 情報が古くなる旨の warn を冒頭に置いた.
5. 例の指示は, 学生のリポジトリに無いファイル (`data/sales.csv`) を前提にしないようにした.
6. 末尾に, この資料を使う 3 つの講義へのリンクを置いた.

git.md は agent.md より先に読む資料なので, agent.md の変更によって「何を手で打たせ, 何を読めればよいか」が変わる.

## 現状の問題

| # | 問題 | 場所 |
|---|---|---|
| P1 | 日常のコマンドを 7 つ, すべて手で打つ前提で並べているが, agent.md では学生が打つのは最初の 1 回だけで, 以後は codex が実行する. 学生に必要なのは, 表示されたコマンドを読んで意味を言えることである | 「日常的に使う 7 つのコマンド」 |
| P2 | 「`git diff` は新規ファイルを表示しない. まず `git status` を見る」の warn は, agent.md の手順 4 (差分を codex に表示させる) と対応していない. codex が `git diff` だけを実行すると, 新規ファイルを読まないまま進む | 同上 (diff の warn) |
| P3 | 演習 GIT-1 と GIT-2 で, `status`, `add`, `diff --staged`, `commit`, `push` を 2 回続けて手で打つ. 初日の学生には分量が多く, 重複している | 演習 GIT-1, GIT-2 |
| P4 | 初日に不要な設定が本文に入っている (既定のエディタ, noreply アドレス, 並列作業とコンフリクトの節) | 「既定のエディタの設定」, 「並列作業とコンフリクト」 |
| P5 | 手順 7 で `git add .` を使わせている. `.gitignore` が正しく設定できているかを確かめる前に全部を選ぶので, `data/` の取りこぼしが起きうる | GIT-1 の手順 7 |
| P6 | 「なぜエージェントと git を一緒に使うのか」が 4 節 (約 40 行) あり, 最初の画面が説明で埋まる | 冒頭 |
| P7 | 最新情報の注意と, 末尾の関連講義へのリンクが無い | 冒頭, 末尾 |
| P8 | push の取り消しにくさと「意味を理解していない操作は許可しない」への言及が, git.md には無い | push の節 |

## 修正案

### 1. 冒頭

- 警告 (warn) を 1 つ足す. GitHub の画面, 認証の方法, 料金は変わるので, 資料と食い違ったら公式のヘルプで確かめる. (agent.md と同じ趣旨)
- 「なぜエージェントと git を一緒に使うのか」は, 4 節を残し, 各節を 2〜3 文に縮める. 「並列作業とコンフリクト」は, 初日の範囲外なので note に降ろす. (P4, P6)

### 2. 日常のコマンド: 7 つ → 5 つ + 読み方の表

- 本文に残すのは `status`, `diff`, `add` (と `diff --staged`), `commit`, `push` の 5 つ. 見出しを「日常的に使う 5 つのコマンド」にする.
- `log` と `restore` は note に移す. ただし `restore` の「取り消せません」の warn は, 見落とすと損失が大きいので, warn のまま note の外に残す. (P1)
- 5 つのコマンドの直後に, 次の対応表を note で足す. 学生が手で打つ必要は無く, codex が実行したコマンドを読めればよい, という位置づけにする.

  | 頼む文 (codex へ) | codex が実行するコマンド | 読むところ |
  |---|---|---|
  | `変更したファイルの一覧を見せてください` | `git status` | `modified` と `Untracked` |
  | `右の pane に変更の差分を表示してください` | `git diff` | `+` の行と `-` の行 |
  | `記録するファイルを一覧にしてください` | `git add` と `git diff --staged` | 鍵やデータが入っていないか |
  | `commit して push してください` | `git commit` と `git push` | メッセージが作業と合っているか |

- `diff` の warn (P2) は書き換える: 「`git diff` は新規ファイルを出さない. 新規ファイルの有無は `git status` で見る」は残し, 続けて「codex に差分を頼むときは, `新しく作ったファイルも含めて` と添える」を足す. (agent.md の手順 4 の依頼文にも同じ一言が要る. §agent.md への追随を参照)

### 3. push の節

- 「提出のたびに push してください」の直後に, 「意味を理解していない操作は許可しない」warn を, agent.md と同じ趣旨で置く. 内容は, push は記録を GitHub へ送る操作で, 鍵やデータが含まれていると情報が外へ出ること, コマンドの意味が分からないときは許可せずに, 聞く, 調べる, 教員に聞く, のいずれかをすること. (P8)

### 4. 演習 GIT-1, GIT-2 の再構成 (P3, P5)

案 A (推奨): 2 つの演習を 1 つにまとめ, 手で通すのは 1 周だけにする.

- 新 GIT-1: アカウント作成, 認証, リポジトリ作成, `clone`, `.gitignore` への追記, `README.md` に 1 行書く, `git status`, `git add README.md .gitignore`, `git diff --staged`, `git commit`, `git push`, GitHub 上で確認. `notes/` と `src/` を作る手順 (旧手順 6) は削る. `src/analysis.py` は agent.md の演習 AGENT-1 で codex が作るので, ここでは不要になる.
- 旧 GIT-2 にあった「`git add` の前後で `git status` の表示が変わる理由を説明する」問いは, 新 GIT-1 の最後に 1 問として残す.
- 新 GIT-2 (小演習): 新規ファイルを 1 つ作り, `git diff` に出ないことと, `git status` に `Untracked` として出ることを確かめる. これは P2 の体験にあたる.
- GIT-3 (公開してよいか判断する) は変更しない.

案 B: 演習は現状のまま, `git add .` だけを `git add <ファイル名>` に直す. 分量は減らない.

### 5. 初日に不要な設定を降ろす (P4)

- 「既定のエディタの設定」は, `-m` を付けて commit するか, codex に頼んで commit するので, 初日には使わない. 見出しごと note に移し, 手順の最後に置く.
- 「名前とメールアドレス」の noreply アドレスの説明は, 1 文を残して note に降ろす.
- OneDrive などの同期の warn は, 事故が多い場所なので warn のまま残す. 箇条書きの 4 項目だけを note に降ろす.

### 6. 末尾

- 「この資料を使う講義」の節を, agent.md と同じ形で足す. (P7)
- `previousChapter` と `nextChapter` は変えない (`setup.html` から `agent.html`).

## agent.md への追随 (この修正案から出た宿題)

- **新規ファイルの見落とし**: agent.md の手順 4 の依頼文は, 新しく作ったファイルを差分に含めるとは限らない. `変更したファイルを VSCode で開いてください` は新規ファイルを含むが, `右の pane に, 変更の差分を表示してください` は `git diff` だけが実行されると新規ファイルが出ない. 依頼文に `新しく作ったファイルも含めて` を足す. 手順 6 の「記録するファイルを一覧にして」は新規ファイルを含むので, 最終的な漏れは防げる.
- agent.md のこの修正は, 本計画の採否とは独立に入れてよい小さな修正である.

## 決めること

1. 演習の再構成は案 A (2 つを 1 つにまとめる) でよいか.
2. `log` と `restore` を note に降ろし, 本文は 5 つのコマンドにしてよいか.
3. 「並列作業とコンフリクト」と「既定のエディタの設定」を note に降ろしてよいか.
4. 「頼む文」の対応表を git.md に置いてよいか. 置かない場合は, agent.md の 1 周の手順の中だけにとどめる.

## リスク

- 本文を減らすと, 学生が `git status` などの出力を読む練習の機会が減る. 対応表と小演習 (新 GIT-2) で補う.
- 演習の統合で, 回答例のコマンド列を直す必要がある. 他の資料から GIT-2 を参照している箇所は, 調べた範囲 (講義資料と進行中の計画) には無かった.
- 本修正案の根拠のうち, codex が `右の pane に差分を表示` をどう実行するかは実機で未確認である (agent.md の確認事項と同じ).
