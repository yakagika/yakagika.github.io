# git.md の修正案 (agent.md の改稿を受けて)

## メタ情報

- **状態**: proposed (修正案. git.md はまだ変更していない)
- **親計画**: [common-agent-literacy-material.md](../in-progress/common-agent-literacy-material.md)
- **根拠**: 2026-10-02 の agent.md の改稿 (`0f606e2` から `8c24fa8` まで). 初日に CLI を使い始め, git をほとんど触ったことのない学生を想定する.
- **対象**: `lectures/common/git.md` (696 行, 見出し 19 節, 演習 GIT-1〜3)

## 背景: agent.md で何が変わったか

1. 差分の確認, 記録するファイルの一覧, commit と push を, 学生がコマンドを打たずに codex へ頼む形にした (`変更したファイルを VSCode で開いてください`, `commit して push してください`).
2. 詳細 (読み込みの順番, 設定の一覧, 補助の操作) を note に移し, 本文を 1 周に必要な内容へ絞った.
3. 「意味を理解していない操作は許可しない」warn を, push の手順の直下に置いた.
4. 情報が古くなる旨の warn を冒頭に置いた.
5. 例の指示は, 学生のリポジトリに無いファイル (`data/sales.csv`) を前提にしないようにした.
6. 末尾に, この資料を使う 3 つの講義へのリンクを置いた.

git.md は agent.md より先に読む, git そのものを学ぶ資料である (2026-10-02 本人: codex 導入前であり, 自分で実行する前提でよい. 使いこなすことより, 一度は使ってみる位置づけ). したがって, コマンドは学生が自分で打つ前提を保ち, 手で打つ範囲は削らない. agent.md の変更から受けるのは, 位置づけの明示, 初日の負担の軽減, 新規ファイルの見落としの注意に限る.

## 修正案

### 1. 冒頭

- 位置づけの 1 段落を足す (P1): この章は git を自分の手で一度使ってみる章であること, 次の[共通資料 コーディングエージェントの利用](agent.html)では codex に頼んで同じ操作をさせるが, 表示されたコマンドの意味を言えるようにここで一度経験しておくこと.
- 警告 (warn) を 1 つ足す. GitHub の画面, 認証の方法, 料金は変わるので, 資料と食い違ったら公式のヘルプで確かめる. (agent.md と同じ趣旨)
- 「なぜエージェントと git を一緒に使うのか」は, 4 節を残し, 各節を 2〜3 文に縮める. 「並列作業とコンフリクト」は, 初日の範囲外なので note に降ろす. (P4, P6)

### 2. 日常のコマンド

- 7 つのコマンドは変更しない. 学生が自分で打つ前提を保つ.
- `diff` の warn (P2) に 1 文を足す: 「後で codex に差分を頼むときも同じで, `新しく作ったファイルも含めて` と添える」.

### 3. push の節

- 「提出のたびに push してください」の直後に, warn を 1 つ置く (P8). push は記録を GitHub へ送る操作で, 鍵やデータが含まれていると情報が外へ出て取り消しにくいこと, 意味の分からないコマンドは実行せずに, 調べる, 教員に聞く, のいずれかをすること. agent.md の同趣旨の warn への導入になる.

### 4. 演習 GIT-1, GIT-2 の再構成 (P3, P5)

案 A (推奨): 2 つの演習を 1 つにまとめ, 一度は通す、という位置づけに合わせて手で通す回数を 1 周にする.

- 新 GIT-1: アカウント作成, 認証, リポジトリ作成, `clone`, `.gitignore` への追記, `README.md` に 1 行書く, `git status`, `git add README.md .gitignore`, `git diff --staged`, `git commit`, `git push`, GitHub 上で確認. `notes/` と `src/` を作る手順 (旧手順 6) は削る. `src/analysis.py` は agent.md の演習 AGENT-1 で codex が作るので, ここでは不要になる.
- 旧 GIT-2 にあった「`git add` の前後で `git status` の表示が変わる理由を説明する」問いは, 新 GIT-1 の最後に 1 問として残す.
- 新 GIT-2 (小演習): 新規ファイルを 1 つ作り, `git diff` に出ないことと, `git status` に `Untracked` として出ることを確かめる. これは P2 の体験にあたる.
- GIT-3 (公開してよいか判断する) は変更しない.

案 B: 演習は現状のまま, `git add .` だけを `git add <ファイル名>` に直す. 分量は減らない.

### 5. 初日に不要な設定を降ろす (P4)

- 「既定のエディタの設定」は, `-m` を付けて commit するか, codex に頼んで commit するので, 初日には使わない. 見出しごと note に移し, 手順の最後に置く.
- 「名前とメールアドレス」の noreply アドレスの説明は, 1 文を残して note に降ろす.
- OneDrive などの同期の warn は, 事故が多い場所なので warn のまま残す. 箇条書きの 4 項目だけを note に降ろす.

### 6. 末尾

- 「この資料を使う講義」の節を, agent.md と同じ形で足す. (P7)
- `previousChapter` と `nextChapter` は変えない (`setup.html` から `agent.html`).

## agent.md への追随

- **新規ファイルの見落とし**: agent.md の手順 4 の依頼文 `右の pane に, 変更の差分を表示してください` は, codex が `git diff` だけを実行すると新しく作ったファイルが出ない. 依頼文に `新しく作ったファイルも含めて` を足す. 手順 6 の「記録するファイルを一覧にして」は新規ファイルを含むので, 最終的な漏れは防げる. この修正は小さく, 本計画の採否と独立に入れる (2026-10-02 に agent.md へ反映).

## 決めること

1. 演習の再構成は案 A (2 つを 1 つにまとめる) でよいか.
2. 「並列作業とコンフリクト」と「既定のエディタの設定」を note に降ろしてよいか.
3. 冒頭に位置づけの 1 段落を足し, 末尾に関連講義へのリンクを足してよいか.

## リスク

- 演習をまとめると, `git status` などを自分で打つ回数が減る. 小演習 (新 GIT-2) と, 一度は通す、という位置づけで補う.
- 演習の統合で, 回答例のコマンド列を直す必要がある. 他の資料から GIT-2 を参照している箇所は, 調べた範囲 (講義資料と進行中の計画) には無かった.
