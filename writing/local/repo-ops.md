# haskell-blog 固有の運用 (view blog-ja への上乗せ)

view (blog-ja) の §A / §B を前提に, この repo でだけ効く規則を置く. view と同旨の規則は
ここに複製しない. 節番号 (§A1〜A9, §B1〜B4) は view の番号を指す.

## 適用範囲

- 対象は `posts/`・`lectures/` の日本語散文 (地の文・見出し・箇条書き・図中の説明文).
  コードブロック・数式・frontmatter は対象外で, 講義コードの機械検証は `CLAUDE.md` の規約に従う.
- main session での執筆・subagent (blog-author-jp)・委譲先 (codex/cursor) のすべてが対象.

## 媒体・文体・参照 (旧 WRITING_STYLE.md §C)

- **媒体/体裁**: Hakyll 製ブログ. 記事は `posts/YYYY-MM-DD-slug.md`, 講義は `lectures/fp/`
  `lectures/slds/`. front matter は `title` / `description` / `tags` / `date` / `tableOfContents`.
  数式を使う記事は `katex: true` を付け, `$...$` (inline) / `$$...$$` (display) で書く.
- **文体 (媒体で使い分ける)**: **講義 (`lectures/`) は敬体 (ですます調) で統一** (fp1〜 と slds が
  敬体のため. 自然に書くと である調へ流れやすいので, 講義 prose を書く前に fp9 等で語り口を確認
  する). **ブログ記事 (`posts/`) は常体 (である調) を既定** とし記事内で統一する. 既存記事には
  「である調の本文 + 結びの一言だけ ですます調」で締める voice があり, 推敲で均して崩さない.
  引用符内の命題や「〜であること」の名詞化は敬体の講義でも常体のままでよい.
- **章参照**: 他章は `[第N章](fpN.html)` と書く (bare な「fp7」表記にしない). 自章は「本章」
  (リンク不要). 日本語助詞は link 直後に続ける (`[第7章](fp7.html)では`).
- **コード・図**: コードブロックは言語を指定する (```haskell ```yaml 等). 図・スクリーンショットは
  `images/` に置き, 本文で必ず言及して takeaway を述べる.
- **漢字かな**: 形式名詞・補助動詞・接続詞はひらがな (事→こと, 為→ため, 出来る→できる,
  下さい→ください, 但し→ただし). 専門用語・記号の表記は記事内で統一する.
- **講義コードの検証**: `lectures/fp/fp*.md` の Haskell コードブロックを追加・変更・削除したら
  fp-examples の対応 spec 更新と `stack test` 通過が必要. 手順の正本は `CLAUDE.md` (ここでは
  重複記載しない).

## view への上乗せ (旧 §A・§B のうち view に無い blog 固有分)

- **中心識別子の carve-out (§A3)**: 後で参照しない固有名は出さないが, 記事の中心となる識別子
  (扱う関数・型) は出してよい.
- **構成メタの追加例 (§A6)**: 「本記事/本節では〜を扱う/見ていく」「先に〜を述べます」
  「それを確かめるのが本節です」も予告・総括の型として削る. 章冒頭の短い地図 (何をどの順で扱うか) は
  1 箇所まで可, 節ごとの反復はしない.
- **語彙の癖の repo 例外 (§A6)**: 講義設計の三本立て (`writing/local/lecture-design.md`) で対照の
  両項を指す「数学側 / Haskell 側」は可. 型の値を列挙するという意味の「数え上げ」は分野の語なので可.
- **章内参照のリンク (§A3)**: 記事内・章内の参照は見出し名で指し, アンカーへのリンクを付ける.
  他章の参照は上の「章参照」に従う.
- **句読点・記号の半角統一**: 読点は `,`, 句点は `.`. 日本語の鉤括弧「」はそのまま. slds の旧章に
  全角が残るが, 新規・改稿分から半角にする. 用語と定義を並べる箇条書きのコロンも半角
  (「**用語**: 説明」. 既存の講義・記事はすべて半角).
- **ダッシュの追加対象 (§B3)**: 散文中の `--` も地の文・見出しで使わない. 見出しの「主題 — 補足」は
  「主題: 補足」か単一の句にする. 既存章の残存は依頼に応じて順次改修する (fp7 は 2026-07-20 改修済み).
- **中黒 (・) の並列使用を許可する** (view B3 の禁止を override. 理由は manifest の exceptions).
  この repo の確立した表記であり, 一文に詰め込みすぎない範囲で使う.
- **演習ラベル見出しの例外 (§B4)**: 演習の `### Exercise CHN-K` / `SLDSn-k` / `DSPn-k` 等のラベル見出しは
  `CLAUDE.md` の規約 (アンカーと提出ファイル名の安定) による. 識別情報は直下の太字タイトルが担う.

## 本文に絶対に入れないもの (旧 §E)

- ソース/スクリプトファイル名, 内部パス, TODO/issue 番号, 内部 plan 文書・codename への言及
  (公開記事に出さない).
- 後で参照しない固有名 (装飾的な精度).
