データサイエンスプロジェクト (旧 特別講義データサイエンス)

本資料の読み方と, 特別講義との違い

本資料の読み方

本資料は, データサイエンスプロジェクトの授業資料です. データサイエンスプロジェクトは, 2026 年度まで開講していた「特別講義 (データサイエンス)」を改めた通年の科目です. 学生が自分の問いを立て, データサイエンスの手法で研究し, 論文にまとめて学会で発表するまでを 1 年間で行います.

本資料には, 研究の進め方を載せます. 扱うのは, LLM (大規模言語モデル. ChatGPT, Gemini, Claude などの対話型の AI の中核にあるモデル) の使い方, 問いの立て方, 研究計画の立て方, 論文と発表です. 授業概要, 成績などについては講義中に別資料で説明します. 資料は作成中で, 構成は変わることがあります.

特別講義との違い

本科目は, 特別講義 (データサイエンス) と 2 つの点で異なります. 技術の学習を他の科目に任せて研究に集中すること, LLM の利用を前提に研究の問いを選ぶことです.

技術の学習を他の科目に分けて, 研究に集中する

特別講義は, プログラミングの基礎から, 統計, データサイエンスの手法, 研究までを 1 つの科目で扱っていました. これらは現在, 次の科目に分かれています.

  • プログラミング: データサイエンスのためのプログラミング
  • 統計: データ活用の統計学, データ活用の統計学実践
  • データサイエンスの技法: データサイエンス実践
  • 研究: データサイエンスプロジェクト (本科目)

本科目では研究に集中します. 技術的な内容は本資料では扱わず, 参考資料へのリンクだけを示します. どの技術が必要になるかは学生ごとの研究で決まるので, 必要な技術は学生の目的に応じて講義の中で扱います.

上の科目を履修していなくても, 本科目は講義の中で完結するように進めます. ただし, 担当教員の科目であるデータ活用の統計学とデータサイエンス実践は, 本科目と同じ年度に履修することを勧めます. 研究で使う統計の考え方と分析の手法を, 授業で順に学べるからです. データサイエンス実践は秋学期の科目なので, 前期に立てた研究計画の分析を, 秋学期に学ぶ手法で進めることができます.

LLM の利用を前提に, 本人が面白いと思える問いを選ぶ

特別講義では, 学生が 1 年間で研究を終えられることを重視していました. そのため研究計画では, 本当に知りたいことよりも, すぐに結果が出そうな目的, 手に入りやすいデータ, 授業で扱った基礎的な手法を選ぶように勧めていました.

本科目では, LLM の利用を前提に授業を行います. LLM を使うと, 一人では書けなかった分析のプログラム, 読み切れなかった量の文献, 扱えなかった規模のデータに手が届きます. そこで本科目では, 取り組みやすさで問いを狭めません. 学生本人の問題意識と関心から出発し, LLM なしでは難しいが本人が本当に面白いと思える研究を目指します.

本科目で「面白い研究」とは, 学生本人の問いを掘り下げ, その問いをどのように研究として実現できるかを考え抜いた研究を指します. 先行研究の中での位置づけは確かめますが, 厳密な新規性は求めません.

このために本科目では, 次の 2 つに時間を使います.

  • LLM を使った研究の進め方: LLM を研究のどの段階でどう使い, 何を自分で確かめるか.
  • 問いの立て方: 興味のあるテーマから, 自分が本当に知りたい問いを取り出す方法.

LLM の使い方には条件があります. LLM が出した結果は, 学生本人が内容を理解し, 人に説明できる範囲でだけ研究に使います. 本人が説明できない結果は, 分析の結果が出ていても研究の成果として採用しません. 本科目は対面の少人数で行い, 教員と話しながら研究を進め, その中で理解を確かめます.

扱う研究の範囲とゼミとの関係

本科目で扱うのは, データサイエンスに属する研究です. すなわち, データを集めて分析し, データを生み出した対象の背後にある構造を明らかにする研究です. エージェント・ベース・モデリング (個々の主体の振る舞いを計算機で模擬する手法) による研究や, 人文学的な研究は扱いません. データサイエンス以外の研究は, 担当教員のゼミで扱います.

本科目は, 担当教員のゼミと並行して履修できます. ゼミと本科目で研究の内容を共通にしても構いません. 共通にする場合の手続きは, 研究倫理と成果の利用に書いています.

1 年間の流れ

最終的な成果物は論文です. 年度末までに論文を書き, 学会で発表します. 希望する学生は, 夏休みに学内の奨学論文コンテストでも発表します.

資料は次の段階に分けています. 「第 N 回」は研究の段階を表し, 1 回の授業とは限りません. 1 つの段階に数回の授業を使うことがあります.

  • 第 1 回 本資料の読み方と, 特別講義との違い
  • 第 2 回 共通資料による準備: プログラミングの環境, git と GitHub, コーディングエージェントを用意します.
  • 第 3 回 LLM を使った研究の進め方
  • 第 4 回 問いの立て方
  • 第 5 回 研究計画: 問いに答えるための小さな問いを文献で調べ, 1 年間で答える問いを選び, 研究の目的, データ, 手法を決めます.
  • 第 6 回 論文と発表 (作成中)

研究計画を立てた後は, データを集めて分析します. その段階で必要になる技術は, 参考資料と講義で学びます.

研究倫理と成果の利用

本科目で行った研究の成果を, 本科目での学会発表と奨学論文コンテスト以外 (卒業論文, 他の講義, 別の学外発表など) で使う場合は, 必ず事前に, 卒業論文や講義の指導教員と本科目の担当教員の双方から許可を取ってください.

アンケート調査などの調査データは, 使用目的を限定して倫理審査を行っています. 審査で申請していない目的にデータを使うと違反になります. ゼミと研究の内容を共通にする場合は, 調査やデータの収集を始める前 (倫理審査を申請する前) に教員に伝えてください. 審査で申請する用途にゼミを含めます.

卒業論文や別の学会発表などで, 本科目の内容から大きく変えずに提出すると, 二重利用や自己剽窃とみなされ, 倫理違反になる可能性があります.

自己剽窃にあたる行為には, 次のようなものがあります.

  • 過去の論文の文章を, 新しい論文にそのまま写して使う.
  • 過去の論文で使ったデータやグラフを, 新しい論文で出典を示さずに使う.
  • 過去に発表したアイデアを, 新しい論文で初めて示したもののように書く.
  • 過去の論文で導いた結論を, 新しい論文で出典を示さずに使う.

本科目で作成した論文の分析結果やデータを, 卒業論文, 他の講義, 別の学外発表などで使う場合は, 引用か参考元として出典を示してください.

本科目の終了後も研究を続けたい場合は, ゼミや IEEE Student Branch など, 担当教員が関わる講義や組織を通じて行ってください. それ以外の場合には, 卒業論文や学外発表の指導はできません.
