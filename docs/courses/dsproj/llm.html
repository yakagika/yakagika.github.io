LLM を使った研究の進め方

← Previous 共通資料による準備 Next → 問いの立て方

LLM を研究に使う条件

本科目では, 研究のすべての段階で LLM を使って構いません. 問いを広げる, 先行研究を探す, 分析のプログラムを書く, 論文の原稿を書く, といった作業です. その代わりに, LLM が出した結果を研究に使うには条件があります.

LLM が出した結果は, 自分が内容を理解し, 人に説明できる範囲でだけ研究に使います. 説明できない結果は, 分析の結果が出ていても研究の成果として採用しません. 説明できるとは, 例えば次の問いに自分の言葉で答えられることです.

  • 分析のコードの各部分は, データに何をしているか.
  • 使った分析の手法は, データに何を仮定し, 結果から何が言えて何が言えないか.
  • 引用した文献は実在し, 自分が引いた主張がその本文に書かれているか.
  • 論文の各段落は, 何を主張し, その根拠はどの分析結果か.

本科目は対面の少人数で行います. 教員は研究の進み具合を学生と話しながら確かめ, その中で上の問いを尋ねます. 答えられなかった箇所は, 参考資料や文献で調べ直すか, LLM に説明させてから自分で確かめ直します.

セキュリティとデータの扱い

コーディングエージェントは, 作業ディレクトリのファイルを読み, コマンドを実行します. 実行してよい範囲の決め方 (sandbox と承認) と, 意味が分からない操作を承認しないことは, 共通資料のsandbox と承認と分からないまま承認しないで扱います. 研究を始める前に読んでください.

研究のデータについては, 次の 2 点を守ります.

  • 個人に関わるデータは LLM に渡しません. アンケートの回答などの生データは, LLM に読ませません. 列の名前と型 (数値か, 選択肢か, 自由記述か) だけを伝えてコードを書かせ, そのコードは自分で手元で実行します. エージェントに実行させると, 出力に含まれるデータの行や回答も LLM に渡るからです. LLM に渡してよいのは, 件数や平均などの集計した結果だけです. LLM の多くは外部のサービスで動くので, データを渡すと, 倫理審査で申請したデータの扱い (研究倫理と成果の利用) の範囲を超えるおそれがあります.
  • コーディングエージェントに作業ディレクトリを任せるときは, データをその外に置きます. エージェントは作業ディレクトリのファイルを読めるので, 中にデータがあると, 指示していなくても読まれることがあります. コードからは, 作業ディレクトリの外のデータの場所を指定して読み込みます.

自分で表示を指示していなくても, 実行の出力にデータの行が含まれることがあります. LLM が書いたコードには, 読み込みを確かめるためにデータの先頭の数行を表示する処理が入っていることがあります. 値の変換に失敗したときのエラーの表示にも, データの値が含まれることがあります. 手元で実行したときのエラーを LLM に貼って直し方を尋ねる場合は, 貼る前に, 表示にデータの値が含まれていないかを確かめます.

API キーやパスワードも, LLM への指示や, エージェントが読むファイルに書きません. API キーの扱いは, 参考資料のデータの取得で扱います.

研究の各段階での使い方

LLM の使い方は, 研究の段階ごとに, 何を LLM に任せ, 何を自分で決めて確かめるかで整理できます.

問いを広げる

問いの立て方で扱うクエスチョンバーストは, 1 つの課題について答えを出さずに問いだけを大量に出し, その中から面白い問いを選ぶ方法です. LLM は, 問いを出す相手としても使えます. 頼むときは, 答えや解決策を書かず問いだけを出すように, 指示に明記します. LLM は, 指示しないと答えや解決策も書くことが多いからです. LLM が出した問いのうち, どれを面白いと感じるかは, 本人が決めます.

研究の出発点は本人の関心なので, LLM に「面白い問いを選んで」と頼んでも, その選択は本人の関心を表しません.

先行研究を探し, 本文を確かめる

LLM は, 存在しない文献や, 文献に書かれていない主張を, もっともらしく出力することがあります. そのため, LLM が挙げた文献は, 次の 2 段階で確かめてから使います.

  1. 文献が実在することを, 出版社, 学会, CiNii や Google Scholar などのデータベースで確かめる.
  2. 本文を開き, 自分が引く主張が本文に書かれていることを確かめる.

検索の結果に出る要旨 (論文の冒頭にある短い要約) や, LLM が作った文献の要約を読んだだけでは, 2 段階目の確認になりません. 要旨には論文の主張の一部しか書かれていません. LLM の要約には, 本文に書かれていない内容が含まれることがあります.

本文を読めない文献は引用しません. 本文の確認をエージェントに手伝わせる手順の例は, 共通資料のskill: 繰り返す手順を切り出すの 2 つ目の例 (文献の本文確認) にあります. 研究に文献が必要な理由と, 小さな問いを文献で調べる進め方は, 研究計画の小さな問いを文献で調べるにあります.

分析のコードを書かせて確かめる

分析のコードは LLM に書かせて構いません. ただし, 結果を左右する選択は自分で決めます. どの変数を使うか, どの観測を除くか, どの手法で分析するかです. その理由を研究のノートに記録し, 論文の方法の節に書けるようにします.

書かせたコードは, 読み込んだデータの行数, 欠損の数, 値の範囲など, 途中の出力を見て確かめます.

エラーを出さずに最後まで動いたコードでも, 意図どおりに分析しているとは限りません. 例えば, 回帰分析の関数には, 欠損のある行を除いてから計算するものがあります. その場合, 分析に使われた行数は, 読み込んだデータの行数より少なくなります. 途中の出力で 2 つの行数を見比べると, 除かれた行があることが分かります.

使った手法が何を仮定しているかは, 参考資料の対応する資料で確かめます. エージェントが加えた変更は, git の差分で読みます. 読んでも意味が分からない変更は, 共通資料のskill: 繰り返す手順を切り出すの 1 つ目の例 (差分の説明) のように, 変更箇所ごとにエージェントに説明させてから確かめます.

論文と発表の原稿に使う

論文と発表資料の原稿に LLM の出力を使って構いません. ただし, 中身を自分で制御できることが前提です. 主張, 根拠, 数値が自分の分析結果と一致していること, 引用した文献を本文で確かめていることを, 自分で確かめます. 投稿先の学会が LLM の利用について定めている場合は, それに従って利用の仕方を論文に書きます. 書き方と発表の方法は論文と発表で扱います.

Exercise DSPJ3-1

LLM が挙げた先行研究を確かめる

今の自分の関心 (テーマのままで構いません) について, LLM に先行研究を 5 件挙げさせてください. 各文献について, 書誌 (著者, 題名, 発行年, 掲載誌か出版社) と, 自分のテーマに関係すると LLM が述べる主張を 1 文ずつ挙げさせます. 各文献が実在するか, LLM が述べた主張が本文に書かれているかを確かめ, 次の表にまとめてください.

文献 実在を確かめた方法 LLM が述べた主張 本文で確かめた結果

本文で確かめた結果の欄には, 「実在を確かめられない」「実在するが本文を読めない」「本文と主張が一致しない」「主張が本文に書かれている」のどれに当たるかを書きます. 本文を読めなかった文献は読めなかった理由を, 本文を確かめた文献は主張に対応する箇所 (頁か節) を添えてください. 表をもとに, LLM の出力のどこを確かめる必要があったかを, 講義で説明できるようにしておきます.
